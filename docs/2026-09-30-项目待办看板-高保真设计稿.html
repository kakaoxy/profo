Project Todo Board · Mockup v2.1 · 2026-09-30

需求地图与口径

看板定位是规则驱动的体检报告，不是任务系统：后端按 R1~R10 规则对签约 + 装修两个阶段的项目实时计算待办，不落库、只读展示。 核心目标 = 一眼看出来哪些项目的哪些事项要处理 —— 3 列网格单屏容纳 8 个项目、统计与筛选合并为单行工具栏、待办单行化。 待办行点击弹出小弹窗（缺失明细 + 去项目详情按钮），卡片其余区域点击直达详情锚点。 需求全文见 docs/2026-09-30-项目待办看板-需求文档.md；展示信息的现网来源核对见第六节。

  1. 1卡头 = 项目识别：小区 + 门牌（15px/480）单行；元信息行 12px：合同号（mono）· 负责人 · 当前工序 · 施工方。地址 / 户型 / 面积移除，识别项目靠小区 + 合同号足够。
  2. 2P0 计数徽章：Rust 填充白字 mono，只在 P0 ≥ 1 时出现 —— 扫一眼定位阻塞卡，无 P0 卡不放（避免告警通胀）。
  3. 3阶段徽章沿用列表页映射：签约 = sky-wash / ink，装修 = apricot-wash / rust，胶囊 9999px，11px/480。
  4. 4待办行 = 一行：优先级点（P0 实心 Rust / P1 空心 Rust 环 / P2 灰点 7px）+ 标题 13px/480。
  5. 5灰色短语：12px/430，只留扫读所需的最小上下文（「水电 27 天 · 标准 20」「签约合同未签」），溢出省略。
  6. 6右侧天数：12px tnum，逾期 / 超期 / 停滞用 Rust 480；「剩 N 天」「N 份」用 Graphite —— 不套金额红绿语义。
  7. 7两级点击：待办行点击 → 小弹窗（结构化缺失明细 + 「去项目详情」按钮，见 03-C）；卡片其余区域点击 → 详情页对应锚点；命中 > 6 条时末行灰底折叠「+ N」。
