## 2. 模块概述与目标

本册扩展线索的归属维度：在现有 `referrer_id`（分享归属员工）之外新增 `store_id`（推荐门店）和 `broker_id`（推荐经纪人），三个字段并存、互不覆盖（D7、Q28、Q33）。同时实现估价分享链路：员工生成带 `referrer` 的分享卡，经纪人打开后识别其绑定门店并代填客户/房源信息，提交时写入三方归属（S11、7.3）。

本册只负责线索归属字段、录入联动、展示与查询，以及估价分享代填链路；线索本身的评估、跟进、成交等既有流程不在本册改造范围。门店/经纪人的业绩归属是否计入绩效不在本期确认范围（Q29）。

## 4. 功能需求

### 4.1 M07 线索归属扩展

#### REQ-M07-001 线索归属字段扩展

| 项目 | 内容 |
|---|---|
| 功能描述 | 在 `leads` 表新增 `store_id`、`broker_id`、`store_owner_employee_id`、`broker_inviter_employee_id` 四个可空字段，保留现有 `referrer_id`。 |
| 触发条件 | 数据库迁移执行；线索创建、更新、查询使用新字段。 |
| 主流程 | 1. 新增 `store_id`（UUID，可空，逻辑外键 `merchant_stores.id`）；2. 新增 `broker_id`（UUID，可空，逻辑外键 `merchant_brokers.id`）；3. 新增 `store_owner_employee_id`（UUID，可空，门店归属员工快照）；4. 新增 `broker_inviter_employee_id`（UUID，可空，经纪人邀请员工快照）；5. 保留 `referrer_id`（UUID，可空，逻辑外键 `users.id`）；6. 新增 `store_id`、`broker_id` 查询索引；7. 存量数据新字段保持 NULL。 |
| 分支与异常 | 1. 迁移重复执行：幂等，不重复加列/索引；2. 存量数据无值：允许 NULL；3. 关联门店/经纪人被删除：逻辑外键不级联，展示时按历史值处理。 |
| 输入字段 | 无（迁移） |
| 输出字段 | `leads.store_id`、`leads.broker_id`、`leads.store_owner_employee_id`、`leads.broker_inviter_employee_id` |
| 业务规则 | BR-M07-001：字段并存，分别表达“谁分享”“哪家门店”“哪个经纪人推荐”“门店归属员工”“经纪人邀请员工”（8.6、D7、m02721）；BR-M07-002：不得用 `store_id`/`broker_id` 覆盖 `referrer_id`（Q28、Q33）；BR-M07-003：`store_id`、`broker_id` 均可空（Q27、Q31）；BR-M07-020：`store_owner_employee_id`、`broker_inviter_employee_id` 为提交时快照，后续门店换负责人或经纪人换邀请人不回写。 |
| 权限与角色 | 系统迁移；无业务角色。 |

#### REQ-M07-002 线索创建与更新入参

| 项目 | 内容 |
|---|---|
| 功能描述 | `LeadCreate`、`LeadUpdate` 增加 `store_id`、`broker_id`；`store_owner_employee_id`、`broker_inviter_employee_id` 仅由服务端回填，不接收客户端传值。保存时校验关联有效性。 |
| 触发条件 | 小程序/后台创建或编辑线索。 |
| 主流程 | 1. 接收 `store_id`、`broker_id`（均可空）；2. 校验门店存在且未停用/未合并；3. 校验经纪人存在且状态可用；4. 若同时传经纪人与门店，校验经纪人当前绑定该门店；5. 服务端回填门店归属员工与经纪人邀请员工快照；6. 保存线索及归属字段；7. 返回多维度归属信息。 |
| 分支与异常 | 1. 门店不存在/已停用/已合并：拒绝并提示；2. 经纪人不存在/已停用：拒绝；3. 经纪人与门店不匹配：拒绝；4. 只传经纪人未传门店：允许；若经纪人有有效绑定门店则回填 `store_id`，无有效绑定则保留空门店并标记 `missing_store` 待审核（Q27/Q31）；5. 只传门店未传经纪人：允许（Q27）；6. 两者都不传：允许；7. 更新时置空字段：允许，但需留痕。 |
| 输入字段 | `store_id`、`broker_id` |
| 输出字段 | 线索 `id`、`store_id`、`broker_id`、`store_owner_employee_id`、`broker_inviter_employee_id`、归属完整性状态 |
| 业务规则 | BR-M07-004：门店→经纪人必须为有效绑定关系（S10）；BR-M07-005：`store_id` 可空、`broker_id` 可空（Q27）；BR-M07-006：门店、经纪人均可选；仅传经纪人且无有效绑定门店时允许提交空门店线索并标记 `missing_store` 待审核（Q27/Q31）；BR-M07-007：归属字段变更写操作日志。 |
| 权限与角色 | 员工 `merchant:write`；运营/管理员可编辑。 |

#### REQ-M07-003 门店—经纪人二级联动

| 项目 | 内容 |
|---|---|
| 功能描述 | 线索录入页选择门店后，联动加载该门店下已绑定且启用的经纪人；经纪人列表只展示有效绑定。 |
| 触发条件 | 用户选择/切换推荐门店。 |
| 主流程 | 1. 选择门店（搜索或附近门店）；2. 调用经纪人列表接口，入参 `store_id`；3. 仅返回 `bind_status=已绑定` 且经纪人状态启用的记录；4. 展示经纪人姓名、手机号脱敏；5. 用户选择经纪人；6. 保存 `broker_id`。 |
| 分支与异常 | 1. 门店无经纪人：展示空列表，允许只保存门店；2. 门店切换：清空已选经纪人；3. 经纪人解绑/停用：刷新后不可选；4. 网络失败：允许重试；5. 未选择门店：经纪人不加载。 |
| 输入字段 | `store_id`、搜索关键字、附近坐标 |
| 输出字段 | 经纪人列表（`id`、姓名、脱敏手机号、绑定状态） |
| 业务规则 | BR-M07-008：只能选择该门店下有效绑定的经纪人（S10）；BR-M07-009：门店与经纪人二级联动，不允许跨店选择；BR-M07-010：未选门店时可按姓名/手机号搜索经纪人，选择后按经纪人当前有效绑定回填 `store_id`，无有效绑定则标记 `missing_store`。 |
| 权限与角色 | 员工、运营；经纪人列表按数据范围过滤。 |

### 4.2 M08 估价分享与经纪人代填

| 输出字段 | 门店名称、经纪人姓名、估价表单 |

| 权限与角色 | 已认证经纪人。 |

#### REQ-M08-003 独立经纪人/未绑定门店的降级提交

| 项目 | 内容 |
|---|---|
| 功能描述 | 经纪人未绑定门店（独立经纪人）时，允许继续填写并提交线索，线索挂空门店待审核。 |
| 触发条件 | 经纪人已登录但无有效绑定门店。 |

| 权限与角色 | 已认证但未绑定门店的经纪人。 |

#### REQ-M08-004 多维度归属写入

| 项目 | 内容 |
|---|---|
| 功能描述 | 经纪人提交估价线索时，同时写入分享员工、门店、经纪人以及门店归属员工、经纪人邀请员工快照，形成员工归因、经纪人归因和门店归因。 |
| 触发条件 | 经纪人在估价分享页提交成功。 |
| 主流程 | 1. 从分享参数取 `referrer_id`；2. 从经纪人当前绑定取 `store_id`（无绑定则为空）；3. 取当前经纪人 `broker_id`；4. 若 `store_id` 有值，读取门店 `owner_employee_id` 写入 `store_owner_employee_id`；5. 读取经纪人 `inviter_employee_id` 写入 `broker_inviter_employee_id`；6. 创建线索并保存五个字段；7. 返回线索详情。 |
| 分支与异常 | 1. `referrer` 无效/非员工：置空或拒绝，见 R-V06-02；2. 门店绑定在提交瞬间失效：按空门店处理；3. 经纪人无邀请员工：`broker_inviter_employee_id` 为空；4. 门店无归属员工：`store_owner_employee_id` 为空；5. 重复提交：幂等，避免重复线索；6. 线索创建失败：不写入部分归属。 |
| 输入字段 | `referrer_id`、`store_id`、`broker_id`、估价表单 |
| 输出字段 | `leads.id`、`referrer_id`、`store_id`、`broker_id`、`store_owner_employee_id`、`broker_inviter_employee_id` |
| 业务规则 | BR-M08-010：`referrer_id` = 分享员工；`store_id` = 经纪人当前绑定门店（独立经纪人为空）；`broker_id` = 经纪人；`store_owner_employee_id` = 门店 `owner_employee_id` 快照；`broker_inviter_employee_id` = 经纪人 `inviter_employee_id` 快照（m02721、7.3）；BR-M08-011：所有归属字段并存，不互相覆盖（D7）；BR-M08-012：空门店场景 `store_id` 为空，其他已有归属字段保留（Q31）；BR-M08-018：独立经纪人无门店时仍必须保留 `broker_id` 与 `broker_inviter_employee_id`。 |
| 权限与角色 | 经纪人；系统按登录态鉴权。 |

#### REQ-M08-005 线索去重与客户信息边界

| 项目 | 内容 |
|---|---|

| 输出字段 | 重复提示、线索 `id` |

| 权限与角色 | 经纪人提交；后台运营可查看重复标记。 |

## 7. 依赖与影响说明

1. 依赖 V02 门店主数据的有效性校验；依赖 V04 经纪人档案、绑定关系与“一人一店”规则（Q23）。

4. 现有 `referrer_id` 归因、分享统计保持；不得用 `referrerName || creatorName` 混用录入人语义（S10 现状问题）。
5. 存量线索不回填（Q30）；新增字段不影响既有线索状态机。
6. 估价分享涉及经纪人身份识别；需与 V04 的 `merchant_brokers.user_id` 关联。
7. 业绩归属不在本期计算（Q29），仅保留字段与展示。
