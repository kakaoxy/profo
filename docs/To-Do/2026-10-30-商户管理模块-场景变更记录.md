## 2. 权威场景原文要点

1. 员工在手机上通过小程序可以创建门店、拜访门店、编辑门店基础信息。
2. 员工通过门店二维码邀请经纪人注册，经纪人扫码注册后自动绑定到门店。
3. Admin 管理后台可以通过列表和地图两种方式查看和处理所有员工创建的门店、所在位置以及员工拜访信息。
4. 员工分享小程序后如果经纪人打开并提交线索，则归因到员工；员工创建的门店以及绑定在该门店下的经纪人提交的线索也归因到员工；一条线索可能同时有员工归因、经纪人归因、经纪人对应的门店归因。
5. 经纪人不强制绑定门店，可以是独立经纪人。
6. 员工分享小程序被用户打开并注册为经纪人后，经纪人自动归属到该员工。
7. 经纪人注册时可以创建门店，也可以选择系统中已有门店；经纪人创建的门店在后台显示未审核状态，admin 可以操作转正或者合并到已有门店。
8. 经纪人要绑定门店必须先绑定手机号码；绑定手机号码走当前完善手机号码的已有流程，不新建流程。

## 3. 冲突裁决

| 冲突点 | 原需求文档口径 | 本次场景口径 | 落地方式 |
|---|---|---|---|
| 首次绑定是否必须选择门店 | V04 首次绑定需搜索并选择门店 | 经纪人可以不绑定门店，允许独立经纪人 | V04 `REQ-M06-001` 改为可选绑定；未绑定状态 `bind_status=未绑定` 合法 |
| 二维码邀请 | 原文无门店二维码邀请 | 员工生成门店二维码，经纪人扫码注册后自动绑定 | V04 新增 `REQ-M06-006`；V02 新增门店二维码字段引用 |
| 经纪人注册建店 | 原文仅允许后台/员工建店 | 经纪人注册时可创建门店或选择已有门店 | V02 新增 `REQ-M01B-007`；V04 `REQ-M05-006` 调用 |
| 经纪人自建门店审核 | 原文无 | 后台显示未审核，admin 可转正或合并 | V02 增 `review_status`；V07 新增 `REQ-M11-012` |
| 经纪人手机号验证 | V04 使用短信验证码 | 走现有完善手机号流程，不新建流程 | V04 `REQ-M05-001/002` 改为复用 `POST /api/v1/public/users/phone` 与 `/phone/wechat` |
| 线索员工归属 | 仅 `referrer_id` 表示分享员工 | 门店归属员工、经纪人邀请员工也构成员工归因 | V06 增 `store_owner_employee_id`、`broker_inviter_employee_id` 快照字段 |
| 经纪人归属 | 仅绑定门店关系 | 扫码注册时自动归属邀请员工 | V04 `merchant_brokers.inviter_employee_id` |
| 门店状态 | 正常/停用/已合并/已搬迁 | 经纪人自建门店增加“未审核”展示 | V02/V07 增 `review_status`（未审核/已转正/已合并），不改变原 `status` 状态机 |

## 4. 数据模型增量

| 对象 | 新增字段 | 说明 |
|---|---|---|
| `merchant_stores` | `review_status` | 未审核 / 已转正 / 已合并；员工/后台建店默认已转正，经纪人建店默认未审核 |
| `merchant_stores` | `created_by_broker_id` | 经纪人自建门店的创建人；非经纪人建店为空 |
| `merchant_stores.source` | 新增枚举“经纪人创建” | 与员工拓展、后台新增、导入并列 |
| `merchant_brokers` | `inviter_employee_id` | 扫码注册/员工分享注册时归属的员工 |
| `merchant_brokers` | `bind_source` | 二维码邀请 / 手动选择 / 后台指定 / 无绑定 |
| `merchant_broker_bindings` | `bind_source` | 同经纪人绑定来源快照 |
| `leads` | `store_owner_employee_id` | 提交时门店归属员工快照 |
| `leads` | `broker_inviter_employee_id` | 提交时经纪人邀请员工快照 |

> 以上字段均为场景落地所需增量，不替换原文 8.1–8.6 既有字段；具体表结构、索引与迁移以技术方案为准。
