## 2. 模块概述与目标

本册复用现有通知中心，新增商户管理相关通知类型：协议到期提醒与拜访超期未复访提醒。协议到期提前 30 天站内通知（Q16）；拜访后 30 天未复访提醒归属员工（N09）。通知按事件去重、按收件人记录已读状态，并支持跳转门店/协议详情。

**范围裁剪说明**：原文 M14 列出的“绑定待审核”通知，因 D3-A 已确认经纪人绑定免审、即时生效，不再产生“待审核”事件；本册不实现绑定审核通知。绑定成功/失败的即时页面提示由 V04 的绑定流程负责，不属于通知中心。原文 S06 将 M14 列为涉及模块，但 S06 未定义任何合作状态变更通知规则，本册不承接 S06 通知，待业务补充。

## 3. 名词与术语

| 术语 | 定义 | 本册使用说明 |
|---|---|---|
| 站内信 | 系统内通知中心消息 | 现有 `notifications` |
| 通知事件 | 一次业务事件生成的一条通知主体 | 按 `dedupe_key` 去重 |
| 收件人 | 接收通知的用户 | `notification_recipients` |
| 去重键 | 防止同一事件重复发送的唯一键 | `dedupe_key` |
| 到期提醒 | 协议到期前 30 天提醒 | Q16 |
| 超期未复访 | 门店超过 30 天无拜访 | N09 |
| 通知模板 | 标题、正文、跳转地址的生成规则 | 本册定义 |

## 4. 功能需求

### 4.1 通知类型与模板

#### REQ-M14-001 商户通知类型注册

| 项目 | 内容 |
|---|---|
| 功能描述 | 在现有通知中心注册商户管理通知类型，定义分类、模板、优先级、跳转行为。 |
| 触发条件 | 系统初始化/通知事件产生。 |
| 主流程 | 1. 注册分类 `merchant`；2. 注册类型 `merchant.agreement.expiring`（协议到期）；3. 注册类型 `merchant.visit.overdue`（拜访超期）；4. 配置标题/正文模板；5. 配置 `action_type` 与 `action_url`；6. 配置优先级；7. 供业务任务调用。 |
| 分支与异常 | 1. 类型重复注册：幂等；2. 模板缺失：拒绝发送并记录 `TEMPLATE_MISSING`；3. 未知类型：拒绝；4. 模板变量缺失：使用空值并告警；5. 通知中心不可用：记录失败并重试。 |
| 输入字段 | 分类、类型、模板、优先级、跳转配置 |
| 输出字段 | 通知类型配置 |
| 业务规则 | BR-M14-001：复用现有通知中心，不新建独立消息表；BR-M14-002：通知类型使用稳定英文编码；BR-M14-003：模板不得包含明文手机号等敏感信息；BR-M14-004：绑定审核通知不注册（D3-A 免审）。 |
| 权限与角色 | 系统；运营只读通知配置。 |

#### REQ-M14-002 协议到期提醒

| 项目 | 内容 |
|---|---|
| 功能描述 | 消费 V05 产生的协议到期事件，在到期前 30 天窗口生成站内通知；门店主体提醒门店归属员工，公司主体提醒公司联系人/运营。 |
| 触发条件 | V05 每日扫描已签署协议并发布 `merchant.agreement.expiring` 事件；本册不再重复扫描协议。 |
| 主流程 | 1. 接收 V05 事件；2. 解析签约主体（`store_id` 或 `company_id`）；3. 按 `agreement_id + expire_date` 校验去重；4. 门店主体取门店归属员工；公司主体取公司联系人手机号匹配到的系统用户；5. 收件人为空时转运营角色；6. 通知标题含门店名称或公司名称与到期日期；7. 跳转协议详情；8. 写投递日志。 |
| 分支与异常 | 1. 协议已作废/已过期：不提醒；2. `expire_at` 为空：不提醒；3. 同一协议同一到期日重复事件：按 `dedupe_key` 去重；4. 事件在到期前 30 天窗口内补发：允许补发一次，复用同一 `dedupe_key`，已发送则跳过；5. 公司联系人不是系统用户：转运营；6. 收件人不存在：记录失败；7. 通知发送失败：重试。 |
| 输入字段 | 协议 `id`、`store_id`、`company_id`、`store_name`、`company_name`、`expire_at`、门店归属员工、公司联系人用户 |
| 输出字段 | 通知事件、收件人、投递日志 |
| 业务规则 | BR-M14-005：到期前 30 天窗口站内通知（Q16）；BR-M14-006：去重键 `merchant:agreement_expiring:{agreement_id}:{expire_date}`；BR-M14-007：同一协议同一到期周期只发一次，漏跑补发复用同一去重键；BR-M14-008：到期后协议状态由 V05 处理，本册不改变协议状态；BR-M14-024：V05 负责扫描与事件生产，本册只负责通知消费与投递。 |
| 权限与角色 | 系统任务；门店主体收件人为门店归属员工，公司主体收件人为公司联系人/运营。 |

#### REQ-M14-003 拜访超期未复访提醒

| 项目 | 内容 |
|---|---|
| 功能描述 | 每日扫描正常门店，最近拜访超过 30 天时提醒归属员工。 |
| 触发条件 | 定时任务每日执行；门店 `status=正常`。 |
| 主流程 | 1. 读取门店 `last_visit_at`；2. 为空时取该门店最早拜访记录时间；3. 计算距今天数；4. 超过 30 天生成通知；5. 收件人为 `owner_employee_id`，为空转运营角色；6. 标题含门店名称与最近拜访日期；7. 跳转门店详情；8. 写投递日志。 |
| 分支与异常 | 1. `last_visit_at` 为空且无拜访记录：不发送并记录；2. 门店停用/已合并/已搬迁：不提醒；3. 归属员工为空：改发运营角色并记录；4. 同一门店同一超期周期重复扫描：去重；5. 员工已离职：改发运营，见 R-V09-04。 |
| 输入字段 | 门店 `id`、`store_name`、`last_visit_at`、最早拜访时间、`owner_employee_id` |
| 输出字段 | 通知事件、收件人 |
| 业务规则 | BR-M14-009：拜访后 30 天未复访提醒归属员工（N09）；BR-M14-010：去重键 `merchant:visit_overdue:{store_id}:{last_visit_date}`；BR-M14-011：新增拜访后 `last_visit_at` 更新，下一周期重新计算；BR-M14-012：只提醒正常门店。 |
| 权限与角色 | 系统任务；收件人为归属员工。 |

### 4.2 通知发送与消费

#### REQ-M14-004 通知生成、去重与投递

| 项目 | 内容 |
|---|---|
| 功能描述 | 统一生成通知主体、展开收件人、按去重键防重、记录投递结果。 |
| 触发条件 | 接收 V05 协议到期事件，或拜访超期任务调用。 |
| 主流程 | 1. 生成 `Notification`；2. 设置 `category=merchant`、`type`、`title`、`body`、`action_type`、`action_url`、`payload`、`dedupe_key`；3. 按收件人列表创建 `NotificationRecipient`；4. 投递站内信；5. 写 `NotificationDeliveryLog`；6. 返回结果。 |
| 分支与异常 | 1. `dedupe_key` 已存在：跳过，不重复创建；2. 收件人重复：按唯一约束去重；3. 站内信投递失败：记录 failed 并重试；4. 未启用微信渠道：不处理；启用后无 openid：记录 skipped（R-V09-02）；5. 事务失败：整笔回滚。 |
| 输入字段 | 通知类型、模板变量、收件人列表、`dedupe_key`、来源对象 |
| 输出字段 | 通知 `id`、收件记录、投递日志 |
| 业务规则 | BR-M14-013：复用 `notifications`、`notification_recipients`、`notification_delivery_logs`；BR-M14-014：`dedupe_key` 全局唯一；BR-M14-015：通知正文不含敏感信息；BR-M14-016：投递失败可重试，重试不重复生成通知主体。 |
| 权限与角色 | 系统任务。 |

#### REQ-M14-005 通知列表、已读与跳转

| 项目 | 内容 |
|---|---|
| 功能描述 | 用户在小程序/后台通知中心查看商户通知、标记已读、点击跳转业务详情。 |
| 触发条件 | 用户打开通知中心。 |
| 主流程 | 1. 按当前用户查询通知；2. 默认未读优先、时间倒序；3. 展示标题、正文、时间；4. 点击标记已读；5. 按 `action_type/action_url` 跳转门店或协议详情；6. 支持全部已读。 |
| 分支与异常 | 1. 无通知：空态；2. 通知已过期：不展示或标记过期；3. 跳转目标无权限/已删除：提示不可访问；4. 重复点击：幂等；5. 收件人不是当前用户：不可见。 |
| 输入字段 | 用户 `id`、分页、已读状态 |
| 输出字段 | 通知列表、未读数、跳转结果 |
| 业务规则 | BR-M14-017：查询按 `user_id` 隔离；BR-M14-018：已读状态记录 `read_at`；BR-M14-019：跳转前校验目标权限；BR-M14-020：通知列表不展示其他收件人信息。 |
| 权限与角色 | 所有登录用户仅看本人通知。 |

#### REQ-M14-006 通知发送监控与日志

| 项目 | 内容 |
|---|---|
| 功能描述 | 监控每日任务执行、通知生成数量、投递失败并支持排查。 |
| 触发条件 | 定时任务执行；运营查看通知统计。 |
| 主流程 | 1. 记录任务开始/结束时间；2. 统计扫描数、生成数、去重跳过数、失败数；3. 记录失败原因；4. 支持按日期/类型查询；5. 异常告警给管理员。 |
| 分支与异常 | 1. 任务超时：记录并告警；2. 连续失败：告警；3. 无数据：正常空统计；4. 日志保留期见 NFR。 |
| 输入字段 | 任务日期、通知类型 |
| 输出字段 | 任务统计、失败明细 |
| 业务规则 | BR-M14-021：任务执行与投递结果可追溯；BR-M14-022：失败日志脱敏；BR-M14-023：不因单条失败中断整批任务。 |
| 权限与角色 | admin/operator 查看；系统执行。 |

## 6. 接口与数据

### 6.1 数据对象（复用现有通知中心）

| `id` | 通知 ID | 系统生成 |

| 字段 | 说明 | 本册使用 |

### 6.2 通知事件定义

| 事件类型 | 触发 | 收件人 | 去重键 | 跳转 |
|---|---|---|---|---|
| `merchant.agreement.expiring` | 已签署协议距到期 ≤30 天（V05 事件） | 门店归属员工；公司主体为公司联系人/运营 | `merchant:agreement_expiring:{agreement_id}:{expire_date}` | 协议详情 |
| `merchant.visit.overdue` | 正常门店超过 30 天未拜访 | `owner_employee_id`，为空转运营 | `merchant:visit_overdue:{store_id}:{last_visit_date}` | 门店详情 |

### 6.3 逻辑接口

| 接口 | 调用方 | 输入 | 输出 | 说明 |
|---|---|---|---|---|
| 接收协议到期事件 | V05 | 协议 ID、`store_id`/`company_id`、到期日、主体名称 | 通知事件 | V05 生产，本册消费 |
| 扫描拜访超期 | 定时任务 | 当前日期 | 通知事件 | V02/V03 数据 |
| 创建通知 | 业务任务 | 类型、变量、收件人、去重键 | 通知 ID | 通知中心 |
| 查询通知 | 小程序/后台 | 用户、分页、已读状态 | 列表 | 用户隔离 |
| 标记已读 | 小程序/后台 | 通知 ID | 结果 | 幂等 |

## 7. 依赖与影响说明

1. 通知中心复用现有 `notifications` 三表，不新建消息表。
2. 协议到期数据来自 V05；门店归属与 `last_visit_at` 来自 V02；拜访记录来自 V03。
3. D3-A 免审后，不实现绑定审核通知；V04 的绑定成功即时提示不属于本册。
4. 通知只发送站内信；微信渠道如启用，需现有模板与 openid，见 R-V09-02。
5. 通知跳转需校验 V01 的权限与数据范围。
6. 协议/拜访主流程不得因通知失败而失败；通知失败只记录并重试。
