## 一、目标与成功定义

### 1.1 目标

把审查报告中**已在浏览器复现**的 7 类阻断项（B-01 ~ B-07）与双重删除（M-06）清零，并建立防回流的自动化底线。修复以**可访问性、令牌真实性、键盘可达性**为先，不以「与 HiFi 像素级一致」为目标（仓库无 Figma 源文件或批准像素基线，审查报告已判定该维度 Inconclusive）。

### 1.2 使用者与场景

- 后台运营/管理层：桌面键鼠为主，读屏与纯键盘用户必须能完成筛选、录入、删除、查看详情；
- C 端访客：移动端为主，表单字段在输入后仍需保留可访问名称；
- 设计与前端维护者：设计契约（DESIGN.md）与实现之间不再出现「类名不报错但渲染失效」的静默偏离。

### 1.3 成功定义（Program 级）

1. 审查报告中的阻断项全部关闭，每项都有可重跑的 E2E 证据与截图/JSON 工件；
2. 设计契约与实现一致：字体、圆角、图表色板、对比度、版心均有唯一来源或书面例外；
3. 防御机制生效：未定义工具类、字体令牌误用、原生 `confirm`、无障碍命名回退会在提交前被拦截；
4. 后续 P1/P2 按模块推进，不重复审计同一问题。

## 五、Phase 0 详细规格

### 5.1 `token-integrity`

#### 问题

- `layout.tsx:36` 的 `font-(--font-sohne)` 被 Tailwind 编译为 `font-weight`，不是字体族；`--font-sohne` 定义在 `@theme inline`，不输出到 `:root`，`body { font-family: var(--font-sohne) }` 计算值为空，全站回退 `ui-sans-serif`；
- 同根因：`globals.css:66-67` 的 `--font-sans: var(--font-geist-sans)`、`--font-mono: var(--font-geist-mono)` 引用了从未加载的 Geist 变量（`layout.tsx` 只加载 Inter 与 Source Serif 4），`font-sans`/`font-mono` 工具类同样静默失效；
- `.font-display` 定义在 `@layer utilities`，不是 `@utility`，Tailwind 不生成响应式前缀，7 处 `md:font-display` 全部无效；
- `rounded-pill` 未定义（`globals.css` 无 `--radius-pill`），15 处使用计算半径为 0px。

#### 改动文件

| 文件 | 动作 |
|---|---|
| `frontend/src/app/layout.tsx` | 移除 body 的 `font-(--font-sohne)`；保留 `inter.variable` / `sourceSerif.variable` |
| `frontend/src/app/globals.css` | 修正 `--font-sans` / `--font-mono`；body 直接使用 Inter 字体栈；`.font-display` 改为 `@utility`；不改 `@theme inline` 的 `--font-sohne` 别名（保留 DESIGN.md 映射） |
| `frontend/src/app/(main)/admin/settings/workbench/_components/workbench-layout-admin.tsx` | 5 处 `rounded-pill` → `rounded-full` |
| `frontend/src/app/(main)/admin/_components/workbench-customizer.tsx` | 1 处 |
| `frontend/src/app/(main)/admin/page.tsx` | 1 处 |
| `frontend/src/app/(main)/admin/notifications/_components/notification-list.tsx` | 2 处 |
| `frontend/src/app/(main)/admin/notifications/_components/preference-form.tsx` | 2 处 |
| `frontend/src/components/notification-bell.tsx` | 2 处 |
| `frontend/src/components/notifications/notification-item.tsx` | 2 处 |
| `DESIGN.md` | 在 Sohne 段记录「Inter 为已批准的长期替代（自托管）」；不复制实现细节 |
| `frontend/e2e/design-qa-p0-tokens.spec.ts` | 新增（见 §10） |

#### 实现口径

1. `globals.css` 的 `@layer base body` 直接声明字体栈：
   ```css
   font-family:
     var(--font-inter), ui-sans-serif, system-ui, -apple-system,
     BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif;
   ```
   不依赖 `var(--font-sohne)`（该变量在 `@theme inline` 中不落到 `:root`）。
2. `@theme inline` 中：
   - `--font-sans: var(--font-inter), ui-sans-serif, system-ui, ...;`
   - `--font-mono: ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, "Liberation Mono", "Courier New", monospace;`
   - `--font-sohne` 保留为 Inter 栈（供未来 `font-sohne` 工具类使用），但 base 样式不再依赖它。
3. `.font-display` 从 `@layer utilities` 移到顶层 `@utility font-display { ... }`，保留原有四条声明（字体族、400、line-height 1.1、letter-spacing -0.025em）。`@utility` 生成响应式与状态变体，`md:font-display` 才会生效。不要同时定义 `--font-display` 主题令牌，避免与自定义 utility 同名冲突。
4. 15 处 `rounded-pill` 统一替换为 Tailwind 内建 `rounded-full`（9999px），不新增 `--radius-pill` 同义令牌（DESIGN.md 的命名半径无 pill 项）。
5. 不改任何页面布局、字号或颜色；`md:font-display` 生效后桌面端标题会从系统无衬线变为 Source Serif 4，这是 B-06 的预期视觉变化。

#### 验收标准

- 静态：`grep -rn "rounded-pill" frontend/src` 为 0；`grep -rn "font-(--" frontend/src` 为 0；
- 运行时 1280px：
  - `getComputedStyle(document.body).fontFamily` 不以 `ui-sans-serif` 开头，且包含 Inter 的实际 family（next/font/local 生成名）；
  - `document.fonts` 中 Inter 与 Source Serif 4 均为 `loaded`；
  - C 端 `/` 的 `h1` 计算字体族为 Source Serif 4；375px 下仍为无衬线（base 类为 `font-medium`，只有 `md:font-display`）；
  - `/admin/notifications` 三个筛选按钮的 `border-top-left-radius` 为 9999px；
- 截图：`/` 375/1280、`/admin/notifications` 1280、`/admin/settings/workbench` 1280；
- `pnpm typecheck`、`pnpm lint`、`pnpm format:check` 通过。

#### 风险 / 未覆盖

- `font-mono` 修复会让合同编号、金额等从继承无衬线变为等宽字体，属同根因修正但不在审查报告条目内；需在 ledger/audit-logs 截图确认可读性。
- `md:font-display` 生效后 7 处标题的行高/字重从继承值变为 400/1.1，可能改变换行；需设计走查截图。
- 不引入 Sohne 授权字体（D2）；如后续采购，需替换 `layout.tsx` 的 localFont 源与 DESIGN.md 记录。

### 5.4 `keyboard-interaction`

#### 问题

- `components/ui/data-table.tsx:69-74` 的 `<TableRow onClick>` 无 `tabIndex`/`role`/`onKeyDown`；
- 7 个页面的可点击行/卡片可聚焦数为 0：projects（20）、marketing（20）、ledger（8）、reports/market（20）、building-dictionary（20）、communities/images（20）、investments（2）；todo-board 19 张卡片；

#### 改动文件

| 文件 | 动作 |
|---|---|
| `frontend/src/components/ui/data-table.tsx` | 新增 `getRowActionLabel?: (row: TData) => string`；存在 `onRowClick` 时行可聚焦、可读名称、Enter/Space 激活、焦点环 |
| `frontend/src/app/(main)/admin/building-dictionary/_components/overview-client.tsx:289` | 自定义 `TableRow` 套用同一键盘模式 |
| `frontend/src/app/(main)/admin/building-dictionary/review/review-client.tsx:128` | 同上 |
| `frontend/src/app/(main)/admin/reports/market/_components/business-district-table.tsx:162` | 同上 |
| `frontend/src/app/(main)/admin/reports/communities/_components/community-table.tsx:138` | 同上（同类缺陷，审查报告未列但代码确认） |
| `frontend/src/app/(main)/admin/communities/images/_components/image-grid.tsx:102` | 图片卡片可聚焦、Enter/Space 打开预览 |
| `frontend/src/app/(main)/admin/projects/todo-board/_components/todo-project-card.tsx:57` | `<article onClick>` 补可聚焦/名称/键盘处理 |
| 各 DataTable 调用方 | 传入 `getRowActionLabel`（如「打开 XX 项目详情」） |

#### 实现口径

采用仓库内已验证的正例（`leads-table.tsx:97-110`）：

```tsx
<tr
  tabIndex={0}
  aria-label={`打开 ${name} 详情`}
  className="cursor-pointer focus-visible:outline-2 focus-visible:-outline-offset-2 focus-visible:outline-rust"
  onClick={open}
  onKeyDown={(e) => {
    if (e.key === "Enter" || e.key === " ") {
      if (e.target === e.currentTarget) {
        e.preventDefault();
        open();
      }
    }
  }}
>
```

约束：

- **不要**给 `<tr>` 加 `role="button"`（会覆盖 row 语义并触发 `aria-allowed-role`）；沿用正例的「可聚焦行 + 可读名称 + 键盘处理」；
- 卡片内部若有独立按钮，`e.target === e.currentTarget` 守卫必须保留，避免 Enter 触发子按钮时同时打开详情；
- 不引入全局 ClickableRow 抽象；DataTable 内一处实现，自定义表格逐处套用；
- 行/卡片的视觉（hover、间距、阴影）不变，只补焦点环与键盘行为。

#### 验收标准

- 7 个页面 + todo-board：可点击行/卡数量 = 可聚焦数量，且可聚焦数量 > 0（复现审查报告 2.3 的测量口径）；
- 每页至少一条键盘路径：Tab 到行/卡片 → Enter 打开详情/抽屉 → Esc 关闭归焦；
- axe `interactive-supports-focus` 为 0；无新增 `aria-allowed-role` 违规；
- 鼠标点击行为不变，嵌套按钮不触发双重导航。

#### 风险 / 未覆盖

- `aria-label` 加在 `<tr>` 上并非所有读屏都会播报；这是仓库既有正例的延续。如验收要求「播报为按钮」，需在 P1 增加显式「查看详情」链接/按钮，另立方案；
- 只覆盖审查报告实测的 7 个页面 + todo-board；其余列表页由 `guardrails` 的 DOM 度量脚本在 P1 扩展。

## 十、代码规范（本次新增/修改必须遵循）

### 10.1 可点击行（canonical）

```tsx
<tr
  tabIndex={0}
  aria-label={`打开 ${name} 详情`}
  className="cursor-pointer focus-visible:outline-2 focus-visible:-outline-offset-2 focus-visible:outline-rust"
  onClick={open}
  onKeyDown={(e) => {
    if (e.key === "Enter" || e.key === " ") {
      if (e.target === e.currentTarget) {
        e.preventDefault();
        open();
      }
    }
  }}
>
```

约定：`<tr>` 不加 `role="button"`；卡片同理；子交互必须用 `e.target === e.currentTarget` 守卫。

### 10.2 标签关联

```tsx
const id = useId();
<div className="space-y-1.5">
  <label htmlFor={id} className="...">面积 (㎡) *</label>
  <Input id={id} value={area} onChange={...} />
</div>
```

组合控件（地址选择、图片上传）用 `role="group"` + `aria-labelledby`，不把 `<label>` 套多个控件。

### 10.3 Dialog / Sheet

```tsx
<Dialog open={isOpen} onOpenChange={(open) => !open && onClose()}>
  <DialogContent className="max-w-2xl p-0 rounded-cards shadow-steep">
    <DialogTitle>录入新线索</DialogTitle>
    <DialogDescription className="sr-only">填写线索基础信息</DialogDescription>
    ...
  </DialogContent>
</Dialog>
```

不使用自定义 `fixed inset-0` 遮罩；Sheet 必须有 `SheetTitle`，无自然描述时用 `sr-only` 文案。

### 10.4 命名与样式约定

- 图标按钮必须 `aria-label`，格式「动作 + 对象」，行内包含行标识；
- 颜色只使用 `globals.css` 的 Steep 语义 token；禁止 `red-700`、`#5d2a1a` 以外的魔法色值（Warm Ladder 例外见 DESIGN.md）；
- 圆角只用 `rounded-cards` / `rounded-images` / `rounded-inputs` / `rounded-full`；
- 字号不新增 `<12px`；不新增 `font-black`；
- 所有函数/组件保持完整类型注解；不新增 `any`。
