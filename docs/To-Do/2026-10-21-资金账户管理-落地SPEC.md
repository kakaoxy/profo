## 3. 数据模型

### 3.1 新表 `fund_accounts`

```python
class FundAccount(BaseModel):
    __tablename__ = "fund_accounts"
    name: Mapped[str]              # String(24)  唯一（is_deleted=false 部分唯一索引）
    type: Mapped[FundAccountType]  # enum: bank/corp/wechat/alipay/cash
    account_no: Mapped[str | None] # String(40)  卡号后四位/掩码
    holder: Mapped[str | None]     # String(50)  谁的卡
    opening_balance: Mapped[Decimal]  # Numeric(15,2) 期初
    opening_date: Mapped[date]     # Date 从哪天算起
    status: Mapped[FundAccountStatus]  # enum: active/off
    note: Mapped[str | None]       # String(120)
    is_deleted: Mapped[bool]       # 有账 → 只能停用，不可删
```

- 索引：`uq_fund_accounts_name`（`WHERE is_deleted = false` 唯一）、`idx_fund_accounts_status`。
- **余额不落库**（设计稿硬要求）：避免「余额与流水两份数」。

### 3.2 新表 `fund_account_adjustments`

```python
class FundAccountAdjustment(BaseModel):
    __tablename__ = "fund_account_adjustments"
    account_id: Mapped[uuid.UUID]  # Uuid 逻辑外键 → fund_accounts.id
    adjust_date: Mapped[date]      # Date 算在哪天
    amount: Mapped[Decimal]        # Numeric(15,2) 差额，可正可负，≠0
    reason: Mapped[str]            # Text 必填
    operator_id: Mapped[str]       # String(36) 谁调的
    receipt_urls: Mapped[list[str] | None]  # JSONB 截图，可不传
```

- 索引：`idx_fund_adjust_account_date (account_id, adjust_date)`。
- **只加不改不删**（无 PATCH/DELETE 端点），调错再调一笔冲回。

### 3.3 改表 `finance_records`

| 列 | 类型 | 语义 |
|----|------|------|
| `account_id` | `Uuid NULL` | 逻辑外键 → `fund_accounts.id`；**NULL = 显式「没走账户」**，不是「忘填」 |

- 索引 `idx_finance_account_date (account_id, record_date)`。
- 不加数据库 FK 约束（沿用 `subject_id` 做法）。
- 存量数据全部 NULL，**不做任何猜测性回填**。

### 3.4 余额推导（唯一口径，前后端同式）

```
balance = opening_balance
        + Σ(inflow  where account_id = X and is_deleted = false)
        − Σ(outflow where account_id = X and is_deleted = false)
        + Σ(adjustment.amount where account_id = X)
```

浮点安全：后端全程 `Decimal`，仅出参序列化为 `float`（与现有 `CashFlowRecordResponse` 一致）。

## 4. 接口契约（后端）

统一前缀 `/api/v1/admin/accounts`。成功裸返回模型；错误统一 `{"code":≠0,"message":"…"}`。

### 4.1 账户 CRUD

| 方法 / 路径 | 权限 | 说明 |
|------------|------|------|
| `GET /admin/accounts` | `account:read` + 已解锁 | 列表（含 `balance`/`inflow_total`/`outflow_total`/`adjust_total`/`flow_count`/`last_flow_date`），支持 `search`/`type`/`status`/`sort` |
| `GET /admin/accounts/summary` | 同上 | 总览 KPI：`active_count`/`total_balance`/`month_inflow`/`month_outflow`/`adjust_total`/`untracked_count`/`untracked_amount` |
| `GET /admin/accounts/flows` | 同上 | 跨账户流水（分页 + `account_id`/`direction`/`search`/`untracked_only`） |
| `GET /admin/accounts/{id}` | 同上 | 详情（余额推导四段 + 最近流水 + 调整次数） |
| `GET /admin/accounts/{id}/flows` | 同上 | 单账户流水（分页） |
| `GET /admin/accounts/{id}/adjustments` | 同上 | 核对记录列表 |
| `POST /admin/accounts` | `account:write` | 新建（名称唯一，24 字上限） |
| `PATCH /admin/accounts/{id}` | `account:write` | 改信息（改期初 → 响应回传新余额供前端提示） |
| `DELETE /admin/accounts/{id}` | `account:write` | **有流水或调整 → 409**，提示改停用 |
| `POST /admin/accounts/{id}/adjustments` | `account:write` | 对账调整（`amount≠0`、`reason` 必填） |

### 4.2 模块入口锁

| 方法 / 路径 | 权限 | 说明 |
|------------|------|------|
| `GET /admin/accounts/lock-state` | `account:read` | `{has_password, unlocked, seconds_left}`（**不解锁也可调**，供锁屏渲染） |
| `POST /admin/accounts/unlock` | `account:read` | body `{password}` → 成功发令牌（Redis 30 min 滑动）；失败 `attempts_left`；5 次 → 429 + `retry_after_seconds` |
| `POST /admin/accounts/lock` | `account:read` | 手动锁（删除当前令牌） |
| `POST /admin/accounts/module-password` | `account:admin` | 设/改密码（6 位数字，禁 6 位相同，禁与旧密码相同） |

**令牌机制**（实现细节，写进实现注释）：

- Redis key `fund_accounts:unlock:<user_id>:<sha256(token)>`，value `1`，`EX 1800`；每次通过校验 `EXPIRE` 重置 = 滑动过期。
- 令牌 = `secrets.token_urlsafe(32)`，仅通过响应体返回给前端，前端存 `sessionStorage`（关闭标签即失效），请求头 `X-Accounts-Unlock` 携带。
- 密码哈希：复用 `utils/auth/password.py` 的 `get_password_hash`/`verify_password`（Argon2），存 `system_configs` key `fund_accounts.password_hash`（值为密文，`updated_by_id` 记录最后修改人）。
- 失败计数：Redis key `fund_accounts:fail:<user_id>` 计数，TTL 与 15 分钟锁定同批；锁定 key `fund_accounts:lock:<user_id>`。
- **Redis 不可用**：解锁相关端点直接 503（`§4.5` 已定义），不降级放行（Fail Loud）。

### 4.3 记账联动（改 `POST /admin/ledger`）

`LedgerRecordCreate` / `LedgerRecordUpdate` 新增：

| 字段 | 类型 | 校验 |
|------|------|------|
| `account_id` | `UUID4 \| None` | 必须存在、`is_deleted=false`、`status=active`；方向必须对上（`outflow>0` 走付款户、`inflow>0` 走收款户，两者互斥已保证） |
| `account_skipped` | `bool` | `true` 时忽略 `account_id`；**服务端要求 `description` 非空**（写明原因） |

约束落地（`services/projects/finance/records.py`）：

- 新建：`account_skipped or account_id` **不强制**（存量客户端兼容）；若给了 `account_id` 则全量校验。
- 更新（PATCH）：仅当显式传 `account_id`/`account_skipped` 才动账户字段 → **存量补挂**走这条路径，不受「必填」影响（R1）。
- 已结算项目：账户字段与其他字段一样被 `_assert_finance_editable` 拦住。
- 审计：`_record_audit_snapshot` 增补 `account_id`；`FinanceRecordLog.detail` 增补 `account_id`/`account_name`。
- 项目盈亏汇总**不含**账户维度（无需改 `_sync_financial_cache`）。

### 4.4 权限码

| 权限码 | 名称 | admin | operator | user |
|--------|------|-------|----------|------|
| `account:read` | 查看资金账户 | ✓ | ✓ | — |
| `account:write` | 编辑资金账户 | ✓ | ✓ | — |
| `account:admin` | 设置账户密码 | ✓ | — | — |

- 追加到 `migrations/_seeds.py::_PERMISSIONS_SEED` + `_ROLE_PERMISSIONS_SEED`（operator 得 read/write，user 不给）。
- 迁移里 `permissions_customized=TRUE` 的角色**跳过**种子回填（沿用 `migrate_permission_system` 语义）；
  但 `account:read/write` 是全新权限点，采用 `_biz_dicts.py::_ensure_dict_manage_permission` 的
  「新权限点必授 admin」策略，避免上线后管理员打不开页面。

### D-001 · 已删除项目的流水出现在账户流水页，点「补上」报「项目不存在」

**复现（用户）**：账户流水页筛选「没记账户」→ 看到 `共康五村 - 共康五村32号402室 / MFB-202607-0002 / ¥1.00`

**定位（代码事实）**

| 环节 | 事实 |
|------|------|
| 数据 | 项目 `42bf2df6-…`：`is_deleted = TRUE`、`status = DELETED`；其下 23 条 `finance_records` 全部 `is_deleted = FALSE` |

| 后果 C | `_RecordMixin.update_record` 校验项目存在（`Project.is_deleted.is_(False)`）→ 404「项目不存在」；但列表仍显示该行 → **列表与操作能力不一致** |
| 存量规模 | 28 条孤儿流水（涉及 2 个已删项目），其中挂资金账户的 0 条（故未污染账户余额） |

| 层 | 文件 | 改动 |
|----|------|------|
| 代码·不再产生 | `services/projects/core.py::delete_project` | 与项目同事务软删该项目下所有未删流水（保留记录可追溯） |
| 代码·兜底过滤 | `services/finance/fund_account.py::_flow_query` | 增加 `Project.is_deleted.is_(False)` |
| 代码·口径一致 | `services/projects/finance/ledger.py` | 新增 `_alive_records_filter()`（流水未删 **且** 项目未删），`get_overall_stats` 全部改用（原先只有列表页过滤、汇总页没过滤） |

**关键口径（写进代码注释，避免后人误解）**

1. **调整正负折算**：`amount > 0` 计入该行 `inflow`；`amount < 0` 的绝对值计入 `outflow`。
   另用 `adjust_amount` 保留带符号原值。这样「流水页合计」= 「余额公式」，可直接推导余额。
2. **`untracked_only`（没记账户）不含调整行**：调整必然属于某账户，若混入会让
   「去补账户」清单出现无法补挂的行。
3. **`direction` 筛选对调整行生效**：`out` 只出负数调整、`in` 只出正数调整。
4. **必须在 SQL 层 UNION**：分页与合计要作用于合并全集，两段各取 N 条再在 Python 拼会导致
   翻页错位、总额只算到一段。
5. **`receipt_urls` 是 json 列且含 json null**：直接 `json_array_length` 会报
   `cannot get array length of a scalar`，故用 `CASE WHEN json_typeof(...)='array'`。

### D-006 · 「花出去」选项描边被弹窗边界裁切（UI 缺陷）

**现象（用户）**：记一笔弹窗里「花出去」选项的外边框被遮住一部分，看起来选项不完整。

**定位（用 Playwright 量出来的，不是猜）**

```
按钮 rect: {l:440, r:633, t:216.75, b:274.25}
祖先链：
  DIV overflowX=auto overflowY=auto pad=[8px,4px,8px,0px] rect=[440.0,840.0] <<< CLIPS RING
      | grid gap-5 py-2 max-h-[70vh] overflow-y-auto overscroll-contain pr-1
```

| 项 | 事实 |
|----|------|
| 裁切者 | 弹窗表单容器 `overflow-y-auto`（浏览器把 `overflow-x` 也视为 `auto`，形成裁切边界） |
| 根因 | 该容器 padding 为 `[8px, 4px, 8px, **0px**]` —— 左侧为 0；而选项用 `ring-[1.5px]`，ring 绘制在元素**外侧**，紧贴裁切边界 → 左边框被切掉 |
| 为什么右侧也缺 | 右侧仅 4px（`pr-1`），且滚动条出现时会进一步压缩可用宽度 |

**修复（两层，避免只治表面）**

1. **换内描边**：`ring-*` → `inset-ring-*`（Tailwind v4.3.0 支持，实测 `box-shadow` 含 `inset` 关键字）。
   内描边永远绘制在元素内侧，**不会被任何祖先 overflow 裁切，也不改变布局尺寸**。
   涉及：方向选项（选中/未选中）、金额输入框（错误态/聚焦态）、账户选择项与外框。
2. **容器留白**：`py-2 pr-1` → `px-1 py-2`（左右对称留白），作为第二道保险
   —— 万一以后有人改回 `ring`，也不会立刻贴边被切。
