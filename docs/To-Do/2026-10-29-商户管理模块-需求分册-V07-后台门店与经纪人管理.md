## 2. 模块概述与目标

本册实现运营/管理员在后台对门店与经纪人的查询、新建、编辑、停用、启用、软删除、合并、强制解绑/换绑，以及门店详情页的完整档案视图。门店详情聚合基础信息、经纪人列表、拜访时间线、协议区、线索统计（S13、Q39）；门店与经纪人列表支持按权限导出 CSV（Q45）。

后台允许直接新建门店用于补录（Q43）；批量导入是否实现见 R-V07-09；门店删除采用软删除，有拜访、绑定、线索、协议关联时禁止删除（Q44）；经纪人可维护姓名、手机、门店、状态、备注（Q46），手机号加密存储并以 `phone_hash` 唯一（Q47）。

## 4. 功能需求

### 4.1 门店管理

#### REQ-M11-001 后台门店列表与筛选

| 项目 | 内容 |
|---|---|
| 功能描述 | 运营在后台按关键词、区域、商圈、合作状态、负责人、经纪人数量筛选门店列表。 |
| 触发条件 | 进入“商户管理 → 门店列表”。 |
| 主流程 | 1. 默认按更新时间倒序展示；2. 支持关键词搜索门店名称/地址/电话；3. 支持省市区、商圈、合作状态、负责人筛选；4. 支持经纪人数量区间筛选；5. 展示门店名称、公司、区域、地址、合作状态、负责人、经纪人数量、最近拜访时间、状态；6. 点击进入详情。 |
| 分支与异常 | 1. 无结果：空状态；2. 筛选条件非法：忽略并提示；3. 无权限：不展示列表；4. 已合并门店默认不展示，可通过状态筛选查看；已搬迁门店是否默认隐藏见 R-V07-07。 |
| 输入字段 | 关键词、省市区、商圈、合作状态、负责人、经纪人数量、状态、分页 |
| 输出字段 | 门店列表及分页总数 |
| 业务规则 | BR-M11-001：门店列表按数据范围过滤；BR-M11-002：默认排除已删除门店；BR-M11-003：已合并门店保留可追溯入口，不进入普通运营列表。 |
| 权限与角色 | admin/operator；`merchant:read`。 |

#### REQ-M11-002 后台新建门店

| 项目 | 内容 |
|---|---|
| 功能描述 | 运营在后台直接新建门店，用于补录或线下拓展补录；批量导入是否实现见 R-V07-09。 |
| 触发条件 | 点击“新建门店”。 |
| 主流程 | 1. 填写公司、门店名称、省市区、商圈、地址、经纬度、联系人、电话、合作状态、负责人、备注；2. 地图选点；3. 保存；4. `source=后台新增`；5. 生成门店记录；6. 写审计日志。 |
| 分支与异常 | 1. 必填字段缺失：拒绝；2. 公司不存在：先新建公司或选择已有公司；3. 经纬度缺失：拒绝；4. 疑似重复：按 V02 REQ-M01B-002 的名称、地址、500 米、电话四要素提示，允许继续；5. 地址与坐标不一致：提示确认；6. 无权限：拒绝。 |
| 输入字段 | 公司 `id`、门店名称、省市区、商圈、地址、经纬度、联系人、联系电话、合作状态、负责人、备注 |
| 输出字段 | 门店 `id`、状态、`source` |
| 业务规则 | BR-M11-004：后台允许直接新建门店（Q43）；BR-M11-005：后台新建必须按 V02 REQ-M01B-002 的名称、地址、500 米、电话四要素查重，只提示不阻断；BR-M11-006：后台新建门店 `source=后台新增`；BR-M11-007：负责人可为空，后续可分配。 |
| 权限与角色 | admin/operator；`merchant:write`。 |

#### REQ-M11-003 后台编辑门店与状态变更

| 项目 | 内容 |
|---|---|
| 功能描述 | 运营编辑门店基础信息，执行停用、启用、地址纠错或搬迁。 |
| 触发条件 | 门店详情点击“编辑”或状态操作。 |
| 主流程 | 1. 加载门店当前信息；2. 修改允许字段；3. 关键字段（名称、地址、经纬度、合作状态）记录变更前后值；4. 地址/坐标变化时选择“纠错”或“搬迁”；5. 保存；6. 写审计日志。 |
| 分支与异常 | 1. 已合并门店：只读，不可编辑；2. 已删除：不可见；3. 必填字段被清空：拒绝；4. 停用门店：禁止新建拜访/绑定；5. 启用：恢复正常；6. 并发修改：提示冲突并保留日志。 |
| 输入字段 | 门店 `id`、可编辑字段、变更原因 |
| 输出字段 | 更新后的门店、变更前后值 |
| 业务规则 | BR-M11-008：门店状态取正常、停用、已合并、已搬迁；BR-M11-009：地址搬迁按 V02 的 Q12 口径处理；BR-M11-010：所有增删改写入 `operation_logs`（S17）；BR-M11-011：合作状态变更按 V02 REQ-M01B-004 校验协议前置。 |
| 权限与角色 | admin/operator；`merchant:write`。 |
| 状态流转 | 正常 ↔ 停用；正常/停用 → 已搬迁；正常/停用 → 已合并。 |

#### REQ-M11-004 门店软删除

| 项目 | 内容 |
|---|---|
| 功能描述 | 运营删除无关联数据的门店；有拜访、绑定、线索、协议关联时禁止删除。 |
| 触发条件 | 门店列表/详情点击“删除”。 |
| 主流程 | 1. 校验门店关联数据；2. 无关联：二次确认；3. 标记 `is_deleted=true`、记录删除人/时间；4. 从默认列表移除；5. 写审计日志。 |
| 分支与异常 | 1. 存在拜访记录：拒绝并提示；2. 存在经纪人绑定：拒绝；3. 存在线索归属：拒绝；4. 存在协议：拒绝；5. 已删除重复操作：幂等；6. 有权限但非 admin：按角色限制。 |
| 输入字段 | 门店 `id`、删除原因 |
| 输出字段 | 删除结果、阻止原因 |
| 业务规则 | BR-M11-012：门店删除为软删（Q44）；BR-M11-013：有关联数据禁止删除，避免历史断链；BR-M11-014：删除操作必须二次确认并记录原因。 |
| 权限与角色 | admin/operator；`merchant:write`；是否仅 admin 见 R-V07-02。 |

#### REQ-M11-005 门店合并

| 项目 | 内容 |
|---|---|
| 功能描述 | 运营选择保留门店与被合并门店，迁移拜访、经纪人绑定、线索、协议，原门店标记已合并并保留追溯。 |
| 触发条件 | 运营在门店列表/详情发起“合并”。 |
| 主流程 | 1. 选择保留门店；2. 选择唯一被合并门店；3. 展示待迁移数据量；4. 二次确认；5. 迁移拜访 `store_id`；6. 迁移经纪人绑定与 `merchant_brokers.store_id`；7. 迁移线索 `store_id`；8. 迁移门店主体协议 `store_id`；9. 被合并门店 `status=已合并`、`merged_to_store_id=保留门店 id`、记录 `former_store_no`；10. 写审计日志。 |
| 分支与异常 | 1. 保留门店与被合并门店相同：拒绝；2. 被合并门店已合并：拒绝；3. 跨公司合并：提示风险，是否允许见 R-V07-04；4. 经纪人与保留门店已有绑定：去重并保留一条有效绑定；5. 迁移失败：整笔回滚；6. 无权限：拒绝。 |
| 输入字段 | 保留门店 `id`、被合并门店 `id`、合并原因 |
| 输出字段 | 迁移数量、原门店状态、`merged_to_store_id` |
| 业务规则 | BR-M11-015：查重只提示不阻断，合并必须二次确认（S03、Q10）；BR-M11-016：被合并门店历史数据全部迁移，原门店保留 `former_store_no` 作为“曾用门店”追溯（S03）；BR-M11-017：合并只允许 admin/operator 执行（Q10）；BR-M11-018：合并写操作日志，记录迁移前后数量。 |
| 权限与角色 | admin/operator；`merchant:write`；Q10 确认仅这两类角色。 |

#### REQ-M11-006 门店详情与拜访时间线

| 项目 | 内容 |
|---|---|
| 功能描述 | 展示门店完整档案：基础信息、经纪人列表、拜访时间线、协议区、线索统计。 |
| 触发条件 | 点击门店列表项或直接访问门店详情。 |
| 主流程 | 1. 加载基础信息区（可编辑）；2. 加载经纪人列表（姓名、手机、绑定状态、推荐线索数）；3. 加载拜访时间线（时间倒序，员工、照片、联系人、备注）；4. 加载协议区（状态、文件、到期时间）；5. 加载线索统计（累计推荐、本月新增）；6. 各区块按权限展示。 |
| 分支与异常 | 1. 门店不存在/已删除：404 提示；2. 已合并：展示“已合并至 XX（曾用门店号 XX）”并保留只读；3. 无拜访：空状态；4. 无协议：空状态；5. 无权限查看协议：隐藏协议区。 |
| 输入字段 | 门店 `id` |
| 输出字段 | 门店详情聚合对象 |
| 业务规则 | BR-M11-019：详情页信息范围按 Q39 确认：档案、经纪人、拜访、协议、线索统计；BR-M11-020：时间线按拜访时间倒序；BR-M11-021：协议文件下载鉴权；BR-M11-022：线索统计只统计未删除线索。 |
| 权限与角色 | admin/operator；`merchant:read`；敏感字段按 V01 权限。 |

#### REQ-M11-007 门店与经纪人列表导出

#### REQ-M11-009 后台新建与编辑经纪人

| 项目 | 内容 |
|---|---|
| 功能描述 | 运营新建经纪人档案，维护姓名、手机号、所属门店、状态、备注。 |
| 触发条件 | 点击“新建经纪人”或编辑。 |
| 主流程 | 1. 填写姓名、手机号、备注；2. 选择所属门店（可空）；3. 保存档案；4. 手机号加密存储并计算 `phone_hash`；5. 若选择门店，创建有效绑定记录；6. 写审计日志。 |
| 分支与异常 | 1. 手机号重复：拒绝（`phone_hash` 唯一）；2. 姓名/手机号为空：拒绝；3. 门店停用/合并：拒绝绑定；4. 经纪人已有有效绑定：先解绑或走换绑；5. 编辑手机号：更新加密值与哈希，保留历史；6. 无权限：拒绝。 |
| 输入字段 | 姓名、手机号、门店 `id`、状态、备注 |
| 输出字段 | 经纪人 `id`、`bind_status`、`store_id` |
| 业务规则 | BR-M11-030：后台可维护姓名、手机、门店、状态、备注（Q46）；BR-M11-031：手机号加密存储 + `phone_hash` 唯一（Q47）；BR-M11-032：新建时选择门店视为建立有效绑定，绑定历史同步生成；BR-M11-033：手机号变更必须重新计算哈希并校验唯一。 |
| 权限与角色 | admin/operator；`merchant:broker`。 |

#### REQ-M11-010 经纪人停用、启用、强制解绑与换绑

| 项目 | 内容 |
|---|---|
| 功能描述 | 运营停用/启用经纪人，强制解除当前绑定或换绑到其他门店。 |
| 触发条件 | 经纪人列表/详情操作。 |
| 主流程 | 1. 停用：校验/同步解除有效绑定，`bind_status=已停用`；2. 启用：恢复为未绑定；3. 强制解绑：填写原因，原绑定置已解绑，清空 `store_id`；4. 强制换绑：选择新门店，原绑定解绑，新建绑定；5. 每次操作写审计日志。 |
| 分支与异常 | 1. 停用时有有效绑定：先解绑或同步解绑，规则见 R-V07-03；2. 新门店与原门店相同：拒绝；3. 新门店停用/合并：拒绝；4. 经纪人已停用：不可换绑，先启用；5. 解绑原因为空：拒绝；6. 操作失败：整笔回滚。 |
| 输入字段 | 经纪人 `id`、目标状态/新门店 `id`、原因 |
| 输出字段 | 经纪人状态、绑定记录、`store_id` |
| 业务规则 | BR-M11-034：强制解绑/换绑保留绑定历史（V04）；BR-M11-035：换店不迁移历史线索（Q25）；BR-M11-036：停用经纪人不可登录、不可被新绑定（V04）；BR-M11-037：后台强制操作必须记录操作人、原因、前后值。 |
| 权限与角色 | admin/operator；`merchant:broker`。 |
| 状态流转 | 未绑定 ↔ 已绑定；已绑定 → 已解绑；任意 → 已停用；已停用 → 未绑定。 |

## 7. 依赖与影响说明

1. 门店、公司字段与校验复用 V02；拜访记录、协议、线索分别来自 V03、V05、V06，本册只做聚合展示。
2. 经纪人档案与绑定规则复用 V04；后台强制解绑/换绑必须走 V04 的绑定历史记录。
3. 门店合并涉及跨册数据迁移，必须在一个事务内完成，并与 V03/V04/V05/V06 的 Service 层协调。
4. 所有增删改、合并、导出均写 `operation_logs`（V01）。
5. 后台导航“商户管理”分组由 V01 注册；本册页面挂载在门店/经纪人路由下。
6. Q39 详情范围包含档案、经纪人、拜访、协议、线索统计；不包含地图轨迹（V08）。
7. 导出使用 CSV（N08），按权限控制（Q45）。
