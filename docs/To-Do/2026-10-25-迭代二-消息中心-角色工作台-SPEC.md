## 1. 定位与范围

### 1.1 一句话定位

把 4 条各自为战的微信订阅链路，收拢成「**一个事件 → 统一收件人解析 → 站内信（持久化、可已读、可偏好）+ 微信（best-effort）**」；同时把单套 `/admin` 仪表盘换成「**角色默认布局 + 个人定制 + 权限硬门控**」的工作台。

### 3.3 设计稿降级规则（前端必须遵守）

被判定 `❌无源` 的指标，前端按以下规则处理，**禁止**填假数、`--`、`0` 冒充：

| 场景 | 处理 |
|------|------|
| 卡片内单个指标无源（如资金卡「本月回款」） | 该指标格**整格移除**，其余指标自动均分栅格宽度（不留下空洞，也不显示「—」） |
| 整个卡片无源 | 该 widget 从注册表**移除**，不注册、不可配置 |
| 徽标/副文案无源（如「进行中 2 场」） | 只保留主文案，删除 meta 行 |
| 筛选器无源（如「近 30 天」若后端未提供） | 删除该筛选器，不留禁用态 |

**验收要求**：以「设计稿对比清单」形式逐条登记（`docs/To-Do/2026-10-25-迭代二-设计稿偏差登记.md`），每条注明「设计稿有什么 / 实际没有 / 依据（`file:line`）」。

**沿用 v1 仍有效的关键口径（K 系列，保留原文语义）**：K1 站内信唯一事实源、微信 best-effort；K2 业务事务 commit **之后**才 emit；K3 收件人最小化（空 audience → `ValueError`）；K4 `dedupe_key` 唯一 + `ON CONFLICT DO NOTHING`；K5 偏好 `category × channel`，`system`/`security` 不可关站内信；K6 C 端事件不建收件记录；K7 用户隔离在 SQL 层、他人通知 **404 不用 403**；K8 已读幂等；K9 保留 180 天只删已读；K11 三级 fallback；K15 权限硬门控；K16 未知 key 丢弃 + warning。
