## 2. 模块概述与目标

本册实现后台两块可视化能力：门店地图（M09）按区域/商圈/合作状态查看门店分布、经纪人数量与统计；员工拜访轨迹（M10）按员工与日期范围展示打卡点顺序连线、时间线与地图双向联动。地图统一接入高德地图、统一使用 GCJ-02 坐标系（D5、N05）；轨迹只做“到店打卡点顺序连线”，不是连续 GPS（D6、Q40）；本期不设停留时长字段（Q41），地图只做点位不做行政区/商圈边界（Q36）。

## 3. 名词与术语

| GCJ-02 | 国测局坐标系，高德地图使用 | D5 |

## 4. 功能需求

### 4.1 M09 后台门店地图

#### REQ-M09-001 地图接入与坐标系

| 项目 | 内容 |
|---|---|
| 功能描述 | 后台门店地图接入高德地图，所有门店坐标以 GCJ-02 存储与展示。 |
| 触发条件 | 打开“商户管理 → 门店地图”。 |
| 主流程 | 1. 加载高德地图 SDK；2. 读取配置的高德 Key；3. 设置地图中心点与缩放级别；4. 加载门店点位；5. 所有坐标按 GCJ-02 解析；6. 地图容器自适应页面。 |
| 分支与异常 | 1. SDK 加载失败：展示错误与重试；2. Key 无效/配额不足：展示提示；3. 坐标不是 GCJ-02：拒绝打点并记录；4. 浏览器不支持 WebGL：降级提示；5. 无权限：不加载地图。 |
| 输入字段 | 地图中心点、缩放级别、门店坐标集合 |
| 输出字段 | 地图实例、点位 |
| 业务规则 | BR-M09-001：地图供应商为高德（N05）；BR-M09-002：统一 GCJ-02（D5）；BR-M09-003：现有 BD-09 坐标（如 `communities`）进入本图前必须转换，不得混用；BR-M09-004：地图 Key 由配置管理，不写死在前端代码。 |
| 权限与角色 | admin/operator；`merchant:map`。 |

#### REQ-M09-002 门店点位与状态样式

| 项目 | 内容 |
|---|---|
| 功能描述 | 按合作状态使用不同颜色/图标展示门店点位，并提供图例；经纪人自建门店额外显示“未审核”标记。 |
| 触发条件 | 地图加载完成或筛选变化。 |
| 主流程 | 1. 读取门店合作状态；2. 映射颜色/图标；3. 打点；4. 展示图例：未合作、洽谈中、已合作、暂停、终止；5. 点击点位弹出信息卡。 |
| 分支与异常 | 1. 状态值不在字典：使用默认样式并告警；2. 坐标为 0/空：不打点；3. 点位重叠：按聚合规则处理；4. 门店已合并/已删除：默认不展示。 |
| 输入字段 | 门店 `id`、名称、公司、地址、经纬度、合作状态、审核状态、经纪人数量、最近拜访时间 |
| 输出字段 | 点位、图例、信息卡 |
| 业务规则 | BR-M09-005：颜色/图标区分合作状态（S12）；BR-M09-006：信息卡字段为门店名称、公司、地址、经纪人数量、合作状态、审核状态、最近拜访时间（S12、m02721）；BR-M09-007：已合并门店不展示，历史详情仍可按 ID 查看；BR-M09-017：`review_status=未审核` 的门店必须打点并显示待审核标识（m02721）。 |
| 权限与角色 | admin/operator；`merchant:map`。 |

#### REQ-M09-003 地图聚合

| 项目 | 内容 |
|---|---|
| 功能描述 | 地图缩放时自动聚合点位，缩放级别 ≥15 显示单点，<15 按区域聚合。 |
| 触发条件 | 地图缩放/拖拽结束。 |
| 主流程 | 1. 监听缩放级别；2. 级别 ≥15：渲染单门店点位；3. 级别 <15：按区域聚合；4. 聚合点展示门店数量；5. 点击聚合点放大并展开；6. 聚合层级变化时刷新。 |
| 分支与异常 | 1. 聚合计算失败：回退单点；2. 同一区域无门店：不显示；3. 缩放级别临界值：按 ≥15/<15 明确切换；4. 坐标缺失门店：不参与聚合。 |
| 输入字段 | 缩放级别、点位集合、区域字段 |
| 输出字段 | 聚合点/单点 |
| 业务规则 | BR-M09-008：≥15 显示单点，<15 按区域聚合（Q38 确认）；BR-M09-009：聚合使用门店已有 `district` / `business_circle` 字段分组，不绘制行政区/商圈边界；行政区优先还是商圈优先见 R-V08-02【待确认】；BR-M09-010：聚合点数量为区域内门店数。 |
| 权限与角色 | admin/operator；`merchant:map`。 |

#### REQ-M09-004 筛选与统计条

| 项目 | 内容 |
|---|---|
| 功能描述 | 按区域、商圈、合作状态、审核状态筛选，顶部统计门店总数、合作中门店数、经纪人总数。 |
| 触发条件 | 进入地图页或修改筛选。 |
| 主流程 | 1. 选择省市区/商圈/合作状态/审核状态；2. 地图与左侧列表同步刷新；3. 统计条按当前筛选结果计算；4. 展示门店总数、合作中门店数、经纪人总数；5. 清除筛选恢复全量。 |
| 分支与异常 | 1. 无结果：地图空态、统计为 0；2. 经纪人数量按有效绑定统计；3. 合作中定义：合作状态为“已合作”；4. 统计口径与列表不一致：以同一查询结果为准。 |
| 输入字段 | 省市区、商圈、合作状态、审核状态 |
| 输出字段 | 筛选结果、统计数值 |
| 业务规则 | BR-M09-011：筛选维度为区域、商圈、合作状态、审核状态（S12、m02721）；BR-M09-012：统计条三项为门店总数、合作中门店数、经纪人总数（S12）；BR-M09-013：统计只计未删除、未合并门店；BR-M09-018：待审核门店可单独筛选。 |
| 权限与角色 | admin/operator；`merchant:map`。 |

#### REQ-M09-005 门店列表与地图联动

| 项目 | 内容 |
|---|---|
| 功能描述 | 左侧门店列表与地图双向联动：点击列表定位地图，点击点位高亮列表。 |
| 触发条件 | 点击列表项或地图点位。 |
| 主流程 | 1. 列表展示门店名称、地址、合作状态、审核状态、经纪人数量；2. 点击列表项：地图定位到该门店并打开信息卡；3. 点击点位：列表滚动并高亮对应门店；4. 列表与地图使用同一筛选结果。 |
| 分支与异常 | 1. 门店坐标缺失：列表可点，地图提示“坐标缺失”；2. 列表项对应门店已删除：不展示；3. 地图未加载完成：点击列表先记录待定位；4. 无权限：不展示列表。 |
| 输入字段 | 门店 `id`、筛选条件 |
| 输出字段 | 列表、地图定位 |
| 业务规则 | BR-M09-014：列表与地图双向联动（S12）；BR-M09-015：列表默认按最近拜访时间倒序；BR-M09-016：坐标缺失门店只在列表展示，不在地图打点（Q37）；BR-M09-019：待审核门店在列表中显示并可跳转 V07 审核页（m02721）。 |
| 权限与角色 | admin/operator；`merchant:map`。 |

#### REQ-M09-006 坐标缺失处理

| 项目 | 内容 |
|---|---|
| 功能描述 | 门店坐标缺失时，列表展示并提示补全，地图不显示该门店。 |
| 触发条件 | 地图页加载、筛选、点击坐标缺失门店。 |
| 主流程 | 1. 识别 `lng`/`lat` 为空的门店；2. 列表展示“坐标缺失”；3. 地图跳过打点；4. 信息卡/详情提示“请补全地址与坐标”；5. 提供跳转编辑入口（有权限时）。 |
| 分支与异常 | 1. 坐标为 0：按缺失处理；2. 坐标格式非法：按缺失处理并记录；3. 无编辑权限：只提示不提供入口；4. 补全后刷新地图。 |
| 输入字段 | 门店 `id`、坐标、地址 |
| 输出字段 | 提示、编辑入口 |
| 业务规则 | BR-M09-017：坐标缺失门店列表展示、地图不显示（Q37）；BR-M09-018：不自动猜测坐标；BR-M09-019：补全坐标后必须写审计日志。 |
| 权限与角色 | admin/operator；编辑需 `merchant:write`。 |

### 4.2 M10 后台员工拜访轨迹

#### REQ-M10-001 按员工与日期查询轨迹

| 项目 | 内容 |
|---|---|
| 功能描述 | 运营按员工 + 日期查看拜访轨迹，默认当天，支持日期范围。 |
| 触发条件 | 进入“商户管理 → 拜访轨迹”，选择员工与日期。 |
| 主流程 | 1. 选择员工；2. 默认日期为当天；3. 支持选择起止日期；4. 查询该员工在范围内的拜访记录；5. 按 `visited_at` 升序生成轨迹点；6. 展示地图与时间线。 |
| 分支与异常 | 1. 未选择员工：提示选择；2. 无拜访记录：空态；3. 日期范围过大：提示缩小范围，具体上限见 R-V08-04；4. 无权限：拒绝；5. 员工已离职：仍可查历史。 |
| 输入字段 | 员工 `id`、开始日期、结束日期 |
| 输出字段 | 拜访记录列表、轨迹点、当日拜访次数、到访门店数 |
| 业务规则 | BR-M10-001：默认按天查看，支持日期范围（S14）；BR-M10-002：按 `visited_at` 升序连线；BR-M10-003：只查询未删除的拜访记录；BR-M10-004：员工数据范围按 V01 权限。 |
| 权限与角色 | admin/operator；`merchant:map`（轨迹查看统一复用地图权限，见 R-V08-05）。 |

#### REQ-M10-002 打卡点顺序连线

| 项目 | 内容 |
|---|---|
| 功能描述 | 在地图上按拜访时间顺序连接打卡点，形成当天拜访路线。 |
| 触发条件 | 轨迹查询成功。 |
| 主流程 | 1. 取每条拜访记录的 `lng/lat`；2. 按 `visited_at` 升序编号；3. 在地图绘制点与折线；4. 起点/终点使用不同标记；5. 点击点展示拜访摘要；6. 坐标缺失记录不参与连线。 |
| 分支与异常 | 1. 只有 1 个点：只显示点，不画线；2. 坐标缺失：跳过并提示；3. 同一门店多次拜访：按时间保留多个点/序号；4. 坐标异常：跳过并记录。 |
| 输入字段 | 拜访 `id`、`store_id`、`visited_at`、`lng/lat`、照片 |
| 输出字段 | 轨迹点、折线、序号 |
| 业务规则 | BR-M10-005：轨迹为“签到点顺序连线”，不是连续 GPS（D6、Q40）；BR-M10-006：不采集员工连续定位；BR-M10-007：连线不表示实际道路路径；BR-M10-008：坐标缺失的拜访只在时间线展示。 |
| 权限与角色 | admin/operator；`merchant:map`。 |

## 6. 接口与数据

### 6.1 数据对象

#### 6.1.1 地图点位字段（来自 `merchant_stores`）

| 字段 | 必填 | 说明 | 来源 |
|---|---|---|---|
| `id` | 是 | 门店 ID | 8.1 |
| `store_name` | 是 | 门店名称 | 8.1 |
| `company_name` | 是 | 公司名称 | 8.1 |
| `province/city/district` | 是 | 区域 | 8.1 |
| `business_circle` | 是 | 商圈 | 8.1 |
| `address` | 是 | 地址 | 8.1 |
| `lng/lat` | 否 | 经纬度；新建门店时必填，存量/导入门店允许为空（Q37） | 8.1 + Q37 |
| `coordinate_system` | 是 | 必须为 GCJ-02 | 8.1、D5 |
