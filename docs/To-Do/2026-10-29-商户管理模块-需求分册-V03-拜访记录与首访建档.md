## 2. 模块概述与目标

本册负责员工对门店的拜访留痕：新门店首次拜访随建档自动生成，已有门店可重复拜访；拜访记录包含时间、联系人、照片、定位、结果与备注。拜访记录是门店“最近拜访时间”、后台时间线、员工轨迹和拜访提醒的数据源。

本期采用 D6-A“到店打卡点 + 顺序连线”，不做连续 GPS 轨迹；拜访照片全部选拍；拜访结果字典化；允许补录 7 天内拜访并标注；拜访定位与门店坐标距离校验阈值采用 500 米。

## 3. 名词与术语

| 术语 | 定义 | 本册使用说明 |
|---|---|---|
| 拜访记录 | 员工对某门店的一次线下到访记录 | 代码称 `merchant_visits` |
| 首访 | 新门店建档时自动生成的第一条拜访记录 | 与门店创建同事务 |
| 复访 | 对已有门店再次拜访 | 同一员工同日可多次 |
| 到店打卡 | 拜访时获取当前定位并与门店坐标比对 | D6-A 的定位点 |
| 补录 | 补填过去发生的拜访 | 限 7 天内并标注 |
| 拜访结果 | 本次拜访的结构化结论 | 字典 `merchant_visit_result` |
| 距离异常 | 拜访定位与门店坐标超过 500 米 | 提示并记录原因，不强制阻断 |

## 4. 功能需求

### 4.1 首访自动建档

#### REQ-M03-001 新门店首访自动生成

| 项目 | 内容 |
|---|---|
| 功能描述 | 员工新建门店成功后，系统在同一业务事务内自动生成该门店的第一条拜访记录，保证“无拜访不建档”。 |
| 触发条件 | V02 REQ-M01B-001 门店创建提交成功。 |
| 主流程 | 1. 校验门店创建结果；2. 使用当前员工、当前时间、门店 `id` 创建拜访记录；3. 写入联系人、联系电话、照片、定位、拜访结果、备注（若员工已填写）；4. 更新门店 `last_visit_at`；5. 返回门店 `id` 与首访 `id`。 |
| 分支与异常 | 1. 首访创建失败：门店创建回滚，整笔失败；2. 定位授权拒绝：必须授权后提交，不得降级；仅弱网/定位超时允许降级并标注未定位原因；3. 照片为空：允许（Q06 全部选拍）；4. 重复提交：前端幂等，后端按请求幂等键防重。 |
| 输入字段 | 门店 `id`、员工 `id`、拜访时间、联系人、联系电话、照片、经纬度、地址、拜访结果、备注 |
| 输出字段 | 首访 `id`、门店 `id`、`last_visit_at` |
| 业务规则 | BR-M03-001：员工小程序现场新增门店必须绑定一次首访，禁止无拜访建档（S01）；后台补录/导入是否生成补录首访见 V07 R-V07-11【待确认】；BR-M03-002：首访与门店创建同事务，任一失败全部回滚；BR-M03-003：首访默认 `visited_at` 为提交时间；BR-M03-004：首访记录来源标记为“首访建档”，字段名待技术方案确认。 |
| 权限与角色 | 员工 `merchant:write` + `merchant:visit`；admin/operator 后台代建按 V07 处理。 |
| 状态流转 | 拜访记录创建后为有效记录；本期不提供员工删除入口，是否开放编辑/删除见 R-V03-01。 |

### 4.2 已有门店拜访

#### REQ-M03-002 拜访登记

| 项目 | 内容 |
|---|---|
| 功能描述 | 员工选择已有门店，填写本次拜访信息并提交，生成新的拜访记录。 |
| 触发条件 | 员工在“拜访登记”中搜索并选中已有门店，或从“附近门店”列表选择。 |
| 主流程 | 1. 选择门店；2. 系统展示门店名称、地址、当前合作状态；3. 获取当前定位；4. 拍照或从相册选择照片；5. 填写本次联系人、联系电话、拜访结果、备注；6. 提交；7. 生成拜访记录；8. 更新门店 `last_visit_at`；9. 如合作状态变化，转 V02 REQ-M01B-004。 |
| 分支与异常 | 1. 门店已停用/已合并：禁止新建拜访；2. 定位授权拒绝：不得降级，需授权后提交；仅弱网/超时允许降级并标注未定位；3. 距离超过 500 米：提示异常并要求填写原因，允许提交；4. 必填字段缺失：拒绝；5. 同一员工同日多次拜访：允许，生成多条记录。 |
| 输入字段 | 门店 `id`、拜访时间、联系人、联系电话、照片、定位、地址、拜访结果、备注 |
| 输出字段 | 拜访 `id`、门店 `last_visit_at`、合作状态变更结果（如有） |
| 业务规则 | BR-M03-005：允许同一员工一天内多次拜访同一门店（S02）；BR-M03-006：拜访时间默认当前时间；补录按 REQ-M03-006；BR-M03-007：拜访定位默认取当前 GPS，并与门店坐标做距离校验；BR-M03-008：照片张数与是否强制按 Q06 执行，全部选拍；BR-M03-009：拜访结果按 Q07 字典化。 |
| 权限与角色 | 员工 `merchant:visit`，且门店在本人数据范围内；admin/operator 可查看，不代填员工拜访。 |

#### REQ-M03-003 拜访拍照与附件

| 项目 | 内容 |
|---|---|
| 功能描述 | 员工在拜访中拍摄或上传门店照片，作为拜访佐证。 |
| 触发条件 | 拜访登记页面点击“拍照/相册”。 |
| 主流程 | 1. 调起相机或相册；2. 选择照片；3. 上传文件服务；4. 返回文件地址；5. 保存到拜访记录 `photos`。 |
| 分支与异常 | 1. 用户取消：不添加照片；2. 上传失败：提示重试，不清空已填表单；3. 文件格式不在白名单：拒绝；4. 超过大小上限：拒绝并提示；5. 无照片：允许提交（Q06）。 |
| 输入字段 | 图片文件、拜访 `id` |
| 输出字段 | 文件地址列表 `photos` |
| 业务规则 | BR-M03-010：拜访照片全部选拍，不强制门头照（Q06 覆盖 8.4 原文“至少 1 张门头照”）；BR-M03-011：照片格式以现有 C 端上传白名单为准，jpg/jpeg/png；BR-M03-012：拜访照片保存到 `merchant_visits.photos`，不替代门店档案照片；门店照片补录见 V02 REQ-M01B-006。 |
| 权限与角色 | 拜访登记人；文件上传权限按现有 C 端上传能力。 |

#### REQ-M03-004 拜访定位与距离校验

| 项目 | 内容 |
|---|---|
| 功能描述 | 获取员工当前定位，与门店 GCJ-02 坐标计算距离，超过阈值时提示异常并记录原因。 |
| 触发条件 | 拜访登记页面加载或点击“获取定位”。 |
| 主流程 | 1. 请求定位权限；2. 获取 GCJ-02 坐标；3. 与门店坐标计算直线距离；4. 小于等于 500 米：正常保存；5. 大于 500 米：弹出异常提示，要求填写原因；6. 保存定位与距离结果。 |
| 分支与异常 | 1. 用户拒绝定位授权：提示必须授权定位后才能提交（Q05 强制定位），不得降级；2. 定位超时或弱网：允许重试或降级，标注“未定位”原因；3. 门店无坐标：不能计算距离，提示先补全门店坐标；4. 坐标系不一致：统一转换为 GCJ-02 后再计算。 |
| 输入字段 | 拜访 `id`、当前经纬度、门店经纬度、异常原因 |
| 输出字段 | `lng`、`lat`、`address`、距离、定位状态 |
| 业务规则 | BR-M03-013：正常情况下必须获取定位（Q05）；BR-M03-014：仅弱网或定位超时允许降级提交，必须标注未定位原因，用户拒绝授权不适用降级；BR-M03-015：距离阈值 500 米（N07）；BR-M03-016：超过 500 米提示异常并记录原因，不强制阻断；BR-M03-017【待确认】：距离仅用于提示与复盘，不作为考勤或绩效依据（原文未规定，待业务确认）。 |
| 权限与角色 | 拜访登记人。 |

#### REQ-M03-005 拜访结果与备注

| 项目 | 内容 |
|---|---|
| 功能描述 | 记录本次拜访的结构化结果与文字备注。 |
| 触发条件 | 拜访登记提交前。 |
| 主流程 | 1. 选择拜访结果；2. 填写备注；3. 提交；4. 结果写入 `result`，备注写入 `remark`。 |
| 分支与异常 | 1. 拜访结果为空：允许提交，结果为空；2. 字典项停用：不可新选，历史值可展示；3. 备注超长：按字段长度限制提示。 |
| 输入字段 | 拜访结果、备注 |
| 输出字段 | `result`、`remark` |
| 业务规则 | BR-M03-018：拜访结果字典为未见到人、有意向、已合作、其他（Q07）；BR-M03-019：拜访结果不直接改变门店合作状态，状态变更走 V02 REQ-M01B-004；BR-M03-020：备注为自由文本，不参与统计。 |
| 权限与角色 | 拜访登记人。 |

#### REQ-M03-006 拜访补录

| 项目 | 内容 |
|---|---|
| 功能描述 | 允许员工补录过去 7 天内发生的拜访，并标注“补录”。 |
| 触发条件 | 员工在拜访登记页选择“补录拜访”。 |
| 主流程 | 1. 选择门店；2. 选择拜访时间；3. 校验时间在 7 天内；4. 填写联系人、照片、定位、结果、备注；5. 提交；6. 记录标记为补录；7. 更新门店 `last_visit_at`（仅当补录时间更晚）。 |
| 分支与异常 | 1. 超过 7 天：拒绝并提示；2. 未来时间：拒绝；3. 补录定位无法获取：允许标注未定位；4. 补录记录与已有记录时间冲突：允许，保留多条。 |
| 输入字段 | 门店 `id`、补录拜访时间、拜访字段、补录原因（写入 `remark`） |
| 输出字段 | 拜访 `id`、补录标记 |
| 业务规则 | BR-M03-021：补录时间范围为 7 天内（Q08）；BR-M03-022：补录记录必须标注“补录”，后台时间线与导出可见；BR-M03-023：补录不改变门店创建时间或首访记录；BR-M03-024：补录原因写入 `remark` 字段并在时间线展示，不新增独立字段。 |
| 权限与角色 | 员工 `merchant:visit`，仅本人数据范围。 |

#### REQ-M03-007 最近拜访时间与门店时间线

| 项目 | 内容 |
|---|---|
| 功能描述 | 每次拜访成功后更新门店最近拜访时间，并在门店详情按时间倒序展示拜访时间线。 |
| 触发条件 | 拜访记录创建成功；或后台打开门店详情。 |
| 主流程 | 1. 拜访保存成功；2. 比较 `visited_at` 与门店 `last_visit_at`；3. 新记录更晚时更新；4. 门店详情查询拜访列表；5. 按 `visited_at` 倒序展示员工、照片、联系人、备注、结果。 |
| 分支与异常 | 1. 补录时间早于当前 `last_visit_at`：不更新；2. 门店已合并：时间线迁移到保留门店（V07）；3. 无拜访记录：展示空状态；4. 无权限：不展示员工敏感信息。 |
| 输入字段 | 门店 `id`、拜访记录 |
| 输出字段 | `last_visit_at`、拜访时间线 |
| 业务规则 | BR-M03-025：`last_visit_at` 取所有有效拜访记录中最大的 `visited_at`；BR-M03-026：时间线默认按时间倒序，支持分页；BR-M03-027：后台时间线的完整展示由 V07 实现，本册提供数据契约。 |
| 权限与角色 | 门店详情查看权限；员工仅本人门店，admin/operator 全量。 |

## 7. 依赖与影响说明

1. 本册依赖 V02 的门店创建事务；首访创建失败必须回滚门店。
2. 拜访记录是 V07 门店详情时间线、V08 员工轨迹、V09 拜访提醒的唯一数据源。
3. 拜访照片复用现有文件上传服务；C 端上传仅支持 jpg/jpeg/png。
4. 员工位置轨迹属于个人信息，V08 展示必须遵守 Q42 的告知与最小必要原则。
5. 拜访结果字典由 V01 注册，本册不硬编码枚举值。
6. 门店合作状态变更由 V02 处理，本册只负责触发。
