## 一、结论摘要

- **详情页是三状态盲的**：`miniapp/pages/projects/detail/` 全目录对 `project_status` 的引用为 **0 处**。在售 / 装修中 / 过往案例三种状态渲染出同一套界面——同一枚深色「调价提醒」胶囊、同一张「贷款参考」卡、同一个「想看房」主 CTA；跨状态文本 diff 显示 03-装修中 与 01-在售 仅差 1 个节点（标题后缀），02-已售 仅差数据与「挂牌价→成交价」措辞。
- **已售态仍在 soliciting 看房**：298 条「已售·发布」房源经公开接口可达，详情页对其展示「想看房」并可真实提交——后端读/写口径（`backend/services/marketing/public.py:335-347`、`:566-578`）只校验 `is_deleted + publish_status`，不校验 `project_status`，故已售房源的预约/调价订阅能成功落库。
- **同产品内状态标识不一致**：列表页有三态徽章（在售=apricot / 装修中=sky / 过往案例=fog），Web C 端详情页有 `STATUS_MAP` 徽章，唯独小程序详情页没有任何状态标识。
- **装修中态在生产不可达且无设计稿**：公开列表 `project_status=在途` 返回 total=0（库内 6 条在途均为草稿且零媒体），列表页「装修中」tab 恒空；本次装修中渲染来自明确标注的合成 fixture。三状态无任何 SCREEN_SPEC/设计稿约束（仅有在售态 HiFi）。
- **量化缺陷**：9 个选择器 WCAG AA 对比度失败（最差 `.loan-tip` 2.27:1），axe `color-contrast` serious 16 节点（全状态 × 3 视口）；2 处 10px 字号；2 处 <44px 热区；320px 下主价格折成两行（价格行高 90px vs 375/414 的 45px）；`total_price=0` 时渲染「¥ 0 万」。
- **加载/空/错态过薄**：loading 与 404 仅一行灰字（无骨架、无返回动作），错误态重试按钮 46×25px。

## 二、复核方式与证据

### 2.1 渲染链路与边界

微信小程序页面无法在浏览器直接运行，本次采用保真度优先的重构链路：

1. **真实逻辑**：esbuild 将 `miniapp/pages/projects/detail/index.ts` 及其真实依赖（utils/request、utils/url、utils/token、utils/marketing-notify、utils/loan-calc）打包为 CJS；Node 层**仅 stub `wx` 平台 API**（request 路由到 fixture、storage、toast/modal、导航），真实执行 `onLoad/onShow` 与全部 setData 流程，产出 8 份数据快照。
2. **真实样式**：Playwright 页面注入 `miniapp/app.wxss` + `index.wxss` 原文（仅做 rpx→px 换算，1rpx=0.5px），DOM 类名与 `index.wxml` 逐一对应。
3. **度量**：页内计算样式（字号/字重/行高/有效背景合成后的 WCAG 对比度）、点击热区尺寸、布局溢出、圆角；axe-core 4.11.1（wcag2a/wcag2aa/wcag21aa）。
4. **截图**：320/375/414 @2x，每用例首屏 + 全页（footer 置静态以截全页）。

**边界声明**：

- swiper / video / button(open-type=share) 以浏览器原生组件近似（`object-fit: cover`、原生 `<video>` 控件、button 样式重置），**不等同于微信原生组件像素表现**；真机渲染差异（字体抗锯齿、swiper 指示点、video 控件样式）未验证。
- axe `document-title` 违规为重构 HTML 无 `<title>` 所致；小程序标题由 `navigationBarTitleText` 提供，**非真实缺陷**。
- axe `scrollable-region-focusable`（`.renovation-hort`）为 Web 键盘语义；小程序为纯触摸环境，记为可接受差异（但横滑提示缺失另记 Minor）。
- 装修中用例为**合成 fixture**（骨架取自真实 306 payload，媒体/阶段按在途语义裁剪并明确标注），因在途状态公开接口不可达。
- 所有产物中顾问 phone / wechat_number 已替换为 `[REDACTED]`，未写入任何真实凭据或 PII。

## 三、Blockers

### B-01 详情页对 `project_status` 完全不感知，三状态 UI 同构

- **Severity**: blocker
- **Evidence**: `miniapp/pages/projects/detail/` 全目录 grep `project_status` = 0 匹配；跨状态文本 diff：03-renovating vs 01-on-sale 仅 1 个节点差异（`.detail-title` 后缀），02-sold 仅数据 + 「挂牌价→成交价」（`index.ts:567-571`）差异；截图 01 与 03 首屏视觉一致。
- **Observed**: 三种状态渲染同一界面：深色「调价提醒」胶囊（`index.wxml:77`）、「贷款参考」卡（`:132`）、「想看房」主 CTA（`:265`）全部原样出现；无任何状态徽章/横幅/措辞差异。
- **Expected**: 与同产品既有实现一致的状态标识：列表页三态徽章（`miniapp/pages/projects/list/index.ts:329-348`，badge-apricot/sky/fog）、Web C 端详情页 `STATUS_MAP` 徽章（`frontend/src/app/(c)/projects/[id]/page.tsx:21-34`）。
- **User/design impact**: 用户在详情页无法判断房源当前可售性；从列表页带徽章进入详情页后状态标识消失，认知断裂；装修中房源一旦发布将以「在售」面貌示人。
- **Recommended fix**: 详情页读取 `project_status` 并渲染与列表页同 token 的状态徽章（复用/抽取共享 badge 组件，见 D-02）；装修中/已售态调整头部信息架构（见 B-02）。
- **Verification**: 重跑 `tmp/qa-miniapp-detail/dump-states.mjs` + `render.mjs`，跨状态文本 diff 应出现徽章节点与状态化措辞差异；三视口截图复核。

### B-02 已售（过往案例）仍提供「想看房」「调价提醒」「贷款参考」，且后端不校验状态

- **Severity**: blocker
- **Evidence**: 02-sold 截图：¥216 万 + 成交价 chip 之下仍是调价提醒胶囊、贷款参考卡、想看房 CTA；DB「已售·发布」=298 条经公开接口可达；后端读口径 `backend/services/marketing/public.py:335-347` 与写口径 `:566-578`（`create_booking` 于 `:416` 调用）仅过滤 `is_deleted + publish_status`，**无 `project_status` 校验**（`:681/:693` 的状态过滤仅用于平台统计聚合）。
- **Observed**: 已售房源详情页可点击「想看房」并真实提交预约；「调价提醒」对价格已固化的成交房源仍可订阅；「页面价格可能随市场调整」提示语（`.price-note`）与成交事实矛盾。
- **Expected**: 过往案例应以「成交展示」为信息架构：成交价 + 成交周期/改造回顾为主，移除或替换看房 CTA（如「看看同小区在售」），移除调价提醒与贷款参考。
- **User/design impact**: 误导用户提交无效看房预约与无效订阅（脏数据进入线索/订阅表）；对已售房源 soliciting 看房存在广告合规风险。
- **Recommended fix**: 前端按 `project_status=="已售"` 切换 footer 与头部动作区；后端 `create_booking` / 订阅 report 增加状态校验（已售拒绝或改语义），前后端同步。
- **Verification**: 对已售 id 调用预约接口应返回 4xx；重跑渲染链路确认已售态无看房/订阅入口；E2E 留档。

## 四、Major Issues

### M-01 `total_price=0` 渲染为「¥ 0 万」

- **Severity**: major
- **Evidence**: 04-renovating-price-zero 快照与截图：主价格「¥ 0 万」、信息格「0万」「0万/㎡」、仍带「挂牌价」chip；贷款卡因金额为 0 被隐藏（逻辑正确），但价格区把「缺数据」渲染成「价格 0」。
- **Observed**: 0 被当作合法价格展示。
- **Expected**: 无有效总价时显示「价格待定」或隐藏价格区与挂牌价 chip（在途/草稿转发布场景常见缺价）。
- **Recommended fix**: `index.ts` 价格组装处对 `total_price<=0` 走缺省分支；信息格单价同判。
- **Verification**: 04 用例重渲染应无「¥ 0 万」节点。

### M-02 系统性 WCAG AA 对比度失败（9 选择器，axe serious ×16 节点）

- **Severity**: major
- **Evidence**: 375px 在售态计算样式（有效背景合成后）：

| 选择器 | 样例 | 字号 | 对比度 | AA(4.5) |
|---|---|---|---|---|
| `.loan-tip` | 以等额本息估算… | 11px | **2.27** | ✗ |
| `.share-btn` | 分享 | 12px | 3.02 | ✗ |
| `.price-scope` | 挂牌价 | 10px | 3.88 | ✗ |
| `.info-label` / `.loan-k` | 总价 / 首付 | 12px | 3.95 | ✗ |
| `.loan-u` / `.loan-sum` | 万 / 3.05% | 12.5px | 3.95 | ✗ |
| `.price-note` / `.renovation-meta` | 页面价格可能… / 完成于… | 11-12px | 4.23 | ✗ |
| `.state`（06/07/08） | 项目不存在 | 14px | 3.95 | ✗ |

  axe `color-contrast` impact=serious：01/02/03 于 320/375 = 16 节点、414 = 17 节点；04 = 10/11 节点；全状态 × 全视口复现。
- **Observed**: 次要说明文字普遍使用 `--dove`/`--graphite` 于 `--fog`/半透明底上，低于 4.5:1。
- **Expected**: 正文与说明文字 ≥4.5:1（WCAG AA）；令牌层提供达标的 muted 色阶。
- **Recommended fix**: 在 `miniapp/app.wxss` 令牌层调整 muted 色阶或底色（见 D-01），避免页面级逐条覆盖；`.share-btn` 提高遮罩底不透明度或加文字描边。
- **Verification**: 重跑度量，`wcagAA` 全 true；axe `color-contrast` 节点归零。

### M-03 320px 视口主价格折行

- **Severity**: major
- **Evidence**: 320px 度量 `.detail-price-row` 高 90px（375/414 为 45px）；截图 01-on-sale-320-top：「¥ 228」/「万」折两行，「挂牌价」chip 折成「挂牌/价」两行，标题与 chip 区被整体下压。
- **Observed**: 小屏（320dp，iPhone SE1/部分 Android）主价格与 scope chip 折行破坏首屏层级。
- **Expected**: 主价格单行不折（价格字号随视口收缩或 scope chip 换行策略受控）。
- **Recommended fix**: `.detail-price` 增 `white-space: nowrap` + 320 断点下缩字号/缩 chip 内边距，或允许 chip 下沉独立行但保持价格单行。
- **Verification**: 320px 重渲染，`.detail-price-row` 高 ≤45px 且价格单行。

### M-04 装修中态生产不可达且三状态无设计契约（needs-design-decision）

- **Severity**: major（含设计决策请求）
- **Evidence**: 公开列表 `project_status=在途` total=0；DB 6 条在途均为草稿且零媒体（公开详情 404）；列表页「装修中」tab 恒空 → 详情页在途渲染无真实入口； Explore 复核确认三状态无 SCREEN_SPEC/设计稿（仅在售态 HiFi `docs/Done/2026-10-02-贷款计算器-高保真设计稿.html`，状态徽章仅见列表页与 `docs/Done/2026-10-04-上新调价订阅通知-高保真设计稿.html:743`）。
- **Observed**: 装修中态的界面完全由在售态代码路径「顺带」产出，未经任何设计定义。
- **Expected**: 三状态各自的信息架构定义（装修中：改造过程前置、无看房 CTA 或改为「开工提醒」；已售：成交展示；在售：现状）。
- **Recommended fix**: 由设计侧补三状态 SCREEN_SPEC 或 HiFi，再实施 B-01/B-02；在此之前至少落地徽章 + CTA 状态化的最小共识。
- **Verification**: 设计稿评审记录 + 实施后三状态渲染 diff 符合稿面。

## 五、Minor Issues

### m-01 10px 字号两处

- `.price-scope`（`index.wxml:73`，挂牌价/成交价 chip）与 `.advisor-role`（`:261`，房源顾问角色）计算字号 10px，低于中文可读下限（建议 ≥11px）。与 M-02 叠加后 chip 既小又低对比。建议 11px + 达标对比度。

### m-02 点击热区 <44px 两处

- `.price-alert-btn` 136×26px（`:77`，订阅主入口之一）；`.retry-btn` 46×25px（`:15`，错误态唯一恢复路径）。建议高度 ≥44px（或 ≥32px 并扩 padding 热区）。WCAG 2.2 AA 24px 下限虽满足，但拇指目标偏小。

### m-03 加载/空/错态设计过薄

- 06-loading 单行灰字无骨架屏（首屏布局跳变）；07-not-found 单行灰字无图标/无「返回列表」动作（用户只能系统返回）；08-error 有重试但按钮过小（见 m-02）；05-no-gallery 的分享钮悬浮于灰色占位区上方，视觉悬浮无依附。建议统一 state 组件：图标 + 主文案 + 动作按钮 + 骨架屏变体。

### m-04 改造过程横滑缺提示

- `.renovation-hort` 为横向滚动（375px scrollW 692 vs clientW 335），右缘卡片与「完成于 20…」被硬切（截图 01-full）；无渐变遮罩/滚动指示/「滑动查看」提示，用户可能不知存在更多阶段。建议右缘渐变 + 阶段计数（如 4/6）。
