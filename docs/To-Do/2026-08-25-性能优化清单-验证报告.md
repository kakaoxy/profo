## 二、验证修正与补充

### 修正①：P-04 触发时机（清单表述偏差）

清单称「首页与 about 页**每次进入**触发」。实际：

- `projects/list/index.ts:182-185`：`onLoad` 中调用 `loadServedCount()`；
- `about/index/index.ts:63-66`：同样在 `onLoad` 调用；
- tabBar 页 `onLoad` **仅在页面实例首次创建时触发一次**，切 tab 不触发 → 动画并非"每次进入"执行，而是**首次加载各一次**。

影响评估：问题严重度比清单描述**略低**（触发频率为首次而非每次），但 16ms 高频 setData 本身仍成立，且动画期与列表首屏渲染重叠（首页 `onLoad` 同时 `loadList(true)` + `loadServedCount()`），仍建议治理。

### 修正②：P-04 无泄漏（对清单 P-09 的交叉确认）

`served-count` 动画 timer 无泄漏风险：
- 动画自结束：`served-count.ts:55-58` `t>=1` 时自动 `clearServedCountTimer`；
- 页面兜底：`projects/list/index.ts:193-194`、`about/index/index.ts:67-69` 均有 `onUnload` 清理。

### 补充③：P-10 清单遗漏 —— CI 无 miniapp 门禁（实际比描述更严重）

清单仅提及「CI 中 `pnpm test` + `tsc --noEmit` 双门禁」作为目标，但未指出现状缺失程度：

- `.github/workflows/lint.yml` 仅覆盖 **backend**（ruff/uv audit）与 **frontend**（tsc/eslint/prettier/audit）；
- **miniapp 目录完全不在 CI 中**：`miniapp` 的 `tsc --noEmit`、`vitest run` 均无任何门禁，`package.json` 中虽已声明 `tsc`/`test` 脚本，但无 CI 消费。

**此项升级为 P0 建议**：与 P-10 一并实施——CI 增加 `miniapp` job（`pnpm install --frozen-lockfile` → `tsc --noEmit` → `vitest run`），改动成本低、收益确定。

### 补充④：P-06 回退通道无 page_size 上限（确认清单 F10 依赖）

`project-list-page.ts:171-192` 的 `GET /projects/my-responsible` 返回全量裸数组，清单已列为 F10 依赖项，验证确认现状如此，无额外发现。
