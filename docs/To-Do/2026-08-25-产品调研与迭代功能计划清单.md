## 二、产品现状总览

### 2.1 产品定位

「美房宝」是房产「收旧改新」业务的微信小程序，**双受众设计**：

- **C 端客户**：浏览改造房源 → 想看房预约；提交估价留资 → 查看评估结果与小区行情
- **内部员工移动工作台**：三类分享获客（房源/评估/招募，含归因漏斗）、市场数据分析、项目记账、带看/装修过程管理、区域伙伴招募落地

技术形态：原生微信小程序（TypeScript），27 页面全主包、tabBar 4 tab（房源/服务/估价/我的），后端 FastAPI + PostgreSQL，API 类型 `pnpm gen-api` 自动生成（`types/api-types.d.ts` 约 2.08 万行）。

### 2.3 用户反馈现状 ⚠️

无真实反馈数据（见第一节标注）。从代码审查推断的**最影响 C 端体验的 5 个缺口**：

1. 估价链路被拦到测试登录页（转化漏斗断裂）
2. 临时账号无法升级/合并（换机用户身份丢失，影响线索归属准确性）
3. 「我的预约」永远「待联系」，用户无法感知服务推进（预约闭环后半段缺失）
4. 详情图集视频黑块（营销第一屏观感受损）
5. 弱网翻页丢数据（房源集合静默残缺）

### 2.4 市场竞争态势

**行业大势（公开资料）：**

- **端口模式衰退，自有私域成为共识**：安居客端口费一路上涨至全网通套餐约 1000~1500 元/月/人，同时平台来的客户成交率被业内反映从约 40% 降至 20%；越来越多中小中介从「买端口」转向自建品牌小程序沉淀私域。
- **流量结构迁移**：《2026 年百万房产经纪人生存报告》口径显示传统门店咨询占比降至约 19.7%，短视频平台升至约 44.1%；个体 IP 与内容化获客崛起。
- **AI 入口前移**：业内观察称超七成购房者进售楼处前先咨询 AI 大模型获取楼盘推荐，内容与数据的「可被引用性」成为新战场。
- **竞品分层**：
  - 平台型：贝壳找房（ACN 合作网络+效果付费）、安居客/58（端口流量）；
  - SaaS 型：房管家 ACN 微店铺等（微站/微店铺，主打免费私域获客，宣称月新增线索 +40%）；
  - 开发商自营：万科易选房、龙湖 U 享家、越秀房宝等集团私域小程序。

**美房宝差异化定位与启示：**

- 差异化资产：① 真实改造案例全过程展示（五阶段改造记录，竞品普遍没有「改造过程」叙事）；② 免费估价工具 + 小区行情分析（专业信任型内容获客，对标「经纪人发行情资讯年积累 10 万客户」的行业打法）；③ 三类分享的员工级归因漏斗（分享/PV/UV/留资，昨日+累计）已统一口径——这是向 SaaS 竞品看齐的能力。
- 启示 1：**内容即获客**——行情图表应可导出转发、可订阅推送（当前只能被动查询）。
- 启示 2：**裂变玩法缺失**——竞品已有助力/拼团类引擎，我方归因基建已就绪，具备低成本上裂变活动的条件。
- 启示 3：**AI 问答/智能推荐**可作为 Q4 预研方向，暂不投入。

### 2.5 技术实现状况小结

亮点：TS 全覆盖 + API 类型自动生成；请求层 401 双端令牌自动续期（单飞防并发刷新）；「瘦页面肥工具」分层使核心逻辑可单测（6 个 vitest 测试文件覆盖纯函数）；页面状态机完备（loading/骨架/empty/error/needLogin/unauthorized 全覆盖）；首屏 Promise.all 并行已成惯例。

短板：27 页全主包无分包、无 `lazyCodeLoading`；全部 image 无 `lazy-load`；数字滚动动画 16ms 高频 setData；追加分页整列表重算重传；核心网络层零测试。**详见性能优化清单。**

### V1.2 功能迭代：转化与服务闭环（P1 ｜ 时间窗：09.01 ~ 09.12）

> 目标：把三条主链路的「最后一公里」补齐——预约有人跟、线索能沉淀、身份打得通。

#### F1 预约状态流转闭环（需求源头：bookings 硬编码「待联系」）

- **目标**：`project_bookings` 增加状态机（`pending 待联系 → contacted 已联系 → viewed 已安排带看 → closed 已关闭`）；工作人员在后台变更状态；C 端「我的预约」实时展示状态标签与时间线；状态推进时通过**微信订阅消息**通知客户（复用招募线已有的 subscribe 基建与手势授权链路）。
- **改动层**：后端（状态字段迁移幂等 + 变更接口 + 后台操作入口）+ 小程序（bookings/mine 卡片状态区 + 订阅授权）。
- **预期用户价值**：客户预约后可感知「有没有人联系我/安排得怎样」，消除预约后的焦虑与流失；对员工侧形成跟进提醒压力，提升预约→带看转化。
- **验收标准**：预约→后台改状态→客户端下拉可见新状态且收到订阅消息；旧数据默认 pending 幂等迁移。
- **依赖**：订阅消息模板申请（提前一周提审）；后台管理端配套操作 UI。

#### F2 线索跟进闭环（recruit/mine + valuation 获客）

- **目标**：「联系客户」增加二次确认；新增轻量跟进记录（一句话备注 + 时间戳时间线 + 可选下次提醒）；待跟进角标（今日未跟进数）；new→contacted 流转保留但补充显式动作。
- **改动层**：后端（leads 增 follow-up 子资源）+ 小程序（recruit/mine、valuation/mine 共用跟进组件）。
- **预期用户价值**（员工侧）：转化过程数据留痕，离职/交接不丢上下文；待跟进角标直接提升线索响应速度——行业共识「线索响应速度决定成交率」。
- **验收标准**：备注→列表时间线可见；角标计数准确；拨打误触可取消。

#### F3 账号合并 SMS 通道

- **目标**：开通短信验证码服务，打通 `bind-account` 外部用户 Tab 与 `phone-bind-modal` 的手机号合并分支（当前整体 toast 占位，`bind-account/index.ts:91-94,153-157`）；后端补 SMS 发送/校验与合并事务。
- **预期用户价值**：微信静默注册的临时账号可自助合并到历史主账号，换机/多端身份统一，**线索归属归因更准**（直接影响员工漏斗数据可信度）。
- **验收标准**：临时账号绑定已有手机号 → 双账号数据合并 → 归因统计不重复计数；错误码文案映射齐全。
- **依赖与风险**：短信服务商签约与模板报备周期（约 3~5 工作日）；费用成本需商务确认。⚠️ 若资质延迟，本项顺延至 V1.3，不阻塞其他任务。

#### F4 视频缩略图与详情图集体验

- **目标**：后端为房源视频生成 poster 帧（OSS 视频截帧能力），前端兜底渐变占位（`projects/detail/index.ts:318`）。
- **预期用户价值**：营销型详情页第一屏不再出现黑色占位块，「实景交付」卖点完整传达。
- **验收标准**：含视频房源详情图集无黑块；poster 加载失败有优雅降级。

#### F5 反馈渠道建设（补齐 2.3 节欠账）

- **目标**：profile 页接入微信官方 `button open-type="feedback"` 意见反馈入口（零后端成本）；关键页 PV/UV 已有埋点基础上，补「估价提交成功率」「预约点击→提交成功率」两个漏斗的后台可视化口径。
- **预期用户价值**：产品团队首次获得真实用户声音与转化基线数据，后续迭代从「推断」走向「数据驱动」。
- **验收标准**：反馈入口可达且后台可查；两漏斗口径写入 docs/Base/api 文档。
