## 一、度量基线声明（⚠️ 必读）

1. **当前无任何线上性能监控数据**：项目未接入 `wx.getPerformance` 上报、未使用微信「体验评分」巡检记录。本清单「现状」列均为**代码级证据**（文件+行号），非实测值。
2. 因此 **P-00（建立度量基线）是第一优先级**：先有数据，再验证每项优化的真实收益，避免凭感觉调优。
3. 「目标值」给出可验证口径；涉及微信官方硬性限制的数值以微信最新文档为准。

## 三、分项实施说明

### P-00 建立性能基线（先行项）

- 在 `app.ts` onLaunch 接入 `wx.getPerformance()` 观察者，采集小程序启动、路由切换、`firstRender` 关键指标，经既有埋点通道上报。
- 每次提审前用开发者工具「体验评分」跑一次并留存截图归档至 docs。
- **完成定义**：拿到首页/详情/估价三个关键页的首份真机基线数据，作为后续各项验收依据。

### P-01 包体积与启动（P0）

现状证据：
- `app.json:2-30`：27 个页面全部注册主包，无 `subPackages`、无 `preloadRule`、无 `lazyCodeLoading`。
- `project.config.json:9` `bigPackageSizeSupport: true` 会掩盖主包超 2M 告警；`:12` `uploadWithSourceMap: true` 增大上传体积。

任务：
- [ ] `app.json` 增加 `"lazyCodeLoading": "requiredComponents"`（一行改动，收益立现）
- [ ] 分包规划（低频、内部属性页迁出主包）：候选 `pages/agreement/**`、`pages/test-login/**`、`pages/bind-account/**`、员工工具 `pages/ledger/**`、`pages/viewing/**`、`pages/renovation/**`、`pages/analysis/**`；tabBar 四页必须留在主包
- [ ] 配 `preloadRule`：进入房源 tab 时预载估价相关分包
- [ ] 关闭 `bigPackageSizeSupport`，暴露真实体积；评估关闭 `uploadWithSourceMap`
- [ ] CI 增加 minify 后主包体积检查脚本（>2M 即 fail）
- ⚠️ 注意：`pages/ledger/record/subject-picker` 被 `usingComponents` 引用，迁移时保持组件相对引用关系不断裂

### P-02 image 懒加载（P0）

- [ ] 全库 16 处 `<image>` 补 `lazy-load`（重点：`projects/list/index.wxml:171`、`properties/list/index.wxml:191`、`projects/detail/index.wxml:37,46,130,229`、`bookings/mine/index.wxml:37`）
- [ ] 回归验证 swiper 内图片懒加载在真机的表现（swiper 场景官方 lazy-load 支持有限，必要时手动用 `wx.createIntersectionObserver` 兜底）

### P-03 OSS 图片压缩核实（P1）

- 责任人动作：登录 OSS 控制台核查图片样式 `profo` 是否包含 resize/quality 规则（仓库内不可见，`.env` 仅存样式名）。
- 若无缩放规则：`utils/url.ts` 的 `resolveImageUrl` 增加 `resize,w_750/quality,q_80` 类参数拼接（详情大图单独放宽），并补 `url.test.ts` 用例。
- ⚠️ 此项为全库图片体验的最大不确定项，若当前线上加载的是原图（可能数 MB），则其优先级实际等同于 P0。

### P-04 高频 setData 治理（P1）

- [ ] `served-count.ts`：16ms → requestAnimationFrame 语义改为 32ms+，且动画结束立即 clear；或改 WXS/CSS 实现
- [ ] `recruit/detail` 数字卡：动画期间只 set 当前变化中的单个值而非整个数组
- 验收：开发者工具 Audits 面板无「频繁 setData」告警

### P-05 分页追加局部更新（P1）

- 统一在 `createProjectListPage` 工厂与两个手写列表页落地：追加时使用索引路径局部 setData；排序仅在筛选变更时执行，翻页不重排
- 验收：翻到第 10 页时单次 setData payload 不随页数增长（开发者工具 AppData 面板核对）

### P-06 全量拉取治理（P1）

- F10（功能计划）完成后回归本项；回退通道 `GET /projects/my-responsible` 增加 `page_size` 与截断提示

### P-07 / P-08 请求层增强（P2）

- [ ] `timeout` 抽常量 + 调用方可覆盖
- [ ] GET 幂等重试（1 次退避）
- [ ] 内存级列表缓存 + onShow 静默刷新（复用现有 silent 模式惯例）

### P-10 基建测试补齐（P1）

- [ ] mock `wx.request`/storage，覆盖：401 双端分流刷新、并发单飞（多请求同时 401 只刷一次）、retried 防循环、令牌选择（`/public/*` 优先 c 令牌）
- [ ] JWT base64url 解码边界（padding、非法字符）
