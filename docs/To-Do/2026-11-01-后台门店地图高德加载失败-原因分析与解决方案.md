# 后台门店地图「高德地图加载失败」原因分析与解决方案

- **日期**：2026-11-01
- **影响范围**：`/admin/merchant/map`（门店地图）、`/admin/merchant/tracks`（拜访轨迹）、`/admin/settings/amap`（高德 Key 配置）
- **现象**：地图区域报「高德地图加载失败」，左侧门店列表、上方统计、筛选均正常可用
- **结论**：**配置的高德 Key 不是「Web端（JS API）」平台的 Key**。高德加载器对错误 Key 返回 `{"info":"USERKEY_PLAT_NOMATCH","infocode":"10009"}`（JSON），而不是 JS 脚本；浏览器按 ORB 规则拦截该响应 → `window.AMap` 始终未定义 → 前端走「地图加载失败、列表仍可用」的降级分支。**数据接口与地图 SDK 完全独立**，因此列表不受影响。

---

## 1. 结论速览

| 维度 | 结论 |
|---|---|
| 直接原因 | `system_configs.amap_js_key` 保存的 Key 与「Web端（JS API）」平台不匹配，高德返回 **10009 USERKEY_PLAT_NOMATCH** |
| 浏览器表现 | 加载器返回 `Content-Type: application/json` 的错误 JSON，Chrome 以 `net::ERR_BLOCKED_BY_ORB` 阻断脚本请求 → `script.onerror` → 页面提示「高德地图加载失败，列表仍可使用」 |
| 列表为何可用 | 列表/统计走 `GET /api/v1/admin/merchant/map/stores`，与高德 SDK 无依赖；地图失败只影响地图容器 |
| 修复关键点 | ① 换成「Web端（JS API）」平台 Key；② **补上安全密钥（securityJsCode）支持**——2021-12-02 之后申请的 Key 必须配合安全密钥，当前配置链路没有该字段，只换 Key 仍会失败；③ 保存时校验 + 错误码可诊断化 |
| 非原因（已排除） | 网络不可达、CSP 拦截、鉴权失败、后端接口故障、Key 过期/删除（会返回 10001 而非 10009） |

## 3. 实测证据（2026-11-01，本地 `:3000` + `:8000`）

### 3.1 配置现状（已脱敏）

| 项 | 值 |
|---|---|
| 存储行 | `system_configs.key = 'amap_js_key'` 存在 |
| Key 长度 | 32（高德 Key 常见格式），**本文档不记录 Key 内容** |
| 最近更新 | 2026-10-31 15:00:03 UTC（北京时间 23:00:03） |
| 最近修改人 | `admin-user` |

### 3.2 高德侧响应：平台不匹配

直接请求高德 JS API 加载器（`$KEY` 为当前库中配置值）：

```bash
curl -s -D - "https://webapi.amap.com/maps?v=2.0&key=$KEY" -o /tmp/amap.js
```

实测结果：

```
HTTP/1.1 200 OK
Content-Type: application/json
...

{"info":"USERKEY_PLAT_NOMATCH","infocode":"10009","status":"0", ...}
```

- **HTTP 状态是 200**，但 `Content-Type` 是 `application/json`，响应体是高德错误 JSON，而不是 JS 脚本；
- `10009 USERKEY_PLAT_NOMATCH` 的官方含义：**请求使用的 Key 与绑定平台不符**（例如把非 JS API 平台的 Key 当 JS API 用）。

进一步排除「其实是 Web 服务 Key」：

```bash
curl -s "https://restapi.amap.com/v3/geocode/geo?key=$KEY&address=上海市"
curl -s "https://restapi.amap.com/v3/geocode/regeo?key=$KEY&location=121.47,31.23"
```

两个 Web 服务接口同样返回 `USERKEY_PLAT_NOMATCH / 10009`。若是正常「Web服务」Key，这里会返回 `10000 OK`。因此当前 Key 的绑定平台是 **Web 端之外的平台**。经配置人确认，该 Key 为**「微信小程序」平台 Key**（小程序 Key 默认不配安全密钥）。

### 3.3 浏览器侧：脚本被 ORB 阻断

用 Playwright（Chromium，headless）在 `http://127.0.0.1:3000/` 同源页面注入同一脚本，捕获网络与控制台：

```
script 结果：onerror
window.AMap：undefined
请求：https://webapi.amap.com/maps?v=2.0&key=<KEY>
失败原因：net::ERR_BLOCKED_BY_ORB
```

解释：脚本请求拿到的是 `application/json` 响应，Chrome 的 **ORB（Opaque Response Blocking）** 会拦截「非脚本 MIME 却被当作脚本加载」的跨源响应 → 触发 `script.onerror` → 地图页进入失败分支。即使换一个不做 ORB 的浏览器，JSON 也不会定义 `window.AMap`，仍会走 `onload` 后的 `!window.AMap` 分支，结果一致。

> 探针同时观察到 CSP Report-Only 违规日志（`script-src 'self' ...`）。该策略目前仅上报、不拦截，**不是本次失败原因**；但它是未来切强制模式时的隐患（见 §5.4）。

## 4. 根因分析

### 4.1 直接根因

**配置进系统的 Key 并非「Web端（JS API）」平台 Key。** 高德对平台不匹配的 Key 不返回脚本，而是返回 `10009` 错误 JSON，导致 SDK 永远加载不成功。

### 4.2 为什么表现成「地图挂了、列表还能用」

- 地图与列表是两条独立链路：地图依赖浏览器直连 `webapi.amap.com`；列表依赖自家后端 `/admin/merchant/map/stores`。
- 地图失败被组件局部捕获（`mapError`），只替换地图容器内容，不阻断页面其它区域。
- 这正是需求 V08「可用性：地图 SDK 故障时的降级：门店列表仍可用」的预期行为，降级本身是**正确**的；问题在于**配置数据错误 + 配置链路缺少校验**。

### 4.3 次生问题（让问题更难被发现）

1. **保存即生效、无校验**：错误 Key 也能保存成功，配置页显示「已配置」绿色徽标，形成「配置正常」的假象。
2. **错误信息不含错误码**：页面只提示「Key 无效或平台不是 Web 端 JS API」，无法区分平台不符 / 配额用尽 / 域名白名单 / 安全密钥缺失。
3. **安全密钥缺位**：即使换成正确平台的新 Key，缺少 `securityJsCode` 仍会以 `10008 INVALID_USER_SCODE` 失败——这一步在现有代码里没有任何配置入口。
4. **自动化未覆盖真实地图**：相关 E2E 在无 `E2E_AMAP_KEY` 时静默跳过（[merchant-amap-config.spec.ts](file:///Users/bugco/Desktop/profo/frontend/e2e/merchant-amap-config.spec.ts#L13-L16)），CI 永远看不到真图回归。

## 5. 解决方案

### 5.1 P0：恢复地图（配置 + 代码，二者缺一不可）

#### 5.1.1 高德控制台取正确凭据

1. 登录高德开放平台 → 应用管理 → 我的应用 → 为目标应用**添加 Key**。
2. 「服务平台」必须选择 **Web端（JS API）**（不是 Web服务、不是微信小程序、不是 Android/iOS）。
3. 同时记录该 Key 对应的 **安全密钥（securityJsCode）**。
4. 若 Key 配置了「域名白名单」，把后台访问域名（如 `admin.fangmengchina.com`）加入白名单；本地调试若不使用白名单可留空。
5. 在「系统设置 → 高德地图」保存新 Key（保存后需刷新地图页；SPA 内跳转不会重新拉取 Key）。

> ⚠️ 2021-12-02 之后申请的 Key **必须**配合安全密钥使用（高德官方文档明示）。因此仅替换 Key 通常不足以恢复，必须同步完成 5.1.2。

#### 5.1.2 代码：支持安全密钥（最小改动集）

**后端**

| 文件 | 改动 |
|---|---|
| `backend/schemas/amap_config.py` | `AmapConfigResponse` / `AmapConfigUpdateRequest` 增加 `security_js_code: str = ""`（`max_length=64`） |
| `backend/services/system/amap_config.py` | 新增存储键 `amap_security_js_code`；`get_amap_config` 一并读取；`save_amap_config(*, js_key, security_js_code, operator_id)` 在同一事务内写两行；`configured` 仍以 `js_key` 是否为空为准 |
| `backend/routers/system/amap_config.py` | `PUT` 透传 `security_js_code` |
| `backend/tests/test_merchant_amap_config.py` | 覆盖「保存/读取/清空」含安全密钥 |

**前端**

| 文件 | 改动 |
|---|---|
| `frontend/src/app/(main)/admin/settings/amap/amap-config-client.tsx` | 增加「安全密钥」输入框与说明；保存 payload 带 `security_js_code`；提示「2021-12-02 后申请的 Key 必须填写」 |
| `frontend/src/app/(main)/admin/merchant/_components/amap.ts` | 新增共享 `loadAMap(key, securityJsCode)`：**在插入脚本前**设置 `window._AMapSecurityConfig = { securityJsCode }`，并做模块级 Promise 去重（两个页面复用同一份加载逻辑） |
| `frontend/src/app/(main)/admin/merchant/map/page.tsx`、`tracks/page.tsx` | 改用共享 loader，删除各自重复的脚本注入代码 |
| `frontend/src/lib/api-types.d.ts`、`miniapp/types/api-types.d.ts` | 后端契约变更后执行 `pnpm gen-api`，禁止手改 |

关键实现要点：

```ts
// 必须在 appendChild(script) 之前设置，否则不生效
window._AMapSecurityConfig = { securityJsCode };
const script = document.createElement("script");
script.src = `https://webapi.amap.com/maps?v=2.0&key=${encodeURIComponent(key)}`;
script.async = true;
```

> 备选（生产加固）：改用 `serviceHost` 代理方式，把安全密钥放在 nginx `/_AMapService/` 转发中，前端不再明文持有安全密钥。该方案依赖 nginx 配置，本地 dev 无代理时不可用，建议作为后续安全加固项（§5.5），不要和 P0 混做。

### 5.2 P1：让配置错误「保存即发现」

1. **配置页增加「检测连通性」**：复用 `loadAMap(key, securityJsCode)`，成功显示「Key 可用」；失败时用小型 `fetch` 读取加载器错误 JSON（跨域响应带 `Access-Control-Allow-Origin: *`，可读），展示具体错误码。
2. **保存前软校验**：检测失败时弹出 warning 但允许强制保存（避免网络受限环境误伤），至少让管理员知道「已配置 ≠ 可用」。
3. **前端错误提示映射错误码**（只在加载失败后发起一次小请求，避免正常路径重复下载脚本）：

```ts
const AMAP_ERROR_HINTS: Record<string, string> = {
  "10001": "高德 Key 无效或已删除/过期",
  "10003": "高德 Key 当日配额已用尽",
  "10005": "请求 IP 不在高德白名单",
  "10006": "当前域名不在高德 Key 域名白名单",
  "10008": "高德安全密钥缺失或不匹配",
  "10009": "当前 Key 不是「Web端(JS API)」平台 Key",
};
```

4. **不要打印 Key**：高德错误 JSON 的 `key` 字段会回显完整 Key，日志/错误提示只能取 `info`、`infocode`。

### 5.3 P2：防回归

| 用例 | 内容 | 依赖 |
|---|---|---|
| 负向（无真实 Key 也能跑） | 保存一个非法 Key → 地图页出现错误提示、门店列表与统计仍可见、无 `.amap-container` | 登录态 |
| 正向 | `E2E_AMAP_KEY` + `E2E_AMAP_SECURITY_CODE` + `E2E_AMAP_EXPECT_LOAD=1` → `.amap-container` 可见、无错误卡片 | CI secrets |
| 轨迹正向 | 同一 Key 下轨迹页折线渲染 | 同上 |

同时把 `E2E_AMAP_KEY` 的「静默跳过」改为**显式 skip 标记 + 发布前人工检查项**，避免再次出现「配置已保存、地图从未验证」。

### 5.4 CSP（切强制模式前必须做）

当前 CSP 是 Report-Only（[proxy.ts](file:///Users/bugco/Desktop/profo/frontend/src/proxy.ts#L94-L108)），不影响本次问题。若后续切换到强制模式，需要：

- `script-src` 增加 `https://webapi.amap.com`（动态注入脚本无 nonce，不能仅靠 nonce 放行）；
- `connect-src` 增加 `https://webapi.amap.com https://restapi.amap.com https://*.amap.com`；
- `img-src` 已含 `https:`，地图瓦片无额外配置；
- ⚠️ 未验证项：AMap 2.0 在 WebGL 渲染/样式解析时是否使用 `blob:` worker 或 wasm/eval，切强制前需在目标浏览器实测后补齐。

### 5.5 安全与凭据

- JS API 的 Key/安全密钥本质会下发到浏览器，**安全边界靠高德侧的域名白名单 + 安全密钥**，不能靠「不暴露」。
- 当前 `/admin/merchant/map/config` 对所有持有 `merchant:map` 权限的用户返回明文 Key，属预期（前端必须拿到）；但应避免写入日志、截图、工单与文档。
- 若后续安全要求提高，再迁移到 `serviceHost` 代理（§5.1.2 备选）。

### 5.6 多端 Key 规划（Web / 小程序必须分开）

高德 Key 在创建时**绑定唯一平台**（Web端(JS API) / Web服务 / 微信小程序 / Android / iOS），平台不可后改，同一 Key 不能跨端复用。结合本项目：

| 使用端 | 技术方案 | 需要的 Key 平台 | 现状 |
|---|---|---|---|
| 后台 Web（门店地图 / 拜访轨迹） | 高德 Web JS API 2.0 | **Web端(JS API)** + 安全密钥 | 本次要配置的 Key |
| 微信小程序（门店地址选择、打卡） | `wx.chooseLocation`（微信内置地图） | **不需要高德 Key** | 已是此方案，无需配置 |
| 微信小程序（若未来原生页接入 `amap-wx.js`） | 高德微信小程序 SDK | **微信小程序** | 当前未接入；现有小程序 Key 可留作此项 |
| 小程序 `web-view` 内嵌 H5 地图 | H5 页面 + Web JS API | **Web端(JS API)** | 需把 H5 访问域名加入该 Key 的域名白名单 |

结论：

- 两个 Key **分开使用**：后台用 Web端 Key，小程序 Key 不与后台混用；
- 当前小程序端没有接入高德 SDK（仅用微信 `wx.chooseLocation`），所以小程序 Key 暂时处于**未使用**状态；若长期不接入可删除，避免被误填到后台；
- 免费配额按 Key 独立计算，分开也便于排查配额与风控问题。

## 7. 影响与风险

- **业务影响**：地图/轨迹可视化不可用，但门店列表、统计、筛选、拜访时间线可用；不阻塞商户模块核心流程。
- **修复风险**：低。安全密钥只是新增字段与加载前设置，不改变数据模型与权限；地图页/轨迹页共用 loader 属等价替换。
- **配置风险**：若 Key 未加域名白名单，Key 可能被他人复用（额度消耗）；建议同时配置白名单。
- **配额风险**：地图页每次加载都请求高德服务，多人同时打开会消耗配额；如出现 `10003` 需评估配额。

## 8. 待确认事项（⚠️ 未覆盖/不确定）

1. **当前 Key 的实际平台（已确认）**：配置人确认为「微信小程序」平台 Key。后续申请 Key 时仍须确认平台为「Web端（JS API）」，避免再次拿错（同一 Key 不能跨平台复用）。
2. **当前 Key 的申请时间**：若在 2021-12-02 之后，仅换 Key 不够，必须做安全密钥支持（§5.1.2）。
3. **生产环境是否同一 Key**：本文实测基于本地库；上线前需在生产库/后台确认，并检查生产域名白名单。
4. **生产是否采用 `serviceHost` 代理**：涉及 nginx 配置变更，需运维确认后另行实施。
5. **CSP 强制模式下的 AMap 依赖**：待实测（见 §5.4）。
6. **WebGL 不可用时的降级**：需求 REQ-M09-001 要求「浏览器不支持 WebGL → 降级提示」，当前代码未检测 WebGL；与本次根因无关，建议另立小项。
