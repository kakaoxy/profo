SEC 01

需求与口径

「我负责的项目」列表页每张卡片底部的 带看 / 出价 / 面谈 三项计数，各自增加一个 周期新增角标（+N），让管理者一眼看出「这个周期里哪些项目有新进展」。样式参考用户提供的竞品截图： 标签旁内联彩色 +N 小字（如「带看 +5」），不使用悬浮圆点气泡。

口径 ①
粒度 · 三计数各自角标
带看、出价、面谈三个数字各自统计本周期新增量，互不合并；某一项本周期无新增则显示 +0。
口径 ②
样式 · 标签旁内联 +N
对齐参考稿：计数标签右侧内联 +N 彩色小字；颜色用 --rust（与卡片右上角「最高出价」强调色同源），风格与当前页面保持一致。
口径 ③
文案 · 只显示 +N
不带「本周新增」等说明文字，保持计数行紧凑；周期规则通过本设计稿与团队文档对齐，不进 UI。
口径 ④
零值 · +0 也显示
对齐参考稿「咨询 +0」：+0 同样渲染，让用户明确知道本周期暂无新增，而非样式缺失。
口径 ⑤
周期 · 周二 → 下周一
以自然周周二 00:00 为起点、下周一 24:00 为终点；周一打开时展示的是上周二至今的累计新增（详见下方可交互演示）。
口径 ⑥
数据源 · 纯前端可算
列表接口已全量下发 project.sales_records（含 record_type / record_date），前端按周期过滤即可，零后端改动、零新增 API。
口径项定义备注
角标数值 count(item, type) = sales_records 中 record_type === type 且 record_date ∈ [周期起点, 今天] 的记录数 带看 = viewing · 出价 = offer · 面谈 = negotiation 与卡片主计数同源（parseSalesRecords 解析），非法 price 过滤逻辑不影响计数
周期起点 offset = (dayFromMonday + 6) % 7 天前；dayFromMonday：周一=0 … 周日=6 周二 → 0 天前（今天）· 周一 → 6 天前（上周二） 等价于「周二为一周之首」的自然周；跨年（如 12-30 周二 → 01-05 周一）由 Date 比较天然支持
角标样式 font-size: 22rpx · font-weight: 600 · color: var(--rust) 位于计数标签右侧 baseline 对齐，margin-left: 4rpx +0 与 +N 同色同样式（口径④）；如嫌 +0 视觉偏重，可降级为 var(--dove)，见 ARTBOARD 02 备注
显示条件 三项计数恒显示角标（含 +0） 不需要「新周期首次打开」等状态记忆，打开即算、无本地存储
CYCLE DEMO · 点击右上按钮切换「今天是周几」，观察周期窗口（高亮 = 计入新增）

SEC 03

实现说明

列表接口 GET /projects/my-responsible 已全量下发 sales_records， 角标是纯前端派生值：复用 parseSalesRecords 的一次解析，在 toDisplay 里顺带统计周期增量即可。

周期起点计算（utils 或页面内联）
/** 当前周期起点（周二 00:00）· 周一返回上周二 */
function cycleStart(now = new Date()): Date {
  const dayFromMonday = (now.getDay() + 6) % 7; // 一0…日6
  const offset = (dayFromMonday + 6) % 7;   // 一6 二0 三1…
  const d = new Date(now.getFullYear(), now.getMonth(),
                     now.getDate() - offset);
  return d; // 周二 00:00 本地时区
}

/** 记录是否落入当前周期 */
const inCycle = (r) =>
  Date.parse(r.record_date) >= cycleStart().getTime();
代码落点（三处，均为现有文件小改）
  • index.ts · toDisplay() 增加 viewingDelta / offerDelta / negotiationDelta 三字段；countByType 加可选起始时间参数复用
  • index.wxml · 三个 count-label 后各加一行 <text class="count-delta">+{{item.viewingDelta}}</text>
  • index.wxss · 新增 .count-delta（22rpx / 600 / var(--rust) / margin-left 4rpx / nowrap）
  • 不需要：后端改动、gen-api、新增页面、本地存储（打开即算）
边界情况
  • record_date 解析失败（NaN）→ 不计入周期新增（Date.parse 返回 NaN 比较恒 false，天然安全）
  • 跨年周期（如 2025-12-30 周二 → 2026-01-05 周一）→ Date 毫秒比较天然支持，无特殊处理
  • 同日多条记录 → 全部计入（与主计数口径一致）
  • 未来日期（误录入）→ record_date > 今天仍会计入「≥周期起点」，与主计数宽松口径一致，可接受
  • 列表分页 append → 每条 item 的 delta 在 toDisplay 内独立计算，append/replace 模式均无状态残留
E2E 验证点
  • 构造 sales_records：周期内 1 条 viewing、周期外（上周一）1 条 offer → 角标应为 +1 / +0 / +0
  • 周一（或 mock 系统时间）打开 → 上周二记录计入、上周一记录不计入（周期边界双向验证）
  • 周二打开 → 当天新记录计入，昨天（周一）不计入
  • 三项全 0 新增 → 三个 +0 均渲染，样式与 +N 一致
  • 两位数（+12）→ 不换行、不挤压 chevron（390 宽 + 长项目名下截图验证）
  • 列表触底加载 append 后 → 旧卡片角标数值不变
