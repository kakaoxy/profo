# Sidebar 各功能模块页 视觉与宽度一致性审查报告

- 审查日期：2026-09-10
- 审查方式：真实 Chrome 浏览器逐个访问 Sidebar 全部模块页面（本地环境 `localhost:3000`），以脚本提取每个页面的关键视觉实测值（内容容器起始 X / 内容宽度 / 卡片圆角与阴影 / 标题字号与层级），并对关键页面截图留档。
- 视口：1470×835（Sidebar 折叠态 64px，两侧页面对比条件一致）
- 截图归档：`docs/audit-sidebar-2026-09-10/`
- 覆盖页面：Sidebar 自上而下全部一级/二级菜单，共 20 页

---

## 一、总体结论

Sidebar 各模块**并非统一体系，而是至少两套设计风格并存，叠加一套混乱的宽度体系**。模块间切换时，标题字号从 16px 跳到 40px、卡片圆角从 8px 跳到 24px、内容区宽度从 498px 跳到 1342px，视觉割裂感强烈，这是"从上到下一路点下来感觉分裂"的直接原因。

## 三、问题清单（按严重程度排序）

### P0｜两套卡片设计风格并存，相邻模块视觉跳跃

相同角色下，页面渲染分属两套体系，且肉眼可辨：

- **A 套（shadcn/ui 标准）**：`bg-card + border border-border + rounded-lg/xl`（8~14px 圆角）+ 无阴影/极浅阴影。用于：工作台、房源列表、小区图库、批量上传、数据治理、数据报表、跟投管理、用户管理、权限管理、审计日志。
- **B 套（自定义 steep 体系）**：`bg-white + rounded-cards(24px) + shadow-steep`（阴影浓重、无边框）+ 点缀 `bg-apricot-wash`(rgb 251,225,209) 杏色 KPI 卡。用于：线索中心、项目管理、房源营销、获客中心全部 4 页、资金账本、科目管理。

影响最典型的切换：**数据报表（A，14px 圆角细边框）→ 线索中心（B，24px 圆角大阴影）**；以及财务组内 **资金账本（B）→ 跟投管理（A）** 的组内反复横跳。

### P1｜内容区宽度体系混乱（498 → 1342px，最大 2.7 倍差距）

| 宽度档位 | 内容宽 | 所属页面 |
|---------|--------|---------|
| 全宽 | 1342 | 工作台、数据报表、线索中心、项目管理、房源营销、用户列表、审计日志、跟投管理 |
| 窄栏 | 1136（右移 103px → 起始 X=199） | 获客中心 4 页、资金账本、科目管理 |
| 更窄 | 1216 | 数据治理 |
| 局部窄 | 1118（表格被压缩，起始 X=336） | 房源列表 |
| 居中窄表 | 720 | 批量上传 |
| 居中极窄 | 498 | API Key |
| 无卡片 | — | 小区户型图库 |

同一侧栏体系里出现 6 档不同宽度，切换页面时内容区左右留白剧烈变化，是全项目"割裂感"第二个来源。

### P2｜页面标题字号混乱（16 ～ 40px）

- 16px：小区户型图库
- 20px：房源列表、数据报表
- 24px：工作台、跟投管理
- 26px：获客中心 4 页
- 30px：数据治理、线索中心、项目管理、房源营销、用户/权限管理、审计日志
- 40px：资金账本、科目管理（全站最大，突兀）

### P3｜标题标签层级不统一

- 测得 17 页标题为 `h1`（但字号差异如上）；**权限管理、API Key 管理 2 页用 `h2` 做页面主标题**，语义层级与其余页面不一致。
- 工作台、资金账本等页面 h1 带副标题说明，其余页面无副标题，视觉节奏不齐（次要问题）。

### P4｜获客中心 / 财务"账本系"整体与其他模块割裂

- 内容区起始 X=199 vs 其余页面 96，即整块内容右移并收窄，这是独立的二次封装容器导致（见源码定位）。
- 标题残留草稿期文案：**"获客总览一期"、"漏斗看板一期"** 的"一期"字样不应出现在正式界面。

### P5｜API Key 页为独立模板

- 居中窄栏（X=518，宽 498）+ emerald 绿色提示卡，与全系统"左对齐全宽"范式完全不同；该页还是 h2 标题。属于独立开发、未并入统一布局。

### P6（细节）｜A 套内部圆角/标题也不统一

- A 套内部圆角跨度 8/10/12/14/16px（`rounded-md/lg/xl/2xl` 混用）：数据治理 8px、跟投 10px、报表/用户 14px、工作台 14+16px。
- KPI 统计卡样式私有化：`users-stat-card` 等页面级自定义类，未收敛到统一 Card 组件。

## 四、源码定位（根因）

| 现象 | 源码线索 | 路径 |
|------|---------|------|
| 两套风格共存的工具类体系 | A 套用 shadcn `border-border`；B 套用自定义 `rounded-cards` / `shadow-steep` / `bg-apricot-wash` | 全局 tailwind 主题新增了 steep/卡片系 tokens，未替换既有页面；`frontend/src/app/globals.css`（待查） |
| B 套页面入口统一窄化（X=199 / w1136） | 获客中心 4 页、资金账本、科目管理共用同一容器包装 | 各页 layout/容器组件（`growth-center`、`ledger` 各自 layout） |
| 标题字号混乱 | 各页手写 `text-3xl/4xl/5xl` 不等；账本系 40px 为自定义 | 逐页 page.tsx 的 h1 类名 |
| 权限管理 h2 / API Key 居中模板 | 两页独立实现未遵循 `(main)` 布局的标题规范 | `users/roles/page.tsx`、`settings/api-key/page.tsx` |

> 说明：本报告为视觉实测结论；精确到文件的修复对应关系建议另立重构任务，逐页统一。

---

## 五、修复建议（统一到单一设计体系）

1. **定统一规范并抽成共享组件/工具类**：卡片统一为「14px 圆角 + 1px border + 极浅阴影」或整体迁移到 steep 体系，二选一，禁止共存；KPI 卡封装为统一 `<StatCard>`。
2. **统一内容宽度**：全系统采用单一内容栅格（建议与"全宽 1342"对齐，即 `pr` 起始 X=96），删除各页自定义的 `max-w`/窄化包装；列表类页面表格占满内容宽。
3. **统一标题**：页面主标题统一 `h1`、30px/600；副标题规则统一（要么全带要么全不带）；删除"一期"等草稿文案；账本系 40px 收敛。
4. **API Key 页改造成标准左对齐全宽页面**，并入侧栏统一布局，去掉独立居中模板与 emerald 提示卡配色。
5. **清理私有化工具类**：`users-stat-card`、`shadow-steep*`、`bg-apricot-wash` 等收敛到主题变量/共享组件，避免再次脱轨。
