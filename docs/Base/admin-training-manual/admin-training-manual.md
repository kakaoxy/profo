### 1.1 系统简介

Profo 管理后台是房产运营管理的核心系统，覆盖**房源数据管理、线索跟进、项目全生命周期管理、房源营销发布、用户权限管控** 等核心业务场景。系统采用 Next.js + FastAPI 技术架构，提供响应式 Web 界面，支持桌面和移动端访问。

### 1.2 角色体系

系统内置四种角色，不同角色拥有不同的操作权限：

角色| 代码| 权限范围| 可登录后台  
---|---|---|---  
超级管理员| `admin`| 全部权限：数据查看/编辑、用户管理、角色管理、系统设置| 是  
运营人员| `operator`| 数据查看/编辑、房源导入、营销管理、API Key 管理| 是  
普通用户| `user`| 仅数据查看| 是  
C端用户| `customer`| C端注册用户，浏览房源、提交估价| 否

模块| 路径| 核心功能| 可见角色  
---|---|---|---

房源列表| `/admin/properties`| 房源浏览、筛选、排序、详情、导出| 全部

数据治理| `/admin/properties/governance`| 小区合并、重复数据清理| admin, operator

## 02 登录与账户安全

### 2.1 登录流程

访问登录页

在浏览器中打开 `http://localhost:3000/admin`，系统自动跳转至登录页 `/admin/login`。

输入账号密码

在登录页输入管理员分配的**用户名** 和**密码** ，点击「立即登录」按钮。

进入工作台

登录成功后自动跳转至工作台首页 `/admin`。系统同时写入 httpOnly Cookie 保存登录状态。

注意

C端用户（`customer`角色）**无法登录管理后台** ，系统会拒绝并提示无权限。仅 `admin`、`operator`、`user` 三种角色可登录后台。

### 2.2 首次登录强制改密

如果管理员创建用户时设置了「首次登录需改密」标记，首次登录时系统会要求修改密码：

  * 输入用户名和密码后，系统返回提示要求修改密码
  * 输入**当前密码** 和**新密码** （需满足强度要求：至少8位，包含大小写字母、数字和特殊字符）
  * 修改成功后，需使用新密码重新登录


### 2.3 退出登录

点击侧边栏底部的用户头像，在弹出菜单中选择「退出登录」即可清除登录状态并返回登录页。

### 2.4 Token 安全机制

Token 安全策略

  * **JWT 受众隔离** ：后台 Token 的 `aud=admin`，C端 Token 的 `aud=c`，互不通用
  * **Token 版本控制** ：密码修改、用户禁用或删除时，系统自动递增 `token_version`，使旧 Token 立即失效
  * **Refresh Token 轮换** ：刷新令牌使用后立即作废，防止重放攻击
  * **Cookie 安全** ：httpOnly 防止 XSS 窃取，生产环境启用 Secure，SameSite=Lax
  * **登录限流** ：同一 IP+用户名组合限制 5次/分钟

## 04 工作台

### 4.1 功能概述

工作台是登录后的首屏页面（`/admin`），提供运营关键数据的实时概览，帮助管理者快速掌握业务全貌。页面标题为「工作台」，副标题「欢迎回来，这是您今日的数据概览」。

### 4.2 页面区块说明

#### 4.2.1 项目总览卡

展示各状态的项目数量统计，帮助快速了解项目分布：

指标| 含义  
---|---  
已签约| 当前处于「签约」阶段的项目数量  
装修中| 当前处于「改造」阶段的项目数量  
在售中| 当前处于「在售」阶段的项目数量  
已成交| 已完成「已售」状态的项目数量  
  
#### 4.2.2 评估预警卡

显示「待评估事项」数量。当有新线索处于待评估状态时，此数字会高亮提醒，点击可跳转至线索中心查看详情。

#### 4.2.3 重点监控项目

横向滚动展示重点监控项目卡片，每个卡片包含：

  * 项目基本信息（小区名、户型、面积、价格）
  * 小区市场数据（在售套数、成交均价、30日成交量、价格趋势）
  * 销售统计（带看量、出价数、最高出价）
  * 点击「详情」可打开项目详情抽屉


#### 4.2.4 近期线索跟进

展示最近 10 条线索记录，包含小区名、户型、面积、楼层、总价、单价、状态、区域、录入人、更新时间。点击「查看全部」跳转至线索中心。

#### 4.2.5 添加新项目

提供快速新建项目的入口，副标题「快速录入房源或新建开发项目」，点击后打开项目创建表单。

容错设计

工作台各区块采用独立加载机制，单个数据接口失败不会影响其他区块的显示，仅对应区域显示错误提示。

## 05 房源管理

### 5.1 房源列表

#### 入口路径

`/admin/properties` → 侧边栏「房源管理」→「房源列表」

#### 核心功能

  * **分页浏览** ：每页默认 50 条，底部显示分页器（支持跳页）
  * **多维筛选** ：左侧筛选面板支持状态、小区名、户型、楼层、价格范围、面积范围筛选
  * **多列排序** ：点击表头按楼层、面积、单价、时间等字段排序
  * **详情查看** ：点击「查看」打开右侧抽屉显示房源完整信息
  * **CSV 导出** ：按当前筛选条件导出全量匹配数据
  * **户型图预览** ：鼠标悬停户型图列可放大预览


#### 筛选条件说明

筛选项| 说明| 输入方式  
---|---|---  
房源状态| 在售 / 成交 / 过期| 下拉单选  
小区名称| 模糊搜索小区名| 文本输入  
户型（室）| 按室数筛选，支持多选| 复选框（1室/2室/3室/4室+）  
楼层| 低楼层 / 中楼层 / 高楼层| 复选框多选  
价格范围（万）| 最低价 ~ 最高价| 数字输入  
面积范围（㎡）| 最小面积 ~ 最大面积| 数字输入  
  
#### 列表字段说明

列名| 字段| 说明| 可排序  
---|---|---|---  
ID| id| 房源内部编号| 否  
户型图| picture_links| 按数据源智能取图，悬停可预览| 否  
小区| community_name| 小区名称（移动端合并户型和楼层）| 否  
状态| status| 在售（蓝）/ 成交（绿）/ 过期（灰）| 否  
商圈| business_circle| 所属商圈| 否  
户型| rooms+halls+baths| 格式如「2室1厅1卫」| 否  
朝向| orientation| 房屋朝向| 否  
楼层| floor_display| 楼层信息（如「中楼层」）| 是  
面积| build_area| 建筑面积（㎡）| 是  
价格| total_price| 在售取挂牌价，成交取成交价（万）| 是  
单价| unit_price| 元/㎡，自动计算| 是  
时间| listed_date/sold_date| 在售卖上架时间，成交取成交时间| 是  
来源| data_source| 数据来源平台（如贝壳）| 否  
操作| -| 「查看」按钮| 否  
  
#### 操作流程

设置筛选条件

在左侧筛选面板选择/输入条件，页面自动刷新结果

排序数据

点击表头列名（楼层/面积/价格/单价/时间）切换升序/降序

查看详情

点击操作列「查看」按钮，右侧弹出详情抽屉

导出数据

点击「导出数据」按钮，按当前筛选条件下载 CSV 文件

翻页浏览

使用底部分页器切换页码或调整每页条数

状态说明

数据库中房源只有两种实际状态：**在售（FOR_SALE）** 和**成交（SOLD）** 。「过期」是派生状态：在售房源超过 30 天未更新自动标记为过期。价格筛选时，在售/过期筛挂牌价，成交筛成交价。

### 5.2 批量上传

#### 入口路径

`/admin/properties/upload` → 侧边栏「房源管理」→「批量上传」（仅 admin/operator 可见）

#### 核心功能

  * **下载 CSV 模板** ：获取标准格式模板（含表头、必填说明、示例数据）
  * **拖拽上传** ：支持拖拽或点击选择 CSV 文件（最大 10MB）
  * **异步导入** ：上传后后台异步处理，前端实时显示进度
  * **失败记录下载** ：导入失败的行可下载 CSV（含行号和错误原因），修正后重传
  * **取消与重试** ：处理中可取消任务，失败后可重试


#### CSV 模板字段

列名| 必填| 说明  
---|---|---  
数据源| 必填| 数据来源平台名称  
房源ID| 必填| 来源平台房源 ID（与数据源组成唯一键）  
状态| 必填| 在售 / 成交  
小区名| 必填| 小区名称  
室| 必填| 室数量（整数）  
朝向| 必填| 房屋朝向  
楼层| 必填| 原始楼层串（如「15/28」）  
面积| 必填| 建筑面积（㎡，大于 0）  
挂牌价| 在售必填| 挂牌价（万）  
上架时间| 在售必填| 上架日期  
成交价| 成交必填| 成交价（万）  
成交时间| 成交必填| 成交日期  
厅/卫/套内面积/物业类型/建筑年代等| 可选| 附加属性字段  
图片链接| 可选| 逗号分隔的 URL 列表  
  
#### 操作流程

下载模板

点击「下载数据模板」获取 CSV 格式文件

填写数据

按模板格式填写房源数据，必填字段不可为空

上传文件

拖拽 CSV 文件到上传区域或点击选择文件

查看进度

页面实时显示处理进度（百分比、已处理/总数、成功/失败数）

处理结果

全部成功→绿色提示；部分失败→下载失败记录修正后重传

注意事项

  * 单次上传建议不超过 1000 条数据
  * 在售状态必须填写挂牌价和上架时间；成交状态必须填写成交价和成交时间
  * 系统按「数据源 + 房源ID」作为唯一键，重复数据会自动更新而非新建
  * 小区名优先精确匹配，其次按别名匹配，找不到则自动创建新小区
  * 导入限流：30次/小时


### 5.3 数据治理

#### 入口路径

`/admin/properties/governance` → 侧边栏「房源管理」→「数据治理」（仅 admin/operator 可见）

#### 核心功能

  * **小区列表浏览** ：分页查看所有小区，显示关联房源数
  * **小区搜索** ：按名称模糊搜索
  * **小区合并** ：选中多个重复小区，合并到主小区（迁移房源+别名，软删除旧小区）


#### 列表字段

列名| 说明  
---|---  
选择| 复选框，用于多选  
ID| 小区 UUID  
小区名称| 小区名称  
关联房源数| 该小区下的活跃房源数量  
行政区| 所属行政区  
商圈| 所属商圈  
创建时间| 小区创建日期  
  
#### 合并操作流程

选择小区

勾选 2 个或以上需要合并的重复小区

点击合并

点击「合并所选」按钮打开合并对话框

选择主小区

在下拉框中选择保留的主小区（其余将被合并并入）

确认合并

预览影响（将被删除的小区列表和迁移房源数），确认后执行合并

不可撤销

小区合并操作**不可撤销** 。合并后，被合并小区的所有房源将迁移至主小区，被合并小区将被软删除（标记为 inactive），其名称将作为别名保留在主小区下。仅 admin 角色可执行合并操作。

## 06 线索中心

### 6.1 功能概述

线索中心（`/admin/leads`）用于管理房源收购线索的全生命周期，从线索录入、评估、带看到最终签约或驳回。页面标题「线索管理」，副标题「管理和跟进房源线索，从初筛到签约的全流程追踪」。

### 6.2 界面说明

  * **统计卡** ：展示待评估、待看房、已看房、已签约、已驳回的线索数量
  * **状态筛选 Tab** ：全部 / 待评估 / 待看房 / 已看房 / 已签约 / 已驳回
  * **视图切换** ：列表视图（表格）/ 网格视图（卡片）
  * **操作按钮** ：导出、新增线索


### 6.3 线索列表字段

列名| 字段| 说明  
---|---|---  
小区/房源信息| community_name| 小区名称及线索 ID  
户型/面积| layout + area| 如「2室1厅1卫 71.02㎡ · 4/6层」  
总价/单价| total_price / unit_price| 总价（万）/ 单价（元/㎡）

区域| district / business_area| 行政区或商圈  
录入人| creator_name| 线索创建者  
操作| -| 点击行打开详情抽屉  
  
### 6.4 新增线索

点击「新增线索」

签约 → 改造 → 在售 → 已售

#### 签约阶段（默认视图）

项目详情抽屉顶部显示**摘要卡片** ，包含四个关键指标：签约总价、净现金流、距交房天数、当前阶段。下方为三个标签页：

##### 项目信息标签页

展示项目的完整信息，按区块组织：

  * **基础信息** ：小区名称、行政区、商圈、详细地址、产证面积、户型、楼层、朝向、业务形式、项目负责人
  * **代理协议** ：合同编号、签约价格、签约日期、合同周期、顺延期、顺延期租金、计划交房日期、委托期限、佣金起止日期、费用承担方、其他约定
  * **业主信息** ：支持多位业主展示，每位业主显示姓名、联系电话（脱敏）、身份证号（脱敏）、开户银行、银行卡号、关系类型、备注

文书签收说明

文书签收是签约阶段的核心流程之一。不同业务形式对应的文书模板不同，代理美化模式通常包含代理合同、委托书、产权确认等；收购美化模式包含收购合同、产权转移等。系统会在项目创建或进入签约阶段时自动初始化模板。

##### 附件标签页

管理项目相关文件，按分类展示（签约合同、产权证明、业主身份证、其他附件）。支持上传、预览、删除操作。

##### 交房确认

签约阶段所有文书签收完成后，底部出现「交房确认」按钮。点击后弹出**交房确认对话框** ，需要填写：

  * 实际交房日期
  * 交房备注（房屋状况、钥匙移交等）
  * 确认后项目状态从「签约」流转到「改造」


#### 改造阶段

  * **改造合同** ：装修公司、合同起止时间、实际起止时间、硬装合同金额、4个支付节点及比例、软装预算/实际成本、设计费/拆除费/垃圾清运费等
  * **改造时间线** ：7个子阶段顺序跟踪（拆除 → 设计 → 水电 → 木瓦 → 油漆 → 安装 → 交付），每个阶段可上传施工照片和记录完工日期
  * **改造照片** ：按阶段上传和管理施工照片，支持通过文件上传 API 上传 JPEG/PNG 等格式图片
  * 完工后转入在售阶段


改造阶段说明

改造时间线的每个阶段默认状态为"进行中"，完成当前阶段后可推进到下一阶段。改造合同信息可在改造阶段随时填写和更新，包括付款节点比例（4个节点比例之和需为100%）。

#### 在售阶段

  * **销售团队** ：设置渠道负责人（channel_manager）、讲房人（property_agent）、谈判人（negotiator），选择后自动保存，后端校验用户 ID 有效性
  * **销售活动记录** ：三类记录，每类包含客户姓名、电话、日期等字段 
    * 带看记录（viewing）：客户姓名、电话、带看日期、备注、反馈、结果
    * 出价记录（offer）：客户姓名、电话、出价日期、出价金额（万）、备注
    * 面谈记录（negotiation）：客户姓名、面谈日期、备注、结果
  * **关键指标** ：带看总量、本周/上周带看量、收到出价数、最高出价
  * 达成交易时通过「确认成交」将项目转为已售，需填写成交价和成交日期


#### 已售阶段

  * 展示成交价、成交日期等最终信息
  * 可视化旅程展示
  * 财务生命周期汇总


业务规则

  * 销售记录仅可在「在售」阶段添加
  * 确认成交仅允许「在售」或「已售」状态操作
  * 项目删除为软删除（状态置为 deleted）
  * 销售角色设置后后端校验用户 ID 有效性


### 7.5 现金流管理

#### 入口路径

项目列表操作列点击「账本」→ 右侧弹出资金账本面板（URL 参数 `cashflow_id`）

#### 面板布局

面板标题格式："资金账本 / [小区名] · [项目地址]"，副标题"全周期资金流向监控，即时核算项目盈亏"。顶部操作栏提供「导出 Excel」和「记一笔」按钮。

#### 核心功能

  * **头部统计** ：总收入、总支出、净现金流（以万元为单位展示）
  * **关键指标** ：ROI（投资回报率）、年化收益率、资金占用天数
  * **流水表格** ：按时间倒序展示收支记录，每条记录包含日期、类型（收入/支出）、分类、金额、描述
  * **新增记录** ：点击「记一笔」选择收支类型（收入/支出）、分类、金额、日期、描述
  * **导出 Excel** ：将现金流记录导出为 Excel 文件


指标计算说明

  * **ROI** = 净现金流 ÷ 总支出 × 100%
  * **年化收益率** = ROI ÷ 资金占用天数 × 365
  * **资金占用天数** = 从首笔支出记录日期至当前日期的天数
  * 净现金流为负值表示项目处于投入期，正值表示已实现盈利


#### 现金流分类

类型| 分类  
---|---  
支出| 履约保证金  
中介佣金  
装修费  
营销费  
税费  
运营费  
其他支出  
收入| 回收保证金  
溢价款  
服务费  
售房款  
其他收入  
  
净现金流 = 总收入 - 总支出，计算结果同步回写项目主表，在项目列表中直接展示。

### 7.6 市场监控

#### 入口路径

项目列表操作列点击「监控」→ 右侧弹出项目房价监控面板（URL 参数 `monitor_id`）

#### 面板概览

面板标题"项目房价监控"，展示项目地址、户型面积、价格信息（签约价/挂牌价/单价）。面板包含以下七大分析区域：

#### 七大分析维度

分析维度| 展示内容| 说明  
---|---|---  
项目房价监控| 项目地址、户型面积、签约价、挂牌价、单价（元/㎡）| 基础信息概览，单价 = 挂牌价 × 10000 ÷ 面积  
时间成本监控 (Time Bomb)| 免租期余额（天）、延期日损失预计（元/天）、进度百分比| 追踪项目时间成本，免租期用尽后每日计损失  
宏观风向标（本小区行情）| 同户型成交统计（12个月，按高/中/低楼层）、同户型挂牌统计（当前在售）、去化压力（库存÷月销）| 去化压力判定：≤6个月为健康市场，>12个月标记为滞销（买方市场）  
周边竞品雷达| 竞品小区多维度对比雷达图| 需先通过"管理竞品小区"添加竞品（最多5个）  
趋势研判（价格与成交量预测）| 价格走势和成交量预测图表| 基于历史数据趋势分析  
竞品肉搏战（明细对比）| 本项目与竞品小区在售房源逐套对比（价格/户型/楼层）| 支持按在售/已售切换，按户型（1室/2室/3室/4室+）筛选  
智能决策建议| 基于市场数据生成的 AI 策略建议| 可在输入框中补充信息（如业主急售、高标准精装等），点击"立即生成专家建议"获取  
  
#### 竞品管理

点击「管理竞品小区」按钮打开竞品管理弹窗，可添加或删除竞品小区（最多 5 个）。系统自动汇总本项目小区和竞品小区的在售/已售房源进行对比分析。

#### 密码安全要求

密码强度规则

密码必须满足以下条件：至少 8 位，包含大写字母、小写字母、数字和特殊字符。密码使用 bcrypt 哈希存储，不可逆。

#### 用户操作业务逻辑

  * **新建用户** ：用户名唯一，密码需满足强度要求，手机号通过哈希校验唯一性
  * **编辑用户** ：可修改角色和状态。将用户由 active 改为 inactive 时，系统自动递增 token_version 并撤销所有 refresh_token，用户立即下线

  * **删除用户** ：软删除（status=inactive），同时撤销所有 Token。**禁止删除自己**

## 11 数据指标解释

### 11.1 工作台指标

指标| 计算方式| 业务含义  
---|---|---  
已签约数| COUNT(status='signing')| 当前处于签约阶段的项目总数  
装修中数| COUNT(status='renovating')| 当前处于改造阶段的项目总数

待评估线索数| COUNT(status='pending_assessment')| 尚未完成评估的线索数量  
线索转化率| 已签约数 ÷ 线索总数 × 100%| 线索从录入到签约的转化比例  
  
### 11.2 房源指标

指标| 计算方式| 业务含义  
---|---|---  
单价| 总价 × 10000 ÷ 面积| 每平方米价格（元/㎡）  
在售状态| status=FOR_SALE 且 updated_at ≥ 当前-30天| 30天内有更新的在售房源  
过期状态| status=FOR_SALE 且 updated_at < 当前-30天| 超过30天未更新的在售房源  
成交状态| status=SOLD| 已完成交易的房源  
楼层分级| ≤33% 低楼层 / 33%-67% 中楼层 / >67% 高楼层| 按总楼层比例自动分级  
  
### 11.3 线索漏斗指标

指标| 含义  
---|---  
线索总数| 所有非删除状态的线索数量

已驳回| 评估未通过的线索数  
带看中| 处于待看房和已看房状态的线索数  
已签约| 成功签约的线索数  
  
### 11.4 项目财务指标

指标| 计算方式| 业务含义  
---|---|---  
总收入| SUM(type='income')| 项目所有收入记录总和  
总支出| SUM(type='expense')| 项目所有支出记录总和  
净现金流| 总收入 - 总支出| 项目盈亏情况，正值盈利，负值亏损  
ROI| 净现金流 ÷ 总支出 × 100%| 投资回报率，衡量资金使用效率  
年化收益率| ROI ÷ 资金占用天数 × 365| 将 ROI 折算为年度收益率，便于跨项目对比  
资金占用天数| 当前日期 - 首笔支出日期| 资金被占用的天数，影响年化收益率  
签约价| 项目签约时的收购价格| 购买房产的成本  
成交价| 项目售出时的价格| 销售房产的收入  
免租期余额| 约定免租期 - 已用天数| Time Bomb 指标，余额为0后每日产生延期损失  
延期日损失| （签约价 + 装修成本）÷ 预计周转天数| 免租期结束后每日的资金成本

## 12 常见业务场景处理流程

### 场景一：新线索录入到签约全流程

录入线索

线索中心 → 新增线索 → 填写房源信息 + 上传图片 → 提交（状态：待评估）

评估线索

跟进带看

创建项目

项目管理 → 新建项目 → 填写4标签页（基础信息/代理协议/业主信息/附件上传）→ 提交（状态：签约）

签约确认

回到线索详情 → 审核流转 → 确认签约（状态：已签约）

### 场景二：项目从签约到售出全流程

管理改造

填写改造合同 → 跟踪改造时间线 → 上传施工照片 → 完工 → 状态：在售

销售管理

设置销售团队 → 记录带看/出价/面谈 → 查看销售指标

确认成交

确认成交 → 填写成交价和日期 → 状态：已售

财务复盘

账本 → 查看净现金流 → 记录所有收支

### 场景三：批量导入房源数据

下载模板

房源管理 → 批量上传 → 下载数据模板

填写数据

按模板格式填写，在售必填挂牌价和上架时间，成交必填成交价和成交时间

上传导入

拖拽 CSV 文件上传 → 等待异步处理完成

检查结果

全部成功→完成；部分失败→下载失败记录 → 修正后重新上传

数据治理

检查是否有重复小区 → 数据治理 → 合并重复小区

AI建议

### 场景六：用户管理操作

### 13.1 安全操作规范

安全红线

  * **禁止共享账号** ：每人使用独立账号，禁止多人共用同一登录凭证
  * **密码安全** ：密码需满足强度要求（≥8位，含大小写+数字+特殊字符），定期更换
  * **API Key 保管** ：完整 Key 仅显示一次，生成后立即保存到安全位置，不要泄露给他人
  * **手机号保护** ：手机号加密存储，界面脱敏显示，不要在非安全渠道传播
  * **禁止删除自己** ：系统禁止用户删除自己的账号


### 13.2 数据操作注意事项

操作| 注意事项  
---|---  
批量导入| 单次不超过 1000 条；必填字段不可为空；在售/成交状态需对应填写价格和时间  
小区合并| 操作不可撤销；合并前确认房源数；仅 admin 可操作  
项目状态流转| 需按顺序流转（签约→改造→在售→已售），不可跳转  
营销项目发布| 发布后 C 端立即可见；改为草稿可暂时下架  
用户禁用| 禁用后用户立即下线，所有已签发 Token 即时失效  
角色删除| 角色下有用户时无法删除，需先转移用户  
  
### 13.3 常见问题与异常处理

#### 问题1：登录失败

可能原因| 解决方案  
---|---  
用户名或密码错误| 检查输入是否有误，注意大小写。连续5次失败需等待1分钟后重试  
账号被禁用| 联系管理员检查账号状态是否为 active  
C端用户尝试登录后台| customer 角色无法登录后台，需联系管理员分配后台角色  
首次登录需改密| 按提示输入当前密码和新密码完成修改  
  
#### 问题2：页面数据不显示

可能原因| 解决方案  
---|---  
后端服务未启动| 检查后端服务（:8000）是否正常运行  
Token 过期| 系统自动刷新，如刷新失败需重新登录  
权限不足| 检查当前角色是否有对应模块的访问权限  
网络异常| 检查网络连接，刷新页面重试  
  
#### 问题3：批量导入失败

可能原因| 解决方案  
---|---  
文件格式错误| 确保文件为 .csv 格式，使用下载的模板填写  
必填字段为空| 下载失败记录 CSV，查看具体行号和错误原因，补充后重传  
文件超过 10MB| 拆分为多个小文件分别上传  
编码问题| 系统自动识别 UTF-8-SIG/UTF-16/GBK 等编码，如仍有问题请转为 UTF-8  
超过限流| 导入限流 30次/小时，等待后重试  
  
#### 问题4：看不到某些菜单

菜单可见性说明

侧边栏菜单根据角色自动过滤，这是正常的安全设计：

  * `user` 角色：看不到「用户管理」和「设置」
  * `operator` 角色：看不到「用户管理」，但可访问「设置」和「批量上传」「数据治理」
  * `admin` 角色：可看到全部菜单


如需更高权限，请联系超级管理员调整角色。
