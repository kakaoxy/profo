小程序 · 我的客户 — 高保真设计稿

在「我的 → 分享获客」中新增「我的客户」模块，将房源预约、估价留资、房源单承接、招募报名四条链路散落的客户线索集中管理，并引入与招募一致、与 admin 获客中心 UnifiedLeadStatus 对齐的统一 5 态状态流转。

版本 V1.0 · 2026-09-02 视觉规范 DESIGN.md · Steep 状态集 统一 5 态 待评审

现状问题

客户线索散落在 4 个「我的」页面：我的获客（valuation/mine）、我的客户（projects/mine，预约归因）、我的线索（recruit/mine）、我的房源单（property-sheet/mine，仅漏斗统计）。员工需在多处切换跟进，且仅招募有状态流转，预约线索无任何跟进动作。

设计方案

① 分享获客分组新增「我的客户」置顶入口（带新线索角标）；② 聚合列表页：四模块筛选 × 统一 5 态 chips × 漏斗统计；③ 客户详情：状态流转 + 归因链路 + 跟进记录；④ 状态规则页说明映射关系。后端复用 growth-center 的 UnifiedLeadStatus 映射。

设计说明

  1. 漏斗统计卡：沿用 recruit/mine 的「昨日/累计两行 × 分享/PV/UV/留资」模式，聚合计数四类链路；「留资」列以 rust 色强调。脚注保留 UV 口径差异提示。
  2. 两级筛选：模块 tabs（带各模块色点与数量）× 统一状态 chips。模块色点与 admin 获客中心来源构成一致：估价 rust / 预约 blue / 房源单 graphite / 招募 teal。
  3. 统一线索卡：模块标签 + 脱敏手机号 + 统一状态标签（右上）；摘要行按模块差异化（估价：小区/户型/面积/预期价；预约：房源标题+预约时间；房源单：名称+短码；招募：主营商圈）；来源 chip（客户分享/卡片/海报）+ 相对时间。
  4. 状态配色（Steep 色板内）：新线索 sky → 已联系 apricot → 意向高 rust 实底 → 已转化 mint → 已淘汰 neutral，语义为「冷→暖→热→成→弃」。
  5. 卡片操作：新线索主按钮「联系客户」→ 查看完整号码（自动流转已联系）；非新线索显示「再次联系」；「状态流转」打开确认面板；已转化/已淘汰仅保留查看。
  6. 列表分页加载（每页 10 条，滚动触底加载），401/403 与空数据沿用现有空态兜底模式。

设计说明

  1. 状态 hero 卡：当前统一状态 + 一句话下一步建议，替代员工自己判断「接下来干嘛」。
  2. 手机号深色卡（ink 实底）：完整号码仅归属员工可见；点击「查看完整号码」直接拨打并自动流转「新线索 → 已联系」，复用招募 mine 页已验证的隐式流转交互（applyLeadPhone 模式）。
  3. 业务信息栅格按模块差异化（估价示例：小区/户型/预期价/评估价；预约示例换为房源标题/预约时间；房源单换为名称+短码；招募换为主营商圈+活动名）。
  4. 归因链路时间线：分享 → 打开 → 留资，与 admin 获客中心线索详情抽屉的 timeline 事件对齐（share / visit / lead_submit）。
  5. 状态流转卡：主链路 4 节点进度条 + 「已淘汰」旁路说明；操作按钮直达确认面板（屏 04）。
  6. 跟进记录：轻量备注 + 时间线，落地 0825 迭代计划 V1.2 F2「leads 增 follow-up 子资源」；新增跟进后自动刷新「上次跟进」时间。

设计说明

  1. 底部动作面板承接所有手动状态变更（列表卡「状态流转」与详情页操作按钮均打开此面板），避免误触直接改状态。

  4. 确认后本地就地更新卡片状态标签（同 recruit/mine applyLeadPhone 的就地刷新模式），并触发订阅消息通知归属员工。

自动流转与归属规则
1查看即联系：点击「查看完整号码」后，「新线索」自动流转为「已联系」，与招募 mine 页既有行为一致，且不可逆。
2归属规则：客户归属以首次留资时的分享归属员工（referrer）为准，后续流转不改变归属。
3内部过滤：内部员工自己提交 / 录入的线索不进入「我的客户」列表（与 admin 获客中心 internal_creator 过滤一致）。
4订阅提醒：新留资与状态被后台变更时，通过微信订阅消息通知归属员工。
二期规划（本次不实现）
预约状态机：已预约 → 已联系 → 已带看 → 已关闭（0825 计划 V1.2 F1），落地后自动并入统一映射。
跟进提醒日历与客户分层标签（V2.0 员工 CRM 增强）。
活动归因扩展：campaign_id 接入估价 / 预约 / 房源单分享。

设计说明

  1. 规则页从详情页「流转规则 ›」与空态页进入，向员工解释统一状态口径，降低「为什么我的估价线索显示已联系」类困惑。
  2. 映射表内容与 services/growth_center/leads.py 的只读映射逐条对应（pending_assessment→new、pending_visit→contacted、visited→high_intent、signed→converted、其余→eliminated）。
  3. 「查看即联系」为既有产品行为（招募线已上线），此处将其显式文档化并推广到估价 / 房源单线。

边界情况

  • 已转化 / 已淘汰为终态：列表默认收进对应筛选，不再出现在「新线索」提醒数中。
  • 同一客户多链路留资：按线索条目展示（每条独立流转），二期再做客户级合并（以手机号去重）。
  • 员工离职 / 权限回收：线索归属转移由后台处理，小程序端仅展示归属自己的线索。
