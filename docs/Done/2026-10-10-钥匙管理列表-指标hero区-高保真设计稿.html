SEC 01

需求与口径

钥匙管理列表页（pages/keys/list/index）页首新增指标 Hero 区：一张白卡内并排三列指标—— 房源 / 分享 / 查看（UI 用短名，全称与口径见下表），每列为「灰色小标签 + 橙色 +N 增量徽标」在上、大数字在下（对齐参考稿）。 增量 = 新周期（每周二 00:00 → 下周一 24:00）内新增量；周期规则说明收进卡片右上角 ⓘ，点击弹出标注浮层。

口径 ①
粒度 · 三指标并排
有钥匙房源数、钥匙分享数、被查看次数三个指标各自统计总量与本周期新增量，互不合并；缺省值显示 0。
口径 ②
样式 · label 行在上 · 大数字在下
对齐参考稿：灰 label 与 +N 同行，下方大数字；+0 与 +N 同为 Rust 橙，明确「本周期暂无新增」而非样式缺失。
口径 ③
周期说明 · 右上角 ⓘ 弹层
hero 卡右上角 ⓘ 图标，点击弹出标注浮层：周期规则 + 当前周期起止日期；点击浮层外任意区域收起，不占常驻版面。
口径 ④
周期 · 周二 → 下周一
以自然周周二 00:00 为起点、下周一 24:00 为终点；周一打开时展示的是上周二至今的累计新增（详见下方可交互演示）。
口径 ⑤
数据源 · 需后端聚合
三指标总量与增量均需跨房源聚合（查看次数在 key_audit_logs），建议新增 GET /keys/summary 只读端点，⚠️ 端点与部分口径待后端确认。
口径 ⑥
权限 · 与列表同范围
hero 统计范围 = 当前用户可见房源（admin 全量 / 相关人仅关联房源），与 /keys/properties 同一权限口径，不泄露无关数据。
指标总量定义（建议口径）周期新增量（+N）
房源 UI 短名 「有钥匙的房源数」：可见房源中「至少有 1 个有效密码」的房源数 普通密码 normal_active_count > 0，或管理密码 manager_key_set = true，与列表页「管理密码已设 / 普通 N 有效」chip 同源 本周期内首次录入有效密码的房源数 按房源最早 confirmed_at（或生成时间）落在本周期计 1 次，重复生成不重复计
分享 UI 短名 「房源钥匙分享数」：可见房源累计创建的钥匙分享总数 含已过期 / 已撤销（share 创建即计）；如需只看「分享中」可切 active 口径，见 SEC 03 待确认① 本周期内新建的分享数 按 key_shares.created_at ∈ [周期起点, 现在] 计
查看 UI 短名 「钥匙被查看次数」：分享密码被查看的累计次数 按 key_audit_logs 的 reveal / agent_view 动作计，与分享记录页「查看明细」同审计口径 本周期内新增的查看次数 按 audit 发生时间过滤；同一访客重复查看按次累计（待确认②）
CYCLE DEMO · 点击右上按钮切换「今天是周几」，观察周期窗口（高亮 = 计入新增）

SEC 03

实现说明

hero 三指标均需跨房源聚合 + 周期过滤，无法纯前端从 /keys/properties 现有字段推出（被查看次数在审计日志里）， 建议后端新增只读聚合端点，前端一次取数渲染。

建议端点 · GET /keys/summary（⚠️ 待确认）
{
  "properties_with_keys": 9,      // 有钥匙房源数
  "shares_total": 15,             // 钥匙分享累计
  "views_total": 36,              // 被查看累计
  "period_new": {
    "properties_with_keys": 2,    // 周期内新录入房源
    "shares_total": 5,            // 周期内新建分享
    "views_total": 12             // 周期内查看次数
  },
  "period": { "start": "2026-10-06", "end": "2026-10-12" }
}
  • 权限与 /keys/properties 同口径（复用 CurrentCEmployeeUserDep + key_access 过滤），仅统计当前用户可见房源
  • Router 不写查询 → Service 聚合（services/projects/key_access.py 同层新增 summary 组装）；周期计算复用周二起点公式
  • 只读端点零落库；查看次数走 key_audit_logs 现有审计记录，不新增埋点
前端落点 · 纯展示改动
  • wxml：pages/keys/list/index.wxml list-head 之前插 <view class="kpi-hero"> 三列 + ⓘ 弹层
  • wxss：新增 .kpi-hero 组样式（令牌复用 --rust / --graphite / --fog，不引入新色值）
  • ts：loadList 并行 request("/keys/summary")；summary 失败静默隐藏 hero，不进列表 error 态
  • ⓘ 弹层：tap 切换 show 类；周期起止文案由后端 period 字段拼装，前端不做周期推算
⚠️ 待确认口径
  • ① 分享数口径：累计创建（含过期/撤销）还是「分享中」active 数？设计稿按累计创建绘制
  • ② 查看次数口径：同一访客重复查看按次累计（本稿口径），还是按去重访客数？
  • ③「有钥匙」定义：普通密码有效或管理密码已设，二者满足其一即计（本稿口径）
  • ④ 缓存策略：/keys/properties 走 SWR 缓存，summary 是否同缓存 key 策略（回列表页即时刷新增量）？
E2E 验证点（落地时）
  • admin 打开钥匙管理：hero 三列数值与 DB 聚合一致（psql 对账）
  • 普通相关人（如 zhiwuping1）：hero 数值 = 其关联房源聚合，不泄露无关房源
  • 周期边界：跨周二 00:00 后增量归零、总量不变；周一打开显示上周二起累计
  • ⓘ 点击开/收、点外部收起；summary 接口 500 时 hero 隐藏且列表正常
  • +0 徽标橙色渲染（可构造无新增的小号测试周期）
