# 迭代计划：房源预约与分享归因闭环（2026-08-23）

> **执行方式**：任务使用 checkbox（`- [ ]`）跟踪，按阶段顺序执行；每个任务完成后跑对应验证命令再提交。

**目标**：打通「房源分享 → 打开 → 想看房预约」归因链路，统一三类分享（房源/评估/招募）的数据漏斗口径（分享次数/PV/UV/留资，昨日 + 累计），并重构「我的」页分享入口。

**技术栈**：FastAPI + SQLAlchemy（同步 Session）+ PostgreSQL ｜ 原生微信小程序（TS + wxml/wxss）｜ 类型由 `pnpm gen-api` 生成。

## 3. 数据库变更（一次迁移，全部幂等）

新表 5 张（均含 `BaseModel` 公共列 + `created_at/updated_at` timestamptz）：

```
project_bookings            预约（需求1/2）
  id PK / marketing_project_id int idx / user_id str(36) idx
  phone EncryptedString(20) / phone_hash str(64)
  referrer_user_id str(36) nullable idx
  UNIQUE(user_id, marketing_project_id)   -- 幂等防重

project_visits              房源详情打开 PV/UV（需求3）
  id PK / visitor_id str(64) idx（匿名 UV 去重键，前端生成 uuid 存 storage）
  referrer_employee_id str(36) idx / marketing_project_id int
  source str(20) / created_at idx

project_share_events        房源分享事件（需求3）
  id PK / employee_id str(36) idx / marketing_project_id int nullable
  share_type str(20)(card|timeline) / created_at idx

valuation_visits            估价页打开 PV/UV（需求6）
  id PK / visitor_id str(64) idx / referrer_employee_id str(36) idx
  source str(20) / created_at idx

valuation_share_events      估价页分享事件（需求6）
  id PK / employee_id str(36) idx / share_type str(20) / created_at idx
```

设计说明：
- **访客埋点免登录**：房源详情/估价页大量访客未登录，PV/UV 若要求 C 端登录会严重低估。采用前端生成的匿名 `visitor_id`（uuid，存 storage）做 UV 去重，接口限流防刷。与招募（需登录、`openid_hash`）口径不同但语义一致，⚠️ 差异已显式标注。
- **分享事件需登录**：仅内部员工分享才有归因意义，复用现有令牌（aud=c 或 aud=admin 均可，取 `sub` 为 employee_id）。
- 不改 recruit 现有表，只扩展统计响应。

统计实现（昨日窗口，招募/评估/房源共用一个工具函数）：

```python
from datetime import datetime, timedelta
from zoneinfo import ZoneInfo

_CST = ZoneInfo("Asia/Shanghai")

def yesterday_window() -> tuple[datetime, datetime]:
    """昨日 00:00 ~ 今日 00:00（Asia/Shanghai，timezone-aware）。"""
    now = datetime.now(_CST)
    today_start = now.replace(hour=0, minute=0, second=0, microsecond=0)
    return today_start - timedelta(days=1), today_start
```
