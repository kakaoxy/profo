## 一、定位与范围

### 1.1 一句话定位

原需求「新增线索跟进列表入口」经评估与现有 `/admin/leads` 列表页功能重复，**不新增路由、不动侧边栏**，
在现有列表上做三处增量（编号与设计稿 ①②③ 一致）：

| # | 改动 | 口径 |
|---|------|------|
| ① | 评估价前移到「业主报价/单价」之后，并补**评估单价**（评估价÷面积） | 派生值前端实时计算，后端不新增列 |
| ② | 创建/更新时间由两列合并为一列，上下两行叠放 | 当年 `MM-DD`，跨年 `YYYY-MM-DD`；`title` 恒为完整时间 |
| ③ | 「状态」与「录入人」之间插入**跟进结论**、**最后一条跟进内容**两列 | 取该线索最近一条跟进（`followed_at` 降序，同刻 `id` 降序兜底） |

表格 **10 列 → 11 列**；行粒度不变：一行 = 一个线索，不展开成跟进记录行。
行点击行为不变：打开右侧 720px 抽屉；抽屉「跟进记录」登记区已有结论 chip（2026-10-26 落地），
本次验证「登记后列表两列即时刷新」链路，不改动登记交互本身。

### 1.2 范围（In）

- ❌ 不新增页面/路由/侧边栏项；❌ 不改状态流转、筛选机制（search/statuses/district 后端口径不动）、权限模型；

### 2.3 表格 11 列规格

容器 `overflow-x-auto`，`<table class="w-full min-w-[1224px] table-fixed">`（⚠️ 不用设计稿的 `colgroup`——
`table-fixed` 下响应式隐藏 `th` 后剩余列按宽度类重排，colgroup 则会错位；列宽由 th 宽度类表达，效果等同设计稿）。
`min-width = 固定列合计 1090 + 弹性列最小 134 = 1224px`：`table-fixed` 只认首行 width、忽略 min-width，
弹性列（最后一条跟进内容）无法用自身 min-width 兜底，必须由表格级 min-width 保证，
否则视口 1180–1280px 时弹性列被压瘪成窄条、与录入人间出现大空白（交付后实测修复，见 §5.3）。
行内 `whitespace-nowrap`，超长 `truncate`；跟进内容列允许 2 行。

| 列 | 宽 | 对齐 | 内容 | 断点 |
|---|---|---|---|---|
| 小区 / 房源 | `w-[196px]` | 左 | 44×36 缩略图（`rounded-[9px]`，无图用 Home 图标 fog 底）+ 小区名 + 楼栋户室 | 常显 |
| 区域 | `w-[84px]` | 左 | 行政区主值（13px ash）+ 商圈次值（cell-sub） | `hidden lg:table-cell` |
| 户型 / 楼层 | `w-[120px]` | 左 | 户型主值；「面积㎡ · 楼层」次值 | 常显 |
| 业主报价 / 单价 | `w-[102px]` | 右 | 报价千分位（万）；单价 `toFixed(2)` 万/㎡ | 常显（<sm 隐藏，沿用现状） |
| 评估价 / 单价 | `w-[102px]` | 右 | 评估价 + 评估单价；空值统一 `—` | 常显 |
| 状态 | `w-[82px]` | 左 | `LEAD_STATUS_META` 徽标 | 常显 |
| 跟进结论 | `w-[142px]` | 左 | 四态徽标（§2.2） | `hidden md:table-cell` |
| 最后一条跟进内容 | 弹性（≥134，由表格级 min-width 保证） | 左 | 正文 `line-clamp-2` + `title` 全文；meta「MM-DD · 跟进人 · 方式」11px dove | `hidden md:table-cell` |
| 录入人 | `w-[96px]` | 左 | 首字圆徽（28px，fog 底 ink 字）+ 昵称（容 3 字姓名，超长 truncate） | `hidden xl:table-cell` |
| 创建 / 更新 | `w-[88px]` | 左 | 两行 stack：`创建 MM-DD` / `更新 MM-DD`，k 标签 10.5px dove，`title` 完整时间 | `hidden xl:table-cell` |
| 操作 | `w-[78px]` | 右 | 「查看 / 删除」文字链（D1） | 常显 |

单元格纵向 `py-2.5`（10px）；表头 12.5px graphite 500，带单位副行（`u`：11px dove）。行 hover `bg-fog`；
行 `tabIndex=0`、`Enter/Space` 开抽屉、焦点环 2px rust（`-outline-offset-2`）。

无跟进行占位与两行正文等高（正文 12.5px×1.55×2 ≈ 39px 的 `min-h`），保证行高一致、无灰条差异。

## 三、后端设计

### 3.1 Schema（`backend/schemas/lead/__init__.py`）

```python
class LeadFollowUpSummary(BaseModel):
    """列表内嵌的最近一条跟进摘要（无跟进时为 None，不得伪造）."""
    method: FollowUpMethod
    content: str
    conclusion: FollowUpConclusion | None = None
    followed_at: datetime
    created_by_name: str | None = None
```

`LeadListItem` 增 `latest_follow_up: LeadFollowUpSummary | None = None`。

**无数据库迁移**：`lead_followups.conclusion` 列已由 `add_lead_followup_conclusion.py`（2026-10-26）落地。

### 3.2 查询（`backend/services/leads/internal/query.py`）

新增 `get_latest_follow_ups(lead_ids: list[str]) -> dict[str, dict[str, Any]]`：
**窗口函数范式**（与 `get_latest_eval_verdicts` 同构，仓库既有范式），
`row_number() over(partition_by lead_id, order_by followed_at DESC, id DESC)` 取 rn=1，
`outerjoin(User)` 回填 `created_by_name`。空列表直接返回 `{}`，不发查询。

口径（写入 docstring）：
- 最近一条 = `ORDER BY followed_at DESC, id DESC` 第一条；**不用 `max(id)` 代替时间**；
- `conclusion` 取该条记录原值，可为 NULL；**不得回退到上一条有结论的记录**；
- `content` 回全文，截断在前端 CSS `line-clamp` 做（保证 `title` 悬停全文完整）。

### 3.3 路由（`backend/routers/leads/core.py`）

`get_leads`：在既有 `verdicts` 批量解析后，加
`followups = service.query_service.get_latest_follow_ups([...])`（单次查询），
`_lead_to_list_item(lead, names=..., verdict=..., followup=followups.get(lead.id))` 组装。
`_lead_to_list_item` 增 `followup: dict | None = None` 参数（默认 None，其他调用点不传不受影响）。

### 3.4 契约同步

后端 `--reload` 生效后 `curl` 验证 openapi → `pnpm gen-api`（生成类型不手改）。
