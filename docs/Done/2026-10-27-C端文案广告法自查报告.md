## 一、结论摘要

### 1.1 一句话结论

C 端文案的最大问题不是"用词夸张"，而是**宣称与数据不一致**：页面反复强调"真实成交价可查""成交价真实可验""4 天成交"，但支撑这些宣称的字段取的是**挂牌价/签约价**与**营销记录创建-更新时间差**，实测 91.7% 的已售房源展示价 ≠ 实际成交价、96.6% 的已售房源被渲染成"0 天成交"。这类问题在《广告法》下属于第二十八条"虚假广告"，罚则为广告费 3–5 倍或 20–100 万，风险等级高于"最/第一"这类绝对化用语。

### 1.2 分级汇总

| 级别 | 数量 | 含义 | 处置要求 |
|---|---|---|---|
| **P0** | 8 | 命中《广告法》禁止性条款或已构成虚假宣传客观要件 | 上线前必须修复，或下线对应文案/字段 |
| **P1** | 11 | 高风险：承诺无依据、引证无出处、强制披露缺失 | 建议本迭代修复 |
| **P2** | 9 | 中风险：措辞不当、易被举报、执法尺度内可解释 | 排期修复 |
| **P3** | 4 | 低风险：命名/一致性问题，不直接违法 | 顺手修复 |

### 1.3 三类系统性问题（比单条文案更值得关注）

1. **"真实性宣称"没有数据保障机制**：`真实成交价`/`成交周期`/`累计服务家庭`/`累计佣金` 四类核心宣称，要么取错字段，要么取的是"条数"当"人数"，要么直接硬编码在常量里。只要宣称"真实"，举证责任就在经营者一侧（《广告法》第四条、第二十八条）。
2. **对外营销文案完全由运营自由输入，无合规校验**：房源标题字段仅校验 `min_length=1, max_length=255`（[`backend/schemas/l4_marketing/project.py:72`](<../../backend/schemas/l4_marketing/project.py>)），后台输入框 placeholder 还是"输入吸引人的房源标题"。线上已出现"书包房""大师设计""豪华装修""质保5年""稀缺房源"等表述。
3. **同一页面内自相矛盾**：About 页一面写"业主不用参与"（`c-locale.ts:163`），一面写"装修方案需业主确认"（`:166`）；一面写"最差=免费得一套装修，0 现金损失"（`:164`），一面写"美房宝不承诺保底收购"（`:293`）。监管与消费者投诉时，矛盾双方都会被引用。

### 2.2 为什么"零风险"比"最好"更危险

《广告绝对化用语执法指南》第十一条明确把两类情形排除在"违法轻微可免罚"之外，其中第(二)项就是**招商类广告中涉及投资收益率、投资安全性的绝对化用语**。本项目"零成本、零风险的卖房方案"同时命中"投资安全性"与"收益确定性"，且小程序招募页（面向经纪人）本身即招商广告，属最严格档位。

### P0-03 「N 天成交」周期失实，96.6% 渲染为「0 天成交」

**问题**：`sold_days` 计算的是**营销记录 `updated_at − created_at`**，不是签约到成交：

```python
# backend/routers/public/projects.py:136-138
if item.updated_at and item.created_at:
    delta = item.updated_at - item.created_at
    sold_days = delta.days
```

**实测证据**

- 全量 298 条已售房源中 **288 条 `sold_days == 0`（96.6%）**；`< 2 天` 共 289 条。
- Web `/contact` 首屏 50 张卡片中 **41 张渲染"0天成交"（82%）**。
- 与真实交易时间线对照（管理端 `signing_date` / `sold_date`）：

| 房源 | C 端展示 | 营销记录创建→更新 | 真实签约→成交 | 偏差倍数 |
|---|---|---|---|---|
| 308 呼玛二村 | **4 天成交** | 10-15 → 10-20 | 2026-07-26 → 2026-10-20（**86 天**） | 21× |
| 4 通河八村 | **22 天成交** | 08-05 → 08-28 | 2026-04-22 → 2026-08-14（**114 天**） | 5× |
| 297 淞南四村 | **52 天成交** | 08-27 → 10-19 | 2026-04-10 → 2026-10-19（**192 天**） | 3.7× |
| 299 阳曲路470弄 | **51 天成交** | 08-27 → 10-18 | 2026-04-19 → 2026-10-14（**178 天**） | 3.5× |
| 10 通河八村 | **2 天成交** | 08-15 → 08-18 | 2025-10-26 → 2026-02-09（**106 天**） | 53× |

**违反**：《广告法》第二十八条（销售状况与实际情况不符）、第二十六条（房源信息真实）。

**整改建议**

- 停止用 `updated_at − created_at` 推算成交周期；改由 `ProjectSale.sold_date − ProjectSale.listing_date`（或其与 `signing_date` 的明确口径）计算，字段缺失时**不渲染**该 chip。
- 若短期内无法改后端，`SoldProjectCard` 应**先隐藏**成交天数 chip（[`SoldProjectCard.tsx:45-51`](<../../frontend/src/components/c/project/SoldProjectCard.tsx>)），不要让 96.6% 的卡片显示"0天成交"。

### P0-07 「最差 = 免费得一套装修，0 现金损失」无法证明 + 与风险告知自相矛盾

**问题**：这是全套文案中**最激进**的一句，但它既无业务文档依据，也未满足"附赠需明示规格"的强制要求，且与同页风险告知直接冲突。

**出现位置**

| 端 | 位置 | 文案 |
|---|---|---|
| Web | [`c-locale.ts:164`](<../../frontend/src/lib/i18n/c-locale.ts>) | "风险上限清晰：**最差=免费得一套装修，0现金损失**" |
| Web | [`c-locale.ts:213`](<../../frontend/src/lib/i18n/c-locale.ts>) | "**业主最差的结果 = 免费得一套装修，0现金损失**" |
| Web | [`c-locale.ts:182`](<../../frontend/src/lib/i18n/c-locale.ts>) | "卖到约定价，业主拿钱；卖不到约定价，装修免费送业主。**两种结果，业主都不亏。**" |
| Web | [`c-locale.ts:210`](<../../frontend/src/lib/i18n/c-locale.ts>) | "装修免费送业主，**业主0现金损失**" |
| 小程序 | [`about/index.wxml:90`](<../../miniapp/pages/about/index/index.wxml>) / [`:131`](<../../miniapp/pages/about/index/index.wxml>) | 同上（"0 现金损失"） |

**三重问题**

1. **无依据**：全仓 `docs/**` 检索 `未售出 / 免费赠送 / 装修归业主 / 卖不到` 均无命中——即该承诺**没有任何业务说明书或合同条款支撑**，属于"广告主无法证明其真实性"（《执法指南》第七条）。
2. **附赠要素缺失**：装修属"附带赠送"，按《广告法》第八条第二款必须明示**品种、规格、数量、期限和方式**。当前只说"一套装修"，无装修标准、无金额上限、无交付期限、无兑现方式。
3. **自相矛盾**：同页 [`c-locale.ts:293`](<../../frontend/src/lib/i18n/c-locale.ts>) 写"美房宝**不承诺保底收购**……未售出则装修免费赠送"，与"0 现金损失"并存，监管与投诉方会同时引用。

**另外**："业主都不亏"中的"不亏"是财务结果判断，属第二十五条(一)禁止的"保本"暗示变体。

**整改建议**

```diff
- 风险上限清晰：最差=免费得一套装修，0现金损失
+ 结果约定清晰：未售出时，已投入的装修按合同约定归属业主（详见合同条款）

- 业主最差的结果 = 免费得一套装修，0现金损失
+ 未售出情形按合同约定处理，装修归属以合同条款为准

- 两种结果，业主都不亏。
+ 卖到约定价，业主按约定价结算；未售出情形按合同约定处理。
```

并在 About 页首次出现"装修归属"处补一行**附赠要素说明**：

```
* 装修赠送标准、范围与交付方式以合同附件《装修清单》为准；本页仅为服务模式示意。
```
