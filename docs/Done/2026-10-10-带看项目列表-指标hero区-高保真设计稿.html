SEC 01

需求与口径

带看项目列表页（pages/viewing/projects/index/index，导航栏「我负责的项目」）页首新增指标 Hero 区， 样式与交互完全对齐钥匙管理列表 hero：一张白卡内并排三列指标——带看 / 出价 / 面谈 （与项目卡 card-counts 三计数同源同短名），每列为「灰色小标签 + 橙色 +N 增量徽标」在上、大数字在下。 增量 = 新周期（每周二 00:00 → 下周一 24:00）内新增量；周期规则说明收进卡片右上角 ⓘ，点击弹出标注浮层。 hero 卡底右侧新增「带看记录」链接，落地到新增的时间降序明细页（ARTBOARD 03）。

口径 ①
粒度 · 三指标并排
带看、出价、面谈三个指标各自统计总量与本周期新增量，互不合并；缺省值显示 0。
口径 ②
样式 · label 行在上 · 大数字在下
对齐钥匙版：灰 label 与 +N 同行，下方大数字；+0 与 +N 同为 Rust 橙，明确「本周期暂无新增」而非样式缺失。
口径 ③
周期说明 · 右上角 ⓘ 弹层
hero 卡右上角 ⓘ 图标，点击弹出标注浮层：周期规则 + 当前周期起止日期；点击浮层外任意区域收起，不占常驻版面。
口径 ④
周期 · 周二 → 下周一
复用 utils/cycle-period 周二起点规则（与项目卡 +N 角标同一周期口径）；周一打开时展示的是上周二至今的累计新增（详见下方可交互演示）。
口径 ⑤
数据源 · 需后端聚合（已确认）
主通道 GET /projects 分页 20 条/页，前端聚合已加载项数字不完整；新增聚合端点按全量可见项目统计总量与增量（见 SEC 03）。
口径 ⑥
权限 · 与列表同范围
主通道（admin/operator，project:read）＝全部在售项目；回退通道 my-responsible＝业务身份负责项目。聚合端点按调用方实际可见范围统计，与列表口径一致。
口径 ⑦
卡底 · 左范围说明 · 右链接（已确认）
卡底一行：左「统计范围与下方列表一致」灰说明；右「带看记录」Rust 链接 → 时间降序明细页，呈现全部记录明细。
指标总量定义（建议口径）周期新增量（+N）
带看 record_type = viewing 可见在售项目的销售记录中 viewing 类型总条数 与项目卡「带看」计数同源（countByType 不过滤字段）；admin 全量 / 相关人仅负责项目 本周期内新增的带看记录数 按 record_date ∈ [周期起点, 现在] 计，与卡片周期角标同一 cycleStart 口径
出价 record_type = offer 可见在售项目的销售记录中 offer 类型总条数 ⚠️ 未填/非正价格的出价是否计入待确认①；卡片计数现不过滤，本稿与卡片同源不过滤 本周期内新增的出价记录数 同上按 record_date 过滤
面谈 record_type = negotiation 可见在售项目的销售记录中 negotiation 类型总条数 与项目卡「面谈」计数同源 本周期内新增的面谈记录数 同上按 record_date 过滤
CYCLE DEMO · 点击右上按钮切换「今天是周几」，观察周期窗口（高亮 = 计入新增）

SEC 03

实现说明

hero 三指标需全量可见项目聚合 + 周期过滤：主通道分页（20 条/页）导致前端聚合已加载项数字不完整， 新增后端聚合端点一次取数；明细页同理需要跨项目时间降序的记录流端点。

建议端点 · GET /projects/sales-summary?status=selling（⚠️ 待确认）
{
  "viewing_total": 24,            // 带看记录总数
  "offer_total": 9,               // 出价记录总数
  "negotiation_total": 6,         // 面谈记录总数
  "period_new": {
    "viewing": 5,                 // 周期内新增带看
    "offer": 2,                   // 周期内新增出价
    "negotiation": 1              // 周期内新增面谈
  },
  "period": { "start": "2026-10-06", "end": "2026-10-12" }
}
  • 权限与列表双通道同口径：持 project:read（admin/operator）聚合全部在售项目；403 场景按 my-responsible 业务身份口径聚合负责项目
  • Router 不写查询 → Service 聚合；周期计算与前端 utils/cycle-period 周二起点公式一致（建议后端为唯一真源，period 直出起止日期）
  • 只读端点零落库；数据源 = projects JOIN sales_records，status=selling 与页面过滤一致
明细页端点 · GET /projects/sales-records（⚠️ 待确认）
{
  "items": [
    {
      "record_type": "offer",
      "record_date": "2026-10-09",
      "price": "460",
      "related_agent": "链家",
      "operator": { "name": "唐" },
      "project_name": "金杨七街坊18号502"
    }
  ],
  "total": 39, "page": 1, "page_size": 20
}
  • 按 record_date 降序、同日 created_at 降序分页；筛选用 ?record_type=viewing|offer|negotiation
  • 权限与 summary 完全同口径（同一 Service 过滤函数复用），不泄露无关项目记录
  • project_name 后端拼好直出（address 兜底 community_name），前端不做项目信息二次请求
前端落点 · 纯展示改动
  • wxml：pages/viewing/projects/index/index.wxml list-title 之前插 <view class="kpi-hero"> 三列 + ⓘ 弹层
  • wxss：新增 .kpi-hero 组样式（整段从 pages/keys/list/index.wxss 平移，令牌复用 --rust / --graphite / --fog，不引入新色值）
  • ts：index.ts toDisplay 后并行 request("/projects/sales-summary")；summary 失败静默隐藏 hero，不进列表 error 态
  • ⓘ 弹层：tap 切换 summaryPopOpen（照抄 keys/list 状态机）；周期起止文案由后端 period 拼装，前端不做周期推算
  • 「带看记录」链接：wx.navigateTo /pages/viewing/records/index（新页面，状态机照抄列表页 loading/error/needLogin/noPermission/empty/items）
⚠️ 待确认口径
  • ① 出价总量口径：未填/非正价格的出价记录是否计入？现卡片计数不过滤（countByType），本稿与卡片同源不过滤；如过滤需同步改卡片口径
  • ② 明细页字段映射：操作人取 operator.name（UserBriefResponse）；「（链家）」渠道取 related_agent——需确认真源字段；类型筛选 chips 是否保留
  • ③ 明细页导航栏标题：本稿用「带看记录」，与列表 list-title 前缀一致；备选「销售记录」
  • ④ hero 缓存策略：是否与列表共用 SWR 缓存 key（回列表页即时刷新增量）
E2E 验证点（落地时）
  • admin 打开「我负责的项目」：hero 三列数值与 DB 聚合一致（psql 对账）
