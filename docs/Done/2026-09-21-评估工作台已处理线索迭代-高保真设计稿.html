项取值说明

7 < d ≤ 14 即将过期 · Apricot 洗底 恰好 14 天算「即将过期」（用户表述的「超过 7 天不足 14 天」与「超过 14 天」之间，14 天归此档）

终态 signed / rejected / lost_to_competitor → 不显示 右下角留空；左侧时间回落为「处理 MM-DD」

我的评估 · 现状：同模块里第三套视觉语言

`pages/valuation/list/index` 是 C 端客户与内部员工的共用页。它目前走「暖色编辑风格」 （hsl(40,16%,98%) 画布 + 描边卡 + 24px 圆角 + 无阴影），而同模块的 detail 与 evaluate 都是 Steep（Fog 画布 + 白卡 + 阴影 + 无边框）—— 切页时底色与卡片质感会跳一次。 叠加第三个问题：状态徽章色来自后端 LEAD_STATUS_DISPLAY_MAP，是一套 Material 色板， 其中的蓝 / 绿 / 紫 / 橙正是 DESIGN.md 明令避免的「saturated blues, greens, or reds」。

本稿明确不改动的部分

  • Web admin/leads：本来就是对齐基准，不动。
  • 详情页的 internalOnly 态：无 C 端令牌的内部员工仍看不到 C 端评估详情（现状保留）。本轮只让「有 C 端身份的内部员工」能登记跟进 —— 这正好也是需求里说的那批人。若以后要让纯后台账号也能看，属于另一个议题。
  • 列表的分页 / 排序 / 搜索：/public/leads/mine 现有行为不变，只换皮。
  • 「授权价提醒」订阅逻辑：onSubscribeTap 与 utils/valuation-notify.ts 不变，只换外观。

本轮开放的三个点

  • 「我的评估」是否对纯 C 端客户也显示时效标签：本稿统一显示（同一套组件、零分支）。备选是客户侧改显「评估中 / 已出评估价」这类进度文案 —— 理由是 14 天阈值本质是内部考核口径，对客户暴露「已过期」可能引起投诉。
  • 卡片样式是否抽成公共组件：两个页面复制同一份 lcard wxss 是下一轮重构的候选（components/lead-card）；本稿只要求「同一份样式」，不强制抽组件。
  • 后端不补字段时的降级：若本轮只做「画布 + 状态标签入令牌体系」，缩略图不留空位、价格栈整体隐藏，视觉骨架仍然统一。
