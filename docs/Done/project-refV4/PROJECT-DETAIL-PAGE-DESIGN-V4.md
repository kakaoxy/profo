# 项目详情独立页设计 V4 — Steep 风格

> 迭代目标：将 `admin/projects` 的抽屉式项目详情升级为**独立页面**，遵循 `DESIGN.md`（Steep / 柔光大理石仪表盘），在**不损失任何现有功能**的前提下重构信息层级。

配套高保真原型：[project-detail-page-design-v4.html](./project-detail-page-design-v4.html)

> **V4.1 更新（2026.08.17）**
> 1. 新增**规范总览封面**（原型默认首页）：Token 色板映射 · 页面布局解剖线框 · 阶段视图矩阵 · 导航流程图
> 2. 补齐**关键交互弹窗**高保真设计：交房确认 / 上架确认 / 成交确认 / 删除确认（含表单字段、危险提示、按钮层级），原型内可实际点击演示，确认后 toast + 自动切换阶段视图
> 3. 强化 **Steep 编辑感**：Hero 区暖光晕（Apricot radial 渐变，对应 DESIGN.md 柔光氛围）、KPI 数字衬线化（Source Serif 4）
> 4. 原型补充移动端适配演示页与加载/空态/错误状态规范页

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| 阶段即导航 | 项目生命周期（签约→装修→在售→已售/已下架）作为页面顶部**水平进度导航**，既是指示器也是阶段视图切换器（沿用现有 `STAGE_CONFIG` 访问规则：只能查看 ≤ 当前阶段的视图） |
| 一屏一重点 | 每个阶段视图只突出该阶段的核心数据与主操作；跨阶段通用信息（基础资料、关键日期、快捷入口）固定在右侧栏 |
| 大理石编辑感 | 白/Fog 画布、24px 陶瓷卡片、Signifier 衬线项目名（唯一 44px 标题）、Rust 作为唯一暖色强调、Apricot/Sky Wash 仅用于数据小卡 |
| 一屏一实心 CTA | 每个阶段视图只有一个 Ink 填充胶囊主按钮（阶段流转动作），编辑/删除等一律为文本链接或次级形态 |
| 功能零损失 | 抽屉全部操作（CRUD、状态流转、文书、附件、照片、销售记录、权限控制）原样保留，仅改变容器与布局 |

## 2. 信息架构

```
/admin/projects/{projectId}
├── 顶部工具行      面包屑「项目列表 / 项目名」· 返回箭头 · 更新时间 · 编辑 ✎ · 删除 🗑（权限控制）
├── Hero 区
│   ├── 生命周期进度条   签约 → 装修 → 在售 → 已售（当前阶段 Rust 高亮，已完成实心圆点，未达成为 Dove 空心+锁）
│   ├── 项目名          Signifier 44px · 状态 pill · 业务形式 tag（代理美化/收购美化）
│   ├── Meta 行         小区 · 行政区/商圈 · 地址 · 面积 · 户型 · 合同编号
│   └── 主操作区        阶段流转 CTA（Ink 胶囊，随阶段变化文案）
├── Sticky 分区导航     概览 | 文书附件 | 装修进度 | 销售动态（按阶段视图动态生成）
└── 内容区（12 栏网格）
    ├── 主列 (8 栏)     阶段专属内容（KPI 行 + 信息卡 / 时间线 / 记录流）
    └── 副列 (4 栏)     团队与成员 · 关键日期 · 快捷入口（账本 / 监控）· 备注
```

## 3. 阶段视图矩阵（功能保留对照）

| 阶段 | 主列内容 | 主 CTA（唯一实心按钮） | 保留的操作 |
|------|----------|------------------------|-----------|
| 签约 signing | 摘要 KPI 行（签约价/面积/签约日期/委托期限）→ 项目信息卡（基本/业主/合同/公用事业）→ 文书与附件（6 类分组 + 上传/删除/预览） | 确认交房，开始装修 | 编辑、删除、文书 CRUD、初始化清单、附件上传/删除/预览、银行卡显隐、交房日期选择 |
| 装修 renovating | 装修 KPI（合同额/工期/当前阶段/已投入）→ 装修合同信息卡（硬装/软装/各项费用，可编辑）→ 六阶段时间线（拆除→设计→水电→木瓦→油漆→交付，照片墙、标记完成、修改日期） | 装修验收完成，上架销售（弹窗填上架日期+价格） | 阶段标记/日期修改、照片上传/删除/预览、合同信息读写 |
| 在售 selling | 在售 KPI（挂牌价/上架天数/带看/出价）→ 基础信息 → 销售团队卡（渠道/讲房/谈判，自动保存）→ 动态 Tabs（带看/出价/面谈，新增+删除） | 确认成交（弹窗填成交价/日期） | 团队保存、记录增删、结束项目（次级危险操作）、补登实际结束日期 |
| 已售 sold | 成交 Hero 指标（成交价/成交日期/售出天数/回报率）→ 财务生命周期（签约→装修→挂牌→成交现金流）→ 视觉旅程（装修前后对比）→ 总结报告 | —（终态无流转） | 修改销售信息（成交价/日期/挂牌价）、编辑、删除 |
| 已下架 ended | 基础信息卡 → 关键日期卡 → 下架说明 | — | 删除项目 |

## 4. 导航与入口

- **入口**：列表行点击 / 行内「编辑」→ `router.push(/admin/projects/{id})`（替换原抽屉 state）；账本、监控等既有 Link 不变
- **返回**：顶部面包屑 + 返回箭头 → `/admin/projects`（保留列表 URL 筛选参数）
- **直达**：URL 可分享、可刷新、可收藏（补齐抽屉刷新即丢的短板）
- **子路由**：`[projectId]/renovation`、`[projectId]/selling` 移动端视图保留，桌面统一入本页

## 5. 响应式

| 断点 | 布局 |
|------|------|
| ≥1280px | 8+4 主副双栏，KPI 4 列 |
| 768–1279px | 单栏，KPI 2×2，副列下沉为主列尾部分区 |
| <768px | 单栏，Hero 折叠（进度条横向滚动），操作收纳进底部吸顶操作条（与现有移动端模式一致） |

## 6. 交互反馈

- **加载**：首屏 RSC 直出；客户端刷新用卡片级 skeleton（24px 圆角呼吸动画）
- **成功/失败**：沿用 sonner toast；危险操作（删除/结束项目）一律 AlertDialog 二次确认
- **空状态**：文书/照片/记录空态提供引导按钮（如「初始化默认文书清单」）
- **阶段流转**：流转成功 → toast + 进度条前进动画 + 自动切至新阶段视图

## 7. 与 DESIGN.md 的 token 映射

| 设计元素 | Token |
|----------|-------|
| 页面画布 | Fog `#f7f7f8` |
| 卡片 | Pure White · 24px radius · 三层签名阴影（1px ink 描边 + 20/25 + 8/10 投影） |
| 项目名 | Signifier 44px / Ink，页面唯一衬线标题 |
| 阶段进度强调 | Rust `#5d2a1a`（进度条、当前阶段圆点、关键数字） |
| 数据小卡 | Apricot Wash `#fbe1d1`（暖：价格/成交）/ Sky Wash `#d3e3fc`（冷：天数/进度） |
| 主 CTA | Ink 填充胶囊（9999px），每屏一个；次级动作为文本链接 |
| 正文/表格 | Sohne（实现以 Inter 替代）14–16px，430/450/480 微字重分级 |

> 原型中以 Source Serif 4 / Inter 作为 Signifier / Sohne 的网页替代字体，实现时对应项目现有字体栈。
