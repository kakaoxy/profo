## 4. 测试验证中的两个重要发现

### 4.1 `test_image_download.py::test_download_jpeg_success`（本次 commit 新增，全量 1 失败）

- **现象**：`FileNotFoundError`——断言 `local_path.read_bytes()` 时本地临时文件已不存在。
- **根因**：该测试断言「本地临时文件应已写入」，但本地开发 .env 配置 `STORAGE_BACKEND=oss`（生产配置），`utils/image_download.py:225-226` 在 oss 模式下上传后主动 `unlink` 临时文件 → 断言必失败。同文件 `test_download_png_success` **没有**该 `read_bytes` 断言，所以通过（不对称即证据）。
- **验证**：`STORAGE_BACKEND=local` 下单独重跑 → `1 passed`。
- **定性**：环境敏感测试缺陷（非代码 bug、非本 commit 逻辑错误）。CI/生产（local）通过、本地（oss）必挂，与 AGENTS「pytest 全绿」矛盾。
- **建议**：测试内 `monkeypatch.setattr("utils.image_download.settings.storage_backend", "local")` 固定后端，或改为在 oss 分支断言「文件已清理」。

### 4.2 `test_phone_encryption.py::TestPhoneMigration`（8 个失败，已修复环境后全部通过）

- **现象**：`null value in column "is_temporary"` NOT NULL 违反。
- **根因**：既有 `profo_test` 库的 `users.is_temporary` 列**存在但缺少 DEFAULT FALSE**（`column_default is None`）。`migrations/_user_security.py:157` 以 `_column_exists` 判定"列已存在"即跳过 ADD COLUMN，对「列存在但缺默认值」的陈旧中间态**无法自愈**。
- **修复**：`ALTER TABLE users ALTER COLUMN is_temporary SET DEFAULT FALSE` 后 16 用例全部通过。
- **定性**：非本 commit 引入的逻辑缺陷，但暴露迁移幂等判断的盲区。
- **建议**：迁移中对该类"带 DEFAULT 的 NOT NULL 列"补 `SET DEFAULT`，或文档标注测试库 schema 需与迁移最终态一致。
