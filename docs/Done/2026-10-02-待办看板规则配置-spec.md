## 一、定位与范围

### 1.1 一句话定位

把待办规则的触发阈值从后端常量升级为**管理员可配置**：看板页右上角新增「规则配置」入口，弹窗内编辑全部阈值并显式保存；R8 由「当前工序停滞」改造为「**交房日 + N 天**里程碑制」，R2 由「缺即提示」改为「**签约后 N 天**宽限 + 字段集三态可编辑」。

### 1.2 范围（In）

| 层 | 内容 |
|---|---|
| 后端 | 规则引擎改造（R8 里程碑制、R2 宽限+字段集、阈值全部改注入）、配置存储（system_configs 单键 JSON）、`GET/PUT /api/v1/projects/todo-board/config` 端点 |
| 前端 | 页头「规则配置」入口按钮 + 配置弹窗（桌面 Popover / 移动 Sheet 共用 body）、RSC 首屏并行取配置 |
| 无迁移 | system_configs 表已存在（models/system.SystemConfig），无 schema 变更、无迁移脚本 |

### 1.3 非范围（Out）

- ❌ 配置变更历史/审计查询（仅 updated_by_id 落库）；❌ 按项目粒度的差异化阈值（全局单值）；❌ 已打开页面热更新（保存后下个快照=下次页面加载）；❌ R3/R3a/R9/R5 规则逻辑变动（本轮不动，也无阈值开放——R3/R3a 无阈值，R9 竣工逾期、R5 交房逾期以日期直接判定）。

### 1.4 关键口径收口

| # | 决策 | 实施口径 |
|---|---|---|
| K1 | R8 里程碑制 | 遍历 6 工序：`today > 锚点 + N 天` 且 `stage_completed_dates` 无该工序记录 → 各出一条待办；`rule_code = "R8·工序名"`（卡片 key 唯一）；锚点 = 约定交房时间 →（为空）进入装修状态日志日 →（皆无）静默跳过；`actual_end_date` 非空**且 6 工序全部有完成记录**（已竣工且工序闭环）才整体跳过，竣工但工序缺记录仍逐工序提示（防「录了竣工日期但工序未完成」的数据矛盾被静默，2026-10-02 修订）。P1 起，逾期 `> milestone_p0_overdue_days` 天升 P0 |
| K2 | R2 宽限 | 触发 = `签约日期存在 且 today > 签约日 + basic_info_grace_days 且 检查字段仍有缺失`；签约日期缺失静默跳过（R1 合同未生效兜底）；核心缺 → P1、仅次要缺 → P2、全齐 → 不提示。⚠️ 现网「缺即提示」→ 默认 7 天宽限属**行为变化**（业务已知悉） |
| K3 | R2 字段集 | 11 字段（签约价/业务形式/交房时间/业主联系方式/面积/户型/朝向/楼层信息/水电户号/水表户号/燃气户号）三态 core/minor/off；字段名 → 判空映射固化在规则引擎；配置中出现未知字段名静默忽略 |
| K4 | 默认值 | 里程碑：设计 7 / 拆除 3 / 水电 14 / 木瓦 30 / 油漆 45 / 交付 60（⚠️ 与旧 STAGE_STANDARD_DAYS 数值不同——语义已从停滞工期变为交房锚点，木瓦/油漆/交付为占位值待业务校准）；升 P0 线 7；R2 宽限 7；R6 宽限 7；R7 宽限 15；R4 归档 30；R10 临近 30 |
| K5 | 存储 | system_configs 单键 `todo_board_rules`，value = JSON 全量；**缺行/JSON 损坏/部分键缺失 → 逐字段回退代码默认**（读取路径永远可用）；保存为全量 upsert，写 updated_by_id 审计 |
| K6 | 权限 | GET 用 `ProjectReadPermDep`（全员可见口径）；PUT 用 `CurrentAdminUserDep`（非 admin 403）；前端按 `usePermission().roleCode === "admin"` 切换编辑/只读态 |
| K7 | 生效语义 | 保存即写库；看板每次进入实时重算 →「下个规则快照」= 下次页面加载/刷新；保存成功后前端 `router.refresh()` 拉新快照 |
| K8 | 恢复默认 | 前端「恢复默认」只回填表单并标脏，**不自动保存**；默认值来源于 GET 响应的 `defaults` 字段（后端唯一真源，避免前端镜像漂移——对设计稿 API 骨架的已声明扩展） |
| K9 | 数值约束 | 所有天数 1~999（整数）；字段值枚举 core/minor/off；PUT 全量提交，6 工序键与 11 字段键必须齐全（422） |
| K10 | 不入弹窗 | R2_HINT_MAX_NAMES / R4_HINT_MAX_NAMES / MAX_TODOS_PER_CARD / CORE_DOCUMENT_NAMES 留在代码 |

### 2.2 数据结构

```python
# todo_board_rules.py（纯模块，不依赖 db）
MILESTONE_STAGES = ("设计", "拆除", "水电", "木瓦", "油漆", "交付")   # 弹窗展示顺序
BASIC_INFO_FIELD_NAMES = ("签约价", "业务形式", "交房时间", "业主联系方式",
                          "面积", "户型", "朝向", "楼层信息",
                          "水电户号", "水表户号", "燃气户号")           # 前 4 默认 core，余默认 minor

@dataclass(frozen=True)
class TodoBoardRules:
    milestone_days: dict[str, int]        # {工序: 交房后 N 天内须完成}
    milestone_p0_overdue_days: int        # 逾期超 N 天 P1→P0
    basic_info_grace_days: int            # R2 签约后宽限
    basic_info_fields: dict[str, str]     # {字段: core|minor|off}
    company_grace_days: int               # R6
    start_grace_days: int                 # R7
    archive_overdue_days: int             # R4
    commission_near_days: int             # R10

    @classmethod
    def defaults(cls) -> "TodoBoardRules"   # 字面量 = 设计稿 ARTBOARD 00-A 默认列
```

规则引擎内新增字段名→判空映射（`ProjectFacts` 属性）：签约价→`signing_price`、业务形式→`business_form`、交房时间→`planned_handover_date`、业主联系方式→`has_owner_contact`、面积→`area`、户型→`layout`、朝向→`orientation`、楼层信息→`floor_info`、水电户号→`electricity_account`、水表户号→`water_account`、燃气户号→`gas_account`。

### 2.3 规则引擎改造要点

- `_rule_r8(facts, today, rules) -> list[TodoDraft]`：
  - 跳过：`actual_end_date` 非空且 6 工序全部有完成记录（竣工闭环）；锚点（`planned_handover_date` → 回退 `entering_renovating_at`）为 None。竣工但工序缺记录 → 不跳过，缺哪条提示哪条。
  - 命中：`deadline = 锚点 + milestone_days[工序]`；`today > deadline` 且工序无完成记录。
  - 产出：`rule_code=f"R8·{工序}"`、title=「工序节点逾期」、hint=`{工序} 交房后 {N} 天`、days_label=`逾期 {over} 天`（hot）、overdue_days=over、anchor=renovation_progress、priority = p0 if `over > milestone_p0_overdue_days` else p1。
  - items 含：工序节点 / 里程碑口径 / 已逾期天数 / 处理建议。
- `_rule_r2(facts, today, rules)`：按 §1.4 K2/K3；title/hint 格式沿用现网（`基础信息缺 N 项` + 前 2 项名等）。
- `_rule_r4/_rule_r6/_rule_r7/_rule_r10`：常量读取改为 `rules.archive_overdue_days` 等注入，逻辑不变。
- `build_project_todos(facts, today, rules)`：R8 分支改为 `drafts += _rule_r8(...)`（返回 list）。

Pydantic 校验用 model_validator（键集合校验给出可读报错，不用 Literal 动态键）。

### 2.5 存储与并发

- upsert 沿用 `services/growth_center/admin_flow.py` 模式：`with_for_update` 查行 → 无行则 add + flush，IntegrityError 时 rollback 后加锁重查更新（两管理员并发保存不 500）。
- 读路径：`json.loads` 失败或类型不符 → 逐字段回退默认（容忍手工改库造成的脏数据）。
- `updated_by_name`：join users 取 nickname→username 回退（与其他 ManagerBrief 同口径）。

## 六、增量口径 K11：交付倒计时阈值入配置弹窗（2026-10-02 追加）

**背景**：装修详情页 KPI 卡「交付倒计时」（`project-detail/views/renovation/kpi.tsx`）三处阈值写死：交付周期 65 天（交房日 + 65 = 交付截止）、剩余 <10 天红色脉冲、≤30 天橙色。业务要求与规则阈值一并开放配置。

| 键 | 默认 | 语义 | 弹窗位置 |
|---|---|---|---|
| `delivery_total_days` | 65 | 交付倒计时 = 约定交房日 + N 天（截止日） | 分组二「宽限与提醒窗口」 |
| `delivery_near_days` | 30 | 剩余 ≤ N 天橙色提示 | 同上 |
| `delivery_urgent_days` | 10 | 剩余 < N 天红色脉冲（判断优先于橙色） | 同上 |

- 消费方为**详情页 KPI 展示**，不参与看板规则引擎；配置存储/接口/权限与既有完全同构（`_merge_with_defaults` 按 dataclass 字段遍历自动兼容）。
- kpi.tsx（客户端组件）挂载时 `client.GET /todo-board/config`，失败/未保存回退代码内默认 65/30/10；红橙配反不强制校验（红色判断在前，desc 文案已说明优先级）。
- 「委托倒计时」（selling 视图）基于项目字段 `signing_period`/`extension_period`，非写死，**不纳入**本弹窗。
- 弹窗分组二 6→9 行，步进器 12→15 个；实现步骤同 §五（后端→gen-api→前端→E2E）。
