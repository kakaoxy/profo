海报上的房源清单

在 600×960 综合海报中新增已选房源文字清单：每行「商圈 / 几室 / 楼层 / 价格」，最多 5 行，行序与图片拼版一致；超 5 套由提示条承接。三个方案均保持既有品牌骨架（暖光晕标题区 / 拼版图 / 右下角小程序码）不变，仅重排纵向预算。

区块 1

三方案对比

示例场景与旧稿一致：按选 6 套绘制，清单显示前 5 条 + 溢出提示条；≤5 套时行数 = 套数且不显示提示条。示例数据为理想格式（商圈字段需后端补充，见区块 3）。

区块 3

每行文案的字段映射与数据依赖

目标格式 商圈/几室/楼层/价格。逐套字段由页面层从 PropertySheetItemResponse 格式化后传给布局纯函数，布局层不接触网络数据。

字段映射

四段拼接，分隔符「/」以 Dove 色弱化；价格段 Rust 500 字重收尾（方案 B 为中点分组 + 价格右对齐）。
段数据来源格式化规则示例
商圈 Community.business_circle（经后端补充进 PropertySheetItemResponse） 原样展示；缺失时降级小区名 community_name 徐家汇商圈
几室 layout（如「三室两厅」） 取首个居室词转数字 +「室」；解析失败整段省略 2室
楼层 floor_info（如「15/28层」） 取所在层转「N F」；无「/」时原样展示 3F
价格 total_price（万元，number） 整数省小数、最多 1 位（与落地页 formatPrice 口径一致）+「万」 248万
⚠️ 数据依赖（实现前置条件）：商圈 business_circle 存于小区表 Community，当前房源单链路 PropertySheetService.get_sheet_detail 只冗余了 community_name，未返回商圈。需后端补 JOIN Community 并在 PropertySheetItemResponse 增加字段（跑 pnpm gen-api 同步类型）；字段缺失期间前端按「降级为小区名」渲染，布局层无需感知。

canvas 实现要点

改动集中在布局纯函数与绘制器，套数自适应逻辑已有单测覆盖，扩展成本低。
property-sheet-poster.ts：buildSheetPosterLayout 新增入参 listings（逐套格式化后的展示字段数组）；新增 SheetPosterListing / SheetPosterList 接口（行段文本、价格、序号、行坐标 y = 510 + i × 33），行数 = min(count, 5)。
提示条触发阈值由 count > 3 改为 count > 5，文案改为「已精选 N 套 · 更多好房 扫码查看」，高度 44→40、y=690。
1~2 套场景：清单行数随套数减少，拼版图高度按剩余空间放宽（布局函数内按同一下边距回算）。
property-sheet-poster-render.ts：新增清单/序号 chip/图片角标落笔；发丝线 1px rgba(23,25,28,0.07)，价格 500 字重；方案 C 需在拼版图左上角绘角标（仅前 3 张）。
单测 property-sheet-poster.test.ts：行数截断（5/6/10 套）、坐标边界、无商圈降级文案、阈值翻转（4、5、6 套）。
文案格式化放页面层 pages/property-sheet/detail/index.ts（layout→几室、floor_info→NF、价格取整），保持纯函数不解析业务字符串。
