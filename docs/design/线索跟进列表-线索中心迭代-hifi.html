线索列表增量迭代：把「跟进」搬进表格

原需求是在线索中心新增一个「线索跟进列表」入口，评估后确认与现有列表页功能重复——不新增路由、不动侧边栏， 直接在现有列表上做三处增量：评估价前移并补评估单价、创建/更新时间合并为一行两行叠放、 状态与录入人之间插入「跟进结论 / 最后一条跟进内容」。一行仍是一个线索，两列取该线索最近一次跟进记录。

①评估价前移 + 评估单价

价格读作一组，而不是两处

评估价从「录入人之后」移到业主报价右侧，两列同结构、同右对齐、同单位行； 评估列下方补 评估价 ÷ 面积 的单价（万/㎡，保留 2 位），与业主单价同口径可比。

  • 单价为派生值，后端不新增列，前端按面积实时计算。
  • 面积缺失或评估价为空时，单价位留空，主值显示 —。
②创建 / 更新合并

一个单元格，两行时间

两列合并为「创建 / 更新」，上下两行叠放，行首带 10.5px 灰标签；省下的 100px 给「最后一条跟进内容」。

  • 当年内显示 MM-DD，跨年显示 YYYY-MM-DD。
  • title 恒为完整时间，鼠标悬停可读。
③跟进结论 + 最后一条跟进

把「谈没谈拢」变成可扫的一列

结论沿用现有三项互斥枚举（价格 / 合作模式 / 两者），未记录不伪造；内容取最近一条， 两行截断，附「时间 · 跟进人 · 方式」次级信息。

  • 无跟进：结论显示「未记录」灰胶囊，内容显示 —，不隐藏行。
  • 取数口径：max(followed_at)，同刻按 id 降序兜底。

跟进结论：同一暖色系的强度阶梯

价格未谈拢单轴分歧 · 杏色底 合作模式未谈拢单轴分歧 · 白底杏描边 价格与模式均未谈拢双轴阻塞 · 实底 未记录不含结论（存量或未填）

不引入新彩色：四态全部落在 Rust / Apricot 色系内，靠填充强度区分严重度， 与 DESIGN.md「唯一暖强调」一致。

最后一条跟进内容：两行 + 次级信息

主值正文 12.5px / 行高 1.55，-webkit-line-clamp: 2 截断，悬停 title 显示全文。

次行 09-28 · 李敏 · 电话，11px Dove；不在表内重复展示跟进次数（抽屉里已有）。

无跟进记录时主值显示 —，次行显示「尚未跟进」，保持行高稳定，不做骨架屏。

为什么一行一个线索，而不是一行一条跟进

跟进记录行的重复会把「106 条线索」变成「400+ 行」，状态、报价、评估价被迫重复或留空， 反而看不清「哪些线索卡在价格上」。一行一线索 + 最近一条，配合抽屉里的完整时间线， 既保留扫读效率，也不丢明细。

03

抽屉：新增两列的数据从哪来、回哪去

行点击行为保持现状（右侧 720px 抽屉）。本次只在抽屉的「跟进记录」页签做两件事：把结论作为可选标签随记录提交， 并在时间线每条记录上显示结论徽标——这样表里的两列既有来源，也能被就地更新。上方的列表点任意一行可打开它。

抽屉

跟进记录页签（720px）

演示数据：大宁金茂府 · 3 栋 1802 室

登记区：结论是「选填单选」，不是必填

沿用现有 FOLLOW_UP_CONCLUSIONS 三项互斥枚举 + 一个「清除」。 不选即表示「本次未出现分歧或未记录」，落库为 NULL——存量记录同样为 NULL， 前端统一渲染为「未记录」，不用默认值伪造结论。

提交成功后：抽屉时间线顶部插入新记录 → 表格该行的「跟进结论 / 最后一条跟进内容」即时刷新，无需重载页面。

时间线：结论徽标贴在内容首行

结论徽标复用列表同一套四态样式，位置在气泡内容上方一行（10px 字号）， 让「这条谈崩在价格还是模式」在滚动时间线时也能一眼看到。

评估事件与「线索初始录入」保持现状不动。

04

新增两列后仍然要求「表头骨架不跳动」。加载态用与真实行同高的骨架（表头保留），空态与错误态替换表体并给出下一步动作。 上方主方案顶部可即时切换这三态。

加载

骨架行，表头保留

6 行占位，行高与真实行一致（63px），宽度按列随机。

空

空：区分「无数据」与「筛不出来」

有筛选条件时给「清除筛选」，无任何线索时给「录入第一条线索」。

错误

错误：说清哪一步失败，可重试

保留页头与工具栏，只让表体进入错误态，避免整页白屏。

05

实现落点与待确认

按 AGENTS.md 的分层：取数口径在后端 Service，渲染与派生计算在前端。以下为建议改动清单，未改任何代码。

前端文件

admin/leads/_components/leads-table.tsx列顺序、合并时间列、两列新内容（主要改动）
admin/leads/_components/leads-grid.tsx卡片视图补一行跟进摘要，与表格口径一致

admin/leads/types.tsLead 增 latestFollowUp 字段（生成类型为准）
admin/leads/_components/drawer-parts/follow-up-timeline.tsx已在做结论标签，确认列表回写路径

后端契约（待确认）

列表接口目前只回 last_follow_up_at，没有结论与内容。现有 LeadQueryService.get_followup_stats() 已用单次 GROUP BY 聚合跟进，可扩展为「每个 lead_id 取最后一条记录的 conclusion / content / method / created_by」， 仍是一次查询、无 N+1。

  • 建议：在 _lead_to_list_item() 回填 latest_follow_up 嵌套对象（conclusion / content / method / followed_at / created_by_name）。
  • 若不想改契约：列表页 N+1 逐条拉 /leads/{id}/follow-ups——不推荐，20 行即 20 次请求。
  • 改动后必须 pnpm gen-api 重新生成类型，不手写。

取数口径（写进 Service 注释）

  • 最近一条 = ORDER BY followed_at DESC, id DESC 的第一条；不用 max(id) 代替时间。
  • 结论 = 该条记录的 conclusion，可为 NULL；不得回退到上一条有结论的记录（否则「最近一次谈了什么」会被历史结论污染）。
  • 内容截断在前端做（CSS clamp），后端回全文，避免 title 悬停内容不完整。

验收点（E2E 可覆盖）

  • 11 列顺序符合本稿，评估单价 = 评估价 ÷ 面积（保留 2 位）。
  • 无跟进线索的两列显示「未记录」+「—」，不报错、不塌行。
  • 在抽屉登记一条带结论的跟进后，返回列表该行两列立即更新。
  • 键盘：Tab 可达行、Enter 开抽屉、Esc 关闭并归还焦点。
  • 1280px 宽度下无需横向滚动即可看到「跟进结论」。
关于「入口」：本稿不新增导航项。跟进数据以「最近一条」直接进入列表， 完整跟进历史在行内抽屉的「跟进记录」页签（第三屏）——它的入口就是任意一行。 如果后续仍希望有一个只读的全局跟进流水（跨线索、按时间倒序）， 那是一个新的聚合视图，与本稿的列表演进不冲突，可另起一稿。
⚠️ 未覆盖 / 待你确认（3 项）： ① 跟进两列在 1024–1280px 是否可见（本稿 md 以下隐藏，见 01 节规格表脚注）； ② 后端是否同意扩展列表响应（否则只能退化为 N+1）； ③ 卡片视图是否同步补跟进摘要（本稿给了方案，可砍）。
规范自检： 颜色仅用 Ink / Fog / White / Dove / Graphite / Ash / Rust / Apricot / Sky，无新增色值； 字号落在 11–15px UI 区间，Signifier 仅用于页头 44px； 表格状态、结论、操作均有 title 或可见文字，不单靠颜色传达； 焦点环 outline: 2px solid var(--rust)； 移动端横向滚动而非压缩列；admin 后台按 DESIGN.md 仅浅色，未做暗色变体。
