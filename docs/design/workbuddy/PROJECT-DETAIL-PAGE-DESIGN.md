## 一、设计概述

### 1.1 项目背景

当前项目详情以**右侧抽屉(768px)**承载,信息密度低、多 Tab 切换频繁、无法平铺查看;本次重构将详情升级为 **Admin 后台独立页**(`/admin/projects/[projectId]`,受全局 sidebar 布局包裹),以长页滚动 + 分段导航承载项目全生命周期信息。

### 1.2 本次交付内容

- **高保真设计稿**(单文件 HTML,`project-detail-page-design.html`,约 93KB):覆盖 5 个阶段视图(签约 P0 主稿 + 装修/在售/已售/已下架示意),含 Header、阶段 Stepper、双栏主/侧布局、各阶段关键组件与交互 Dialog(交接确认/删除确认/图片预览/上架/结束项目/确认成交);v2 已按 Steep 风格对齐重绘(24px 圆角、Ink 胶囊 CTA、衬线 display 标题、签名三层阴影)。
- **本设计交付说明**(本文档):设计决策、页面结构、零功能影响对照、质量审查结论、待确认决策点、实现建议。

### 1.3 设计目标

| 目标 | 落地方式 |
|------|---------|
| 一流 UI/UX | shadcn/ui 组件结构保留 + Steep 视觉全面对齐(衬线 display 标题、24px 圆角、Ink 胶囊 CTA、签名三层阴影),信息密度与呼吸感平衡 |

### 2.2 关键设计决策

| # | 决策 | 说明 |
|---|------|------|
| 1 | **Stepper 阶段导航替代下拉** | 抽屉时代用下拉切换阶段,信息密度低;独立页顶部(Header 之下)改用横向 **Stepper 时间轴**(签约→装修→在售→已售→已下架),利用全宽页面让阶段一目了然;未解锁阶段 Lock 图标 + `aria-disabled` + 禁点击;已下架为终态节点 |
| 2 | **双栏 2fr/1fr 布局**(≥lg) | 左主栏 2/3 = 核心概览 + 项目信息 + 任务跟进;右栏 1/3 = 快捷操作 / 成员团队 / 文书附件 / 财务摘要;<lg 单栏按 DOM 顺序自动堆叠,无需重排 |
| 3 | **状态色冻结沿用 `status-colors.ts`** | 签约蓝 / 装修橙 / 在售绿 / 已售灰 / 已下架棕,徽标统一浅底 pill 样式(`bg-*/10 + text-* + border-*/20`,9999px 胶囊);Stepper 完成/当前态统一 Ink,不逐阶段变色,避免五色打架 |
| 4 | **金额红涨绿跌(中国习惯)** | 流入/盈利 = 红(`#ef4444`)、流出/亏损 = 绿(`#10b981`),全页一致禁止反转;一般指标(如带看环比)保持正绿负红与列表页一致 |
| 5 | **阶段 CTA 常驻** | 签约「交接确认」/ 装修「上架」/ 在售「确认成交 + 结束项目」作为该阶段唯一主 CTA 常驻(侧栏快捷操作或底部固定栏);主 CTA = **Ink 填充胶囊,每屏 ≤1**(全局唯一,编辑/删除等一律 outline / 文字链 / 危险描边) |

### 2.3 空间红利利用(抽屉 768px → 全宽双栏)

抽屉 768px 只能单栏滚动;独立页全宽(容器 `max-w-[1200px]`,对齐 v2 令牌 §4.1)释放出的横向空间直接转化为:

- **主/侧双栏**:核心信息(概览、项目信息、任务)与辅助信息(快捷操作、团队、文书附件、财务摘要)分栏并行,首屏信息量提升且层级清晰;
- **文书与附件由 Tab 升为独立分区**:签约视图原「文书与附件 Tab」上移至侧栏独立卡,6 类分组 + 状态 pill + 上传 dropzone 平铺可见,降低首屏滚动成本;
- **KPI/照片网格化**:指标卡 2–4 列、装修照片 4 列网格、附件分组 3 列,替代单栏长滚动;
- **任务与跟进新分区(预留)**:`ProjectFollowUp` 实体已定义但 UI 未呈现,本稿在主栏预留「任务与跟进」收口入口(空态示意),是否本期新增待产品确认(决策点 3)。
