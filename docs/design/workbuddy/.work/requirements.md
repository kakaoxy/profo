# profo 项目详情页重构 — 设计需求摘要

> 需求发现分析师(许明需)· 2025-08-16 · 交付物:高保真设计稿(HTML),**不改任何业务代码**

## 一、五要素

| 维度 | 结论 |
|------|------|
| 场景 Surface | Admin 后台 Web 独立页 `/admin/projects/[projectId]`,受全局 sidebar 布局包裹;单页多分区(长页滚动 + 分段导航) |
| 受众 Audience | 运营/销售操作用户:项目操盘、销售、装修跟进、财务查看;多角色权限;桌面为主,兼顾窄屏 |
| 调性 Tone | **以 shadcn/ui 浅色 admin 体系为基线**(必须与列表页/DataTable/全局组件一致),叠加 DESIGN.md「Steep」的编辑质感:暖灰画布、克制留白、大圆角卡片、单一暖色强调 |
| 品牌 Brand | 沿用现有 admin 体系;状态色统一走 `status-colors.ts`(签约蓝/装修橙/在售绿/已售灰/已下架棕);Steep 的 rust/apricot 仅作暖色点缀,不新增色系 |
| 规模 Scale | 单页多分区;桌面优先(≥1280),断点 lg/md/sm;阶段视图保留 Tab/区块组织,不强行平铺 |

## 二、现有功能完整清单(零影响基线)

**全局 Header(所有阶段)**:返回按钮 · 项目名+状态徽标(状态色) · 阶段切换下拉(未解锁 Lock 禁用) · 创建时间 · 编辑(先 refresh full 再开表单,装修视图隐藏) · 删除(AlertDialog 确认→返列表) · 图片预览 Dialog(共用)。

**签约/默认视图**:① 摘要卡=签约总价/净现金流(±色)/距交房(超时/临期色)/当前阶段(左边框)。② 项目信息 Tab:基础信息(小区/行政区异步/业务形式/面积/户型/朝向/地址复制)、代理协议(合同编号复制/签约·交房日期/签约价/周期/顺延/顺延租金/委托期限/税费承担方/其他约定)、业主信息(多业主:电话·身份证脱敏+显隐+复制,银行卡脱敏+按需解密+复制,开户行,备注;兼容单业主)、公用事业户号、交易数据、备注。③ 文书与附件 Tab:文书签收(6 类分组、状态 pill 行内编辑、统一保存、新增/删除/初始化默认清单、归档后可上传附件);附件(6 类分组、预览/下载/删除、图片压缩上传+类型校验)。④ 交接确认(仅签约态):选交房日期→更新+流转 renovating→自动切装修视图。

**装修视图**:① KPI=交付倒计时(65 天)/当前阶段/总体进度/相册张数。② 装修合同表单:公司/对接负责人下拉/合同与实际起止/硬装·软装·定制柜·窗户·墙面·设计·拆除·垃圾·其他费+原因/费用汇总;行内编辑/保存/取消。③ 装修进度:拆除→设计→水电→木瓦→油漆→交付 6 子阶段时间轴;每阶段照片网格(缩略图/预览/下载原图/删除/批量下载/多选上传带进度与错误态)、标记完成(选日期)、admin 可改/清空完成日期。④ 上架:选上架日期+挂牌价→流转 selling→自动切在售。

**在售视图**:① 基础概览:挂牌价大卡+单价/小区/剩余天数倒计时/面积/挂牌日期/实际竣工(异步)+编辑实际竣工。② KPI=本周带看(环比)/出价(最高价)/面谈(最新)。③ 销售团队:渠道/讲房/谈判三角色自动保存(权限控制,只读 fallback)。④ 活动记录:带看/出价/面谈三 Tab,新增(日期/人名/金额/纪要)、删除。⑤ 底部固定栏:结束项目(→ended)+确认成交(成交日期+价格→sold→自动切已售)。

**已售视图**:Hero 指标(净利润/ROI/年化/资金占用+成交用时·委托期限)、财务生命周期(成交价/实收/实付+签约→开工→上架→售出 Stepper)、视觉旅程(按子阶段横向照片时间轴)、总结报告、编辑销售信息(成交价/日期/挂牌价/上架日期)、可回看前阶段。

**已下架视图**:项目名+徽标、基础信息卡、关键日期卡(挂牌/签约/委托期限)、删除按钮、不可恢复提示。

## 三、信息架构建议

- **Header**:sticky 面包屑+返回+项目名+阶段徽标+主操作(编辑/删除 或 该阶段 CTA)。
- **二级阶段导航**:横向 **Stepper 时间轴**(签约→装修→在售→已售→已下架)替代抽屉下拉,锁定未解锁阶段;sticky 于 header 下方,利用页面宽度红利让阶段一目了然。
- **主内容双栏(≥lg)**:左主栏=核心概览+该阶段任务/跟进/记录;右栏=成员团队/附件文书/财务摘要/快捷操作;`<lg` 单栏堆叠。抽屉 768px→全宽容器。
- **阶段专属 CTA 常驻**:交接/上架/成交作为主 CTA 置顶或底部 sticky 操作栏。
- **KPI/照片网格化**:3-4 列指标卡、照片瀑布流、文档分组网格,替代单栏滚动。

## 四、「任务」概念落点

系统无独立任务实体,任务类数据有三类:① 跟进记录 `ProjectFollowUp`(类型已定义但 **UI 未呈现**,预留待确认);② 活动记录 `sales_records`(在售阶段带看/出价/面谈);③ 装修子阶段待办(拆除→交付时间轴)。建议设计稿设「任务与跟进」分区统一收口,但保留各任务在原阶段的展示位置,避免重复。

## 五、关键决策点与假设

1. 阶段切换:建议 Stepper 时间轴(见三),需产品确认是否含已下架终态节点。
2. 状态色沿用 `status-colors.ts`,不新造色;Steep 暖色仅作点缀。
3. 返回路径:列表筛选态由 URL query(status/page/business_form)驱动,返回应 `router.back` 保留筛选。
4. 独立页已有全量数据,编辑前「先 refresh full 再开弹窗」逻辑可省略(待确认)。
5. 文书/附件在签约阶段体积大,建议升为独立分区而非 Tab,降低首屏高度。
6. 列表「导出」未实现;详情页是否加导出/打印待确认。

## 六、待确认问题清单(按优先级)

1. **阶段导航形态**:横向 Stepper 时间轴 vs 保持下拉/Tabs?(决定页面骨架,最高优先)
2. **双栏布局**:主内容+侧栏(≥lg)是否符合预期?侧栏放团队/附件/财务摘要/快捷操作哪些?
3. **「任务与跟进」是否本期新增**:跟进记录数据存在但无 UI,是否纳入独立页并规划入口?
4. **入口改造**:列表行点击由「开抽屉」改「跳详情页」,是否同时保留抽屉快捷预览?返回是否恢复筛选态?
5. **设计稿覆盖范围**:5 个阶段视图全部出稿,还是优先 签约/装修/在售?(建议全部)
