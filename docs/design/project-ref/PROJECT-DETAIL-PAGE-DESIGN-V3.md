## 一、迭代概述

### 1.1 需求背景

项目管理详情当前以**右侧抽屉(768px)**承载;虽已存在 `/admin/projects/[projectId]` 独立页雏形(为解除 PM-03/04/05 下游用例阻塞而建的极简适配,复用抽屉的 hooks/views),但存在明显短板:

- 列表主入口仍是**开抽屉**,独立页无入口、用户不可达;
- 页面雏形仅把抽屉内容平移到页面,Header 简单替换,未利用全宽空间做信息组织;
- 缺少独立页应有的**导航闭环**(面包屑/返回路径/深链接)、**状态页**(404/加载失败)、**任务与跟进**等功能分区;
- 视觉沿袭 shadcn 基线,与 DESIGN.md(Steep)编辑质感有差距。

本次 v3 在 v2 设计稿(已确认的 Stepper + 双栏 + 5 阶段视图方向)基础上迭代,补齐上述短板,形成**可进入实现排期**的高保真设计。

## 二、设计系统遵循(DESIGN.md / Steep,延续 v2 基线)

v2 已确认的视觉基线**不变**,v3 继续执行:

- **色彩**:Ink `#17191c` 主文字/主 CTA、Ash 次要、Graphite 三级、Dove 发丝描边;Rust `#5d2a1a` 暖强调;apricot/sky 双 wash 仅作数据卡底(每屏各 ≤1);**状态色 5 色冻结**(`status-colors.ts`:签约蓝/装修橙/在售绿/已售灰/已下架棕,浅底 pill 徽标,文字加深一档保 AA)。
- **排版**:衬线 display(Noto Serif SC / Songti SC)**仅页面级 3 类**——项目名 26px、大分区标题 22px、Hero 醒目数字 32–38px;其余一律无衬线,微字重 450/480/500 代替 bold;数字统一 `tabular-nums`。
- **圆角**:内容卡 24px、图片 12px、输入 16px、按钮/徽标/头像 9999px、内嵌 chip ≥12px,全页无锐角。
- **按钮**:主 CTA = Ink 填充胶囊,**每屏 ≤1**(弹层模态主操作叠加可接受);次级一律 outline / 文字链 / 危险描边。
- **阴影**:签名三层阴影(1px 环 + 20/25px 主落影 + 8/10px 微落影)为卡片默认;浮层 = 签名三层 + 40px 扩展。
- **冻结项**:金额红涨绿跌(正红负绿)口径、状态徽标样式、页面结构/功能/交互断点策略、可访问性骨架——全部不动。

v3 相比 v2 的**视觉修正**(沿用 v2 遗留 P2 清单):

| 项 | v2 | v3 |
|----|----|----|
| 照片/图片占位 | 彩色线性渐变 | **平色 Fog 占位 + 图标**,灰阶克制 |
| 金额字体 | 部分等宽 `mono` | 统一 **sans + `tabular-nums`**(仅编号/合同号等代码类保留等宽) |
| 浮层阴影 | 普通阴影 | **签名三层 + 40px 扩展**(`--shadow-dialog`) |
| KPI 卡内部层级 | 全卡签名阴影 | 概览网格内 KPI 降为**平卡 + 1px 细描边**,主卡保留签名阴影,层级更清晰 |

## 三、页面结构总览

```
/admin/projects/{projectId}(独立页,受全局 admin sidebar 包裹)
├── Header(sticky,全阶段共用)
│   ├── 返回按钮(router.back,保留来源页筛选态)
│   ├── 面包屑:项目管理(可点) / 项目名 + 状态徽标
│   ├── meta:创建时间
│   └── 编辑(装修视图隐藏,与现有行为一致)/ 删除(AlertDialog → 返列表)
├── 阶段 Stepper(sticky,Header 之下,全阶段共用)
│   └── 签约 → 装修 → 在售 → 已售 → 已下架(完成/当前态 Ink;未解锁 Lock + aria-disabled + 提示)
├── 内容区(容器 max-w-1200px;≥lg 双栏 2fr/1fr,<lg 单栏堆叠)
│   ├── 签约视图(主栏:核心概览 4KPI / 项目信息 6 锚点分区 / 任务与跟进 ← v3 新增
│   │            侧栏:快捷操作 / 成员与团队 / 文书与附件 / 财务摘要 / 竞品监控入口 ← v3 新增)
│   ├── 装修视图(主栏:装修 KPI 4 网格 / 装修合同行内编辑 / 进度 6 子阶段时间轴 / 阶段照片网格
│   │            侧栏:快捷操作(上架)/ 成员与团队 / 竞品监控入口)
│   ├── 在售视图(主栏:挂牌价大卡 / KPI 3 网格 / 活动记录三 Tab
│   │            侧栏:销售团队 / 竞品监控入口 + 底部固定操作栏:结束项目 / 确认成交)
│   ├── 已售视图(主栏:Hero 指标 / 财务金额 KPI / 财务生命周期 / 视觉旅程+总结报告
│   │            侧栏:结案信息)
│   ├── 已下架视图(基础信息 / 关键日期 / 不可恢复提示 / 删除)
│   └── 状态页:加载骨架 / 404(项目不存在)/ 错误重试(加载失败)
└── 交互浮层:交接确认 / 新建跟进(v3) / 删除 / 图片预览 / 上架 / 结束项目 / 确认成交
```

**v3 关键结构决策:5 个阶段视图统一骨架**(Header + Stepper + 双栏容器),阶段间仅内容卡不同——信息层级一致、切换无跳变;v2 中装修/在售/已售/已下架为「紧凑示意」,本次全部补齐为与签约视图同等保真。

## 六、交互反馈覆盖矩阵

| 场景 | 状态 | 设计稿表现 |
|------|------|-----------|
| 进入页面/切换阶段 | 加载中 | 全局骨架屏(Header 保留,内容区 4 KPI + 2 卡占位,脉冲动画) |
| 项目不存在/无权限/已删除 | 404 | 居中状态卡:图标 + 「项目不存在或已被删除」+ 返回列表(主 CTA)+ 查看示例项目;对应 `notFound()` |
| 接口/网络失败 | 错误 | 状态卡:「加载失败,请重试」+ 重新加载(主 CTA)+ 返回列表;对应 refresh 失败 + toast.error |
| 表单提交(交接/上架/成交/跟进) | 校验失败 | 输入框 error 描边 + 红色错误提示行(aria 关联);成功 → toast + 阶段自动流转 |
| 上传照片 | 进行/失败/成功 | 上传 tile 带进度(实现阶段);失败 tile 红色描边 + 重试,重试成功转绿(演示可交互) |
| 敏感信息(业主电话/身份证/银行卡) | 脱敏 | 星号掩码 + 眼睛显隐 + 复制(银行卡需按需解密,提示语保留) |
| 各分区无数据 | 空态 | 任务/跟进筛选无结果空态;活动记录、照片等沿用组件自身空态 |
| 无权限角色 | 只读 | 销售团队卡只读 fallback 标注(灰色 + 不可编辑,保留现有) |
| 阶段未解锁 | 禁用 | Lock 图标 + aria-disabled + title 提示 + 点击 toast 说明,消除「为什么点不动」歧义 |
| 删除/结束项目 | 二次确认 | AlertDialog 危险操作(icon + 影响说明 + 取消/确认),确认按钮 loading |
| 操作成功/失败 | Toast | Ink 深色 toast(失败红),自动消失,`role="status"` |
