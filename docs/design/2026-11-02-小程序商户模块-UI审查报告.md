# 小程序商户模块 UI 审查报告（unslop critique）

- **日期**：2026-11-02
- **范围**：`miniapp/pages/merchant/**`，共 11 个页面（home / store-create / store-detail / visit-create / broker / broker-store-create / agreement-list / agreement-create / agreement-detail / agreement-sign / merchant-sign）
- **唯一设计契约**：`DESIGN.md`（Steep — Style Reference，light theme）
- **审查方式**：静态审查 WXML + WXSS + TS（共 2,257 行 WXSS / 1,225 行 WXML / 3,459 行 TS）。未启动微信开发者工具做真机截图，运行时项在文末单列（⚠️）。
- **结论**：**重度 AI 味（heavy slop）**，但问题不在单页，而在「每页各写一份 CSS」的系统性失序。11 个页面各自看都成立，放在一起不像同一个产品。

---

## 0. 一句话诊断

模块里 9 个页面把「页面标题」装进一张 24px 圆角白卡，把每个动作做成胶囊，用 600 字重的无衬线字当标题，用暖/冷两色随意点缀状态——**结果是一堵卡片墙 + 一锅胶囊 + 一套没有阶梯的标题**。DESIGN.md 里真正值钱的三件事（Signifier 的编辑感、Rust 作为唯一标点、暖/冷数据面的「一个亮点」）在商户模块里**一件都没发生**。

| 维度 | 结果 |
|---|---|
| 颜色越界 | 2 处饱和绿、1 处饱和蓝、1 处 token 漂移、1 处正文用 Dove |
| 字号 | 16 种字号，其中 12 种不在 DESIGN 比例上；25 处 `font-weight: 600` |
| 组件一致性 | `.state` 复制 8 次、`.input` 9 次、`.mini-btn` 8 次、`.modal` 6 次；同一「次要按钮」5 种高度 |
| 层级 | 4 种页面标题尺寸（38/40/44/48rpx）；`agreement/detail` 同屏 2 个 Ink 主按钮 |
| 亮点 | 0 个数据可视化、0 个 Apricot/Sky 数据面、0 个只有本产品才有的细节 |
| 触控 | 0 个 `hover-class`，0 个按压态；多个可点目标 < 44px |

## 1. 审查方法与边界

按 unslop 的九轮顺序逐层过：间距 → 颜色 → 图标 → 文案 → 字体 → 布局 → 细节 → 视觉 → 动效。每一轮都扫全部 11 页，不做单页特判。

**判定优先级**：DESIGN.md 明文条款 > DESIGN.md 组件范式 > unslop 通用工艺规则。凡 DESIGN.md 未定义的移动端事项，一律标 ⚠️ 而不是擅自判违规（见第 8 节）。

**本次不做**：不改代码、不重画界面、不生成 story 视频。产出只有本报告。

## 2. 设计方向（供后续修复参考，本次不落地）

这五条从 DESIGN.md + 产品本身推导，用来判断「改完之后是不是这个产品」，不是新发明一套风格。

- **Product**：给门店拓展员工与经纪人的现场工作台——找店、拜访、建档、签约、留痕。
- **Character**：克制、可核验、带一点纸质档案的温度。
- **World**：城市街区 + 纸质档案。门店档案卡、拜访回执、合同签章，都是纸与印的世界，正好接住 DESIGN 的 Rust 与暖灰。
- **Moments**：① 门店档案首屏（店名 + 一枚 Rust「火漆印」状态）；② 拜访时间线（一条连续的竖向轨迹 + 距离异常标记）；③ 签署页的签名画布（唯一允许大面积留白的地方）。
- **Signature**：Rust 只做「印」——门店状态印、签署完成印。它出现的地方就是需要被记住的地方，别处一律墨色。

> 现状与该方向的差距：Rust 现在被当成「链接色 + 状态色 + 选中底色 + 警告色」四处使用，印章没有，纸感没有。

## 3. P0 · 系统性问题

### P0-1　没有共享样式层，同一组件被复制 8–9 次

**证据**：`.state` 出现 8 次、`.input` 9 次、`.mini-btn` 8 次、`.modal` 6 次、`.hero` 9 次、`.footer` 4 次、`.chip--tap` 3 次。11 个页面共 2,257 行 WXSS，其中约 500 行是同一段代码的近似复制。

**表现**：同一个「次要按钮」在 6 个文件里长成 5 个高度：

| 位置 | 高度 | 字号 | 内边距 |
|---|---|---|---|
| `home/index.wxss:130-143` `.visit-btn` | 60rpx / 30px | 24rpx / 12px | 0 22rpx |
| `visit/create/index.wxss:119-129` `.mini-btn` | 72rpx / 36px | 26rpx / 13px | 0 28rpx |
| `agreement/merchant-sign/index.wxss:136-147` | 76rpx / 38px | 26rpx / 13px | 0 28rpx |
| `broker/index.wxss:145-155`、`store/create:98-110`、`store/detail:299-309` 等 | 80rpx / 40px | 27–28rpx | 0 / 0 32rpx |
| `broker/store-create/index.wxss:75-85` | 88rpx / 44px | 27rpx / 13.5px | 0 32rpx |

**违反**：DESIGN「same thing, same size」；按钮组件只定义了 9999px 圆角 + Ink 填充，未定义次要按钮，但代码没有收敛出一个统一实现。

**影响**：这是所有其它问题的根因。每一处 ±2–4rpx 的漂移都来自「复制上一页再微调」。

**建议**：把 `.state / .input / .mini-btn / .modal / .footer / .hero` 收敛进 `styles/merchant-theme.wxss`（或新增 `merchant-ui.wxss`），页面只保留各自独有的布局。先做这一步，后面 90% 的视觉不一致会自动消失。

### P0-2　字号体系失控：16 种字号，12 种不在比例上

**证据**（rpx → px → DESIGN 对应）：

| 字号 | px | DESIGN token |
|---|---|---|
| 20 | 10 | — |
| 22 | 11 | — |
| 23 | 11.5 | — |
| 24 | 12 | — |
| 25 | 12.5 | — |
| 26 | 13 | — |
| 27 | 13.5 | — |
| 28 | 14 | caption ✓ |
| 30 | 15 | — |
| 32 | 16 | body ✓ |
| 34 | 17 | — |
| 36 | 18 | body-lg ✓ |
| 38 | 19 | — |
| 40 | 20 | — |
| 44 | 22 | subheading ✓ |
| 48 | 24 | — |

DESIGN 的 26px（`heading-sm`，52rpx）**一次都没用**。而 25rpx（12.5px）、23rpx（11.5px）这种半像素字号会直接落成非整数像素，中文在 2x/3x 屏上发虚。

**违反**：DESIGN「Type Scale」八档 + 规则「A few sizes from a scale」。

**影响**：字号越密，层级越不存在。用户看到的不是「标题 > 正文 > 注释」，而是「一堆差不多大的字」。

**建议**：商户模块只允许 `28 / 32 / 36 / 44 / 52rpx` 五档；删除 20/22/23/24/25/26/27/30/34/38/40/48。正文用 32rpx（16px），说明文字最低 28rpx（14px）。

### P0-3　字重全线 600，DESIGN 的上限是 500

**证据**：`font-weight: 600` 共 **25 处**（home 2、broker 4、store/create 3、store/detail 3、visit 2、agreement 系列 10、broker/store-create 1）。

**违反**：DESIGN「Typography — Weights」只定义 400 / 430 / 450 / 480 / 500；Typographic Voice 原文：「**Never bold Sohne; use weight 480 or 500 instead**」。代码里没有一处 480。

**表现**：标题、卡片标题、列表主标题、弹层标题全部 600 —— 层级不是靠大小和颜色，而是靠「全都加粗一点」。这正是 AI 生成的默认手感。

**建议**：标题统一 500，正文 400。⚠️ 中文环境无法使用 430/450/480 微字重（PingFang/思源不支持），须在 DESIGN 里补一条移动端降级规则，否则这条契约在 Web 与小程序之间永远对不上（见第 8 节）。

### P0-4　「一屏一个 Ink 填充」被破坏

**证据**：

| 页面 | Ink 填充数 | 位置 |
|---|---|---|
| `agreement/detail` | **2** | `wxml:32`「分享给商户签署」+ `wxml:35`「去签署」 |
| `agreement/list` | **2** | `wxss:43-46` 激活 tab 用 Ink 填充 + `wxml:52` 页脚 CTA |
| `broker` | **2** | `wxml:82`「绑定已有门店」+ 任一弹层主按钮 |
| `broker/store-create`、`store/create`、`agreement/create` | **2** | 页面/页脚 CTA + 弹层 `mini-btn--primary` |

**违反**：DESIGN Do's「one per viewport」；Don'ts「**Don't use the dark Ink fill for anything other than the primary CTA and dark text**」「**Don't exceed one filled button per screen; secondary actions are text links, not ghost buttons**」。

**最典型**：`agreement/list` 的激活 tab 是一枚 Ink 胶囊（`wxss:43-46`）。它既不是 CTA，也不是深色文字，纯粹是「选中的 tab 看着更重」，却和页脚真正的 CTA 抢同一块黑色。DESIGN 对激活态的原文是「#ffffff 背景 + 12px 圆角」，不是黑色填充。

**建议**：激活态改为白面 + 1rpx hairline 或 Rust 文字，让黑色只留给每屏唯一的那个动作。

### P0-5　9 个页面以一张白卡开场，形成卡片墙

**证据**：`broker:9-16`、`store/detail:9-16`、`agreement/list:9-16`、`agreement/create:8-15`、`agreement/detail:8-15`、`agreement/sign:8-15`、`merchant-sign:8-15`、`broker/store-create:8-15`、`visit/create:9-16` 的 `.hero / .store-head` 全是「白底 + `--merchant-shadow` + 48rpx 圆角 + 40rpx 内边距」。其中 7 份装的是页面标题（`home` 与 `store/create` 是唯一把标题留在画布上的两个页面），另 2 份装的是门店档案头。

**表现**：页面一打开，第一眼是一张和内容卡完全同级、同样阴影的「标题卡」，然后下面再堆 3–6 张一样的卡。深度语言归一 → 全部卡片浮在同一层 → 反而没有深度。

**违反**：DESIGN「Product UI stays on white/Fog canvas」「Reserve the warm gradient glow for hero contexts only」「delineation happens through surface tints and radii」。标题属于页面 chrome，不该穿内容卡的外套。

**建议**：
- 删掉标题卡，页面标题回到 Fog 画布上（`home` 已经是正确做法）。
- 卡片阴影只给真正需要抬升的内容（或统一降到单层 hairline + 8rpx 柔和投影），不要 10 张卡各挂一套 20px 双层投影。

### P0-6　状态色语义自相矛盾，同一个色表示四种含义

**证据**：

| 页面 | 逻辑 | 后果 |
|---|---|---|
| `home/index.wxml:57` | 待审核 → apricot，其余 → fog | apricot = 待审核 |
| `store/detail/index.wxml:16` | 待审核 → apricot，其余 → **sky** | sky = 一切非待审核（含未合作） |
| `agreement/list/index.wxml:40` | 待签署 → apricot，其余 → fog | apricot = 待签署 |
| `agreement/detail/index.wxml:15` | 已签署 → **sky**，其余 → apricot | apricot = 待签署 **∪ 已作废 ∪ 已过期** |
| `broker/index.wxml:111` | 推荐状态 → 恒为 apricot | apricot = 任何线索状态 |

同一个 Apricot 同时表示「需要处理」「已完成」「已作废」「已过期」；Sky 同时表示「正常合作」和「已签署」。

**违反**：DESIGN「palette treats color as punctuation」「Semantic colors only carry meaning」；Don'ts「the only chromatic voices are Rust and the two pastel washes」—— 现在两片洗色被当成了红绿灯。

**建议**：定一张状态映射表并全模块复用：
- **待处理**（待审核 / 待签署）→ Apricot 底 + Rust 字
- **已落定**（正常 / 已合作 / 已签署）→ Fog 底 + Graphite 字，**不给色相**
- **异常**（已作废 / 已过期 / 距离异常）→ 白底 + Rust 字 + hairline
- Sky Wash 只留给「冷色数据面」，本模块当前无数据面 → 暂停使用。

### P0-7　固定底栏遮住内容（安全区未计入）

**证据**：`.footer` 高度 = `20rpx` 上内边距 + `96rpx` 按钮 + `20rpx` 下内边距 = **136rpx = 68px**，再加 `env(safe-area-inset-bottom)`（iPhone 刘海屏 34px）≈ **102px**。

| 页面 | 预留底部 | 差额 |
|---|---|---|
| `home/index.wxss:5` | 180rpx = 90px | **少 12px** |
| `agreement/list/index.wxss:5` | 160rpx = 80px | **少 22px** |
| `store/create/index.wxss:5` | 200rpx = 100px | 少 2px |
| `visit/create/index.wxss:5` | 200rpx = 100px | 少 2px |

**影响**：在刘海屏上，最后一张卡片 / 最后一条记录会被 CTA 压住，且遮罩是渐变（`home:153`），内容会从半透明底栏里透出来。

**建议**：统一 `padding-bottom: calc(136rpx + env(safe-area-inset-bottom) + 24rpx)`，或把底栏改为不透明 Fog + 顶部 1rpx hairline。

## 8. DESIGN.md 未覆盖 / 需要裁决（⚠️ 不确定）

以下不是代码单方面的问题，是契约本身缺项，必须由设计负责人裁决后写回 DESIGN.md，否则每轮实现都会重新猜一次。

1. **移动端比例尺缺失**：DESIGN 的 type scale 从 14px 直接跳到 22 / 26 / 44 / 64 / 90，且明令「Signifier 不得低于 40px」。小程序页面标题只有 20–24px 的空间 → 现有契约下**移动端没有合法的标题字体与字号**。建议补一张 375px 宽度的移动端 ramp。
2. **中文字体替代未定义**：DESIGN 给的替代（Inter / Untitled Sans / General Sans）都是拉丁字族；中文需 Noto Sans SC / 思源黑体。建议明确「Web 用 Sohne，小程序用系统中文黑体，标题不降级为衬线」。
3. **430 / 450 / 480 微字重不可用**：DESIGN 把这套微字重当作「最可辨识的层级手法」，但 iOS/Android 中文字体没有这些字重。需要一条降级规则（如「中文环境用 400/500，靠字号与颜色分层」），否则 P0-3 无解。
4. **Dove / Graphite 的对比度**：DESIGN 定义 Graphite #777b86 白底约 4.27:1、Dove #a3a6af 约 2.4:1，均低于正文 4.5:1。代码已私自加深 Graphite → 双源。建议直接在 DESIGN 修正 token 值并注明「Dove 仅装饰」。
5. **移动端组件缺席**：DESIGN 只有 Web 的 Top Nav / Sidebar / Dashboard Card，没有小程序需要的：页面头、列表行、底部固定操作栏、tab、chip 状态、居中弹层/半屏、空/载/错三态、安全区。商户模块的所有漂移都发生在这块契约真空里。
6. **状态色语义未定义**：DESIGN 只给了「语义色要克制」，没有给待审核/已签署/已作废的映射。P0-6 的根因在此。
7. **触控与可访问性未定义**：无最小点击区（44px）、无按压态、无 `aria-role` 约定。目前 11 页 0 个 `hover-class` 不算违规，只是没人规定。
