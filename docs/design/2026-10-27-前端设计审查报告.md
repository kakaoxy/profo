## 一、结论摘要

上一版报告因无法渲染，将“当前渲染视觉一致性”判为 Inconclusive。本次前后端已启动，报告结论已替换为真实渲染证据：

- **7 类阻断问题全部在浏览器中复现或新增确认**：表单控件无可编程标签、图表维度色板失控、`rounded-pill` 计算半径为 0、可点击行/卡片不可键盘操作、Dialog/Sheet 缺少名称与焦点管理、**全局正文字体令牌失效（新）**、**67 个图标按钮无可访问名称（新）**。
- **实测推翻或修正了多条旧结论，关键的 4 条是**：登录页主标题并非橙色；C 端首页桌面端并未切换 Signifier；`/profile` 标签问题无法用后台账号复验；`/admin/recruit`、`/admin/growth-center` 的 404 是分组目录特性，不是缺陷。
- **新发现 2 类系统性问题**：全站正文实际渲染为 `ui-sans-serif`（Inter 从未加载），以及用户管理页 375px 下 Tab 文案按单字竖排（112×108px）。
- **量化证据**：18 个后台路由 + 3 个 C 端路由 + 登录页完成 axe 扫描；后台累计 **1,228 个对比度告警节点**、**67 个无名按钮节点**；15 组响应式截图均无横向溢出，但字体/令牌/移动端局部布局仍有确定性缺陷。

本次仍不对“与 HiFi 的像素级还原”下结论：HiFi 是可交互 HTML 原型而非 Figma/批准基线，且页面含动态业务数据，无法建立稳定的逐像素 diff。视觉一致性只依据可度量的字体、圆角、色板、版心、响应式行为判定。

## 三、阻断项（Blockers）

### B-01 核心表单控件缺少可编程标签

- **复核状态**：已复现（审计日志、录入线索弹窗）；新发现（C 端首页）；未验证（`/profile`）
- **实测证据**：
  - `/admin/audit-logs`：axe `label` **2**（两个日期输入）；5 个视觉标签 `操作人/动作/对象/开始日期/结束日期` 的 `htmlFor` 全为 `null`，对应 5 个控件关联标签数均为 0。3 个筛选 combobox 没有 `aria-label`/`aria-labelledby`，可见文本只是当前值（“全部人员/全部动作/全部对象”），按 ARIA 名称计算不构成可访问名称；axe `button-name` 另有 4 个节点。
  - `/admin/leads` 录入线索弹窗：10 个 `<label>` 全部 `htmlFor=null` 且未包裹控件；15 个控件中 0 个有关联标签；axe `label` 2 + `select-name` 1。视觉标签为 10px `font-black uppercase tracking-widest`，输入框仅靠 placeholder 提示。
  - `/` C 端首页：5 个输入框（小区搜索、最低/最高总价、最小/最大面积）均无 `id`、无 `label`、无 `aria-label`，只有 placeholder；placeholder 一旦输入即消失，用户失去字段说明。
  - 正例：`/admin/leads` 表格行的 `aria-label`、登录页 `Label htmlFor` + `Input id` 均正确，说明项目内已有可复用范式。
- **期望**：每个控件都有可编程名称（`htmlFor`+`id`、包裹式 `<label>` 或 `aria-label`）。
- **影响**：审计日志的日期输入与筛选组合框会被读屏播报为无名控件；C 端字段仅靠 placeholder，输入后即失去说明。管理员无法确认字段含义，违反 WCAG 1.3.1、3.3.2、4.1.2。录入线索与筛选是高频主路径。
- **修复建议**：为上述控件补 `id`/`htmlFor`；C 端价格/面积用可见标签或 `aria-label`；把表单行封装为 `components/custom/` 组件，避免每页重写。
- **验证**：axe `label`、`select-name` 为 0；Tab 到每个控件时读屏播报字段名；输入后标签仍可见。

### B-02 图表维度色板违反 Steep 契约

- **复核状态**：已复现
- **实测证据**：
  - 市场报告默认视图的 SVG 颜色为 `#5d2a1a`（Rust）与 `#4a90e2`，符合契约允许的冷色补充。
  - 点击“户型”维度后，同一图表出现 `#ef4444`（红）、`#3b82f6`（蓝）、`#f59e0b`（琥珀）、`#10b981`（翠绿）；“楼层”维度出现 `#ef4444`。
  - 源码：`frontend/src/app/(main)/admin/reports/market/_components/comparison-chart-renderer.tsx:41-49` 的 `SERIES_COLOR_PALETTE` 含靛/翠绿/琥珀/红/紫/青/粉；`trend-chart-renderer.tsx:21-30` 的 `DIM_COLOR_PALETTE` 含 8 个饱和色。
- **期望**：UI chrome 的唯一彩色声音是 Rust 与两种 pastel wash；数据可视化只允许 Rust + 契约蓝 `#4a90e2`，不得引入彩虹色板。
- **影响**：市场报告面向管理层，切换维度后品牌观感回退到默认图表库；红/绿会与“金额涨跌”语义冲突，增加误读。
- **修复建议**：系列色映射到 Rust / Apricot / Sky 梯度；用实线/虚线/点线、标记形状、透明度区分多系列；确需冷色时仅用 `#4a90e2`。色板集中到 token 文件。
- **验证**：任意维度切换后 SVG 中不再出现上述 hex；axe/视觉截图复核。

### B-03 `rounded-pill` 未定义，胶囊按钮静默变成直角

- **复核状态**：已复现
- **实测证据**：
  - `/admin/notifications` 三个筛选按钮（`全部/未读/线索`）类名含 `rounded-pill`，计算 `border-radius` 全为 **0px**，高度 32px；同页 8 个按钮半径为 0px。
  - `/admin` Tab、`/admin/settings/workbench` 的 `rounded-pill` 元素同样为 0px；`getComputedStyle(document.documentElement).getPropertyValue('--radius-pill')` 为空。
  - 源码 `grep` 命中 15 处；`globals.css` 无 `--radius-pill`，编译产物中 `rounded-pill` 出现 0 次，而 `text-dove`、`rounded-cards`、`shadow-steep` 正常生成。
- **期望**：DESIGN.md 规定按钮/标签圆角 9999px。
- **影响**：消息中心筛选 tab、创建按钮等必然渲染为直角；类名不报错，后续开发者会继续复制。
- **修复建议**：15 处替换为 `rounded-full`，或在 `@theme` 新增 `--radius-pill: 9999px`；加 lint 禁止未定义的自定义 `rounded-*`。
- **验证**：编译产物可检索到选择器；截图确认胶囊形态。

### B-05 Dialog / Sheet 缺少可访问名称与焦点管理

- **复核状态**：已复现（两处）
- **实测证据**：
  - 待办详情 Sheet：`role="dialog"` 存在，但 `aria-label=null`、`aria-labelledby=null`、`SheetTitle` 节点数为 **0**；Radix 未在控制台输出缺失标题警告。
  - 录入线索弹窗：不是 Radix Dialog，而是自定义 `fixed inset-0 z-50` 遮罩。遮罩 `role=null`、`aria-modal=null`、`aria-label=null`、`labelledby=null`；连续 Tab 30 次后焦点逃逸到下层表格行（`inside=false`）；按 Esc 不关闭；`body` 滚动未锁定（`overflow: clip visible`）。
  - 弹窗内 axe：`button-name` 1、`label` 2、`select-name` 1、`color-contrast` 17。
  - 源码：`todo-detail-popup.tsx:112`、`todo-rules-config-popup.tsx:97` 使用 `SheetContent` 但未引入 `SheetTitle/SheetDescription`；`add-lead-modal.tsx` 在 `!isOpen` 时直接 `return null`，无 dialog 原语。
- **期望**：每个 dialog/sheet 有可访问名称与描述，焦点被约束在弹窗内，Esc 可关闭，背景滚动锁定。
- **影响**：读屏把抽屉播报为“对话框”但无名称；键盘用户 Tab 到背景控件后失去上下文；违反 WCAG 4.1.2、2.1.2、2.4.3。
- **修复建议**：统一使用 Radix `Dialog/Sheet` 原语并补 `SheetTitle`（可 `sr-only`）与 `SheetDescription`；录入线索改用 `Dialog` 或补齐 `role="dialog"`、`aria-modal`、`aria-labelledby`、焦点陷阱、Esc、滚动锁。
- **验证**：axe `aria-dialog-name` 为 0；Tab 循环停留在弹窗内；Esc 关闭；背景不可滚动。

### B-06 全局正文字体令牌失效，Inter 从未加载

- **复核状态**：已复现（全局）
- **实测证据**：
  - `body` 计算字体为 `ui-sans-serif, system-ui, sans-serif, "Apple Color Emoji", ...`；所有 `<p>` 同样是系统字体。
  - `:root` 与 `body` 上的 `--font-sohne` 计算值均为空字符串；`document.fonts.check("16px inter")` 为 `false`，`interUsers=0`（页面上没有任何元素使用 Inter）。
  - `layout.tsx:36` 的 `font-(--font-sohne)` 被 Tailwind 编译为：
    ```css
    --tw-font-weight: var(--font-sohne);
    font-weight: var(--font-sohne);
    ```
    即被当成字重工具类，而不是字体族。
  - 根因：`globals.css` 的 `--font-sohne` 定义在 `@theme inline` 中，Tailwind 不把该变量输出到 `:root`；`@layer base body { font-family: var(--font-sohne) }` 引用空变量，声明在计算值阶段失效，回退到系统字体。
  - 次级问题：`.font-display` 写在 `@layer utilities` 中，不是 Tailwind 主题字体工具，**响应式前缀不会被生成**。C 端 `md:font-display` 共 7 处（`app/(c)/page.tsx:176`、`app/(c)/about/page.tsx:450/499/534/576/603`、`app/(c)/projects/[id]/page.tsx:151`）全部无效；1280px 下 C 首页 h1 实测为 **ui-sans-serif 56px**，而不是 Signifier。
- **期望**：全站正文使用 DESIGN.md 指定的 Sohne（当前实现以 Inter 代替）；C 端桌面标题切换 Signifier。
- **影响**：品牌排版在所有页面失效，不同操作系统渲染结果不一致；上一版报告假设“base body 规则可兜底”，实测该兜底本身也失效。这是全局视觉契约阻断，不是局部漂移。
- **修复建议**：
  1. 在 `body` 直接写 `font-family: var(--font-inter), ui-sans-serif, system-ui, sans-serif`，或把字体变量类移到 `<html>` 并在 `:root` 定义可解析的字体栈；不要依赖 `@theme inline` 的空变量。
  2. 把 `.font-display` 改为 `@theme { --font-display: var(--font-source-serif), ... }`，使用生成的 `font-display` 工具类，才能支持 `md:`。
  3. 增加自动化断言：`document.fonts.check("16px inter") === true`、关键元素 `font-family` 含 Inter/Source Serif、`md:font-display` 在桌面视口生效。
- **验证**：1280px 下 body 计算字体为 Inter 栈、C 首页 h1 为 `sourceSerif`；网络面板出现 Inter 字体文件；axe/视觉截图复核。

9. **删除按钮使用饱和红**：多处 `AlertDialogAction` 使用 `bg-error hover:bg-red-700`，`red-700` 不在契约中。
10. **原生文件输入样式不统一**：部分上传入口使用原生 `<input type="file">`，与 Steep 输入框形态不一致。
11. **页面标题不一致**：`/admin/ledger` 实测 `document.title = "Profo"`，其余页面多为“工作台 - ProFo”等；疑似缺少 metadata。**（实测新增）**
12. **侧栏菜单产生双倍 Tab 停靠点**：键盘路径中 11 个菜单项同时出现 `<a>` 与折叠 `<button>`（如“线索中心”两次），走完侧栏到内容区需 23 次 Tab；若折叠按钮无独立功能，应合并或移出 Tab 序列。**（实测新增）**

## 六、设计债（Debt）

1. **死代码：`lib/status-colors.ts`**——`SSR_STATUS_COLORS` 仍是旧版饱和色，`getStatusColor` / `getAllStatusColors` 在文件外 0 引用；复用会把旧色板带回。
2. **死代码：`components/common/stats-card-grid.tsx`**——组件外 0 引用，且 `role="button"` 没有 `onClick`/`tabIndex`/键盘处理，是“看似可点击”的错误范式。
3. **旧图表/状态令牌**：`globals.css:211` 的 `--chart-1..5`（OKLCH）与 `--status-pending:#d946ef`（洋红）、`--status-signing:#005daa` 仍存在，与 Steep 色板并行。
4. **`ui/data-table.tsx` 承载业务逻辑**：TanStack 表格、写死“暂无数据”、行点击都在 shadcn 目录，违反 `AGENTS.md` 的 `ui/` 边界；行点击不可键盘操作（B-04）。
5. **类型令牌缺失**：DESIGN.md 的 type scale 未写入 `globals.css`，字号只能靠任意值表达。
6. **字体令牌误用**：`font-(--font-sohne)` 被编译成 `font-weight`，`@theme inline` 不输出变量，导致全站回退系统字体（B-06）。
7. **卡片标记复制粘贴**：大量页面重复 `rounded-cards bg-pure-white shadow-steep`，没有统一 Card 变体。
8. **局部状态色板**：`projects/[projectId]/_components/page-shell/hero-section.tsx` 的 `STATUS_PILL_CLASS` 硬编码 `#2c4d7f`、`#e5efe7/#3e6b4f`、`#ececee`。
9. **Dialog/Sheet 语义覆盖不全**：57 个文件导入 Dialog、58 个文件使用 `DialogDescription`；15 个文件导入 Sheet、14 个使用 `SheetTitle`，待办两处遗漏。
10. **契约注释与实现不符**：`page-header.tsx:18-19` 注释声称 34px 移动端字号符合“不低于 40px”，会误导维护者。
11. **未定义工具类无防护**：`rounded-pill` 15 处使用、编译 0 产出（B-03）；目前没有 lint 阻止未定义的自定义工具类。

### 7.1 已核验的非问题

| 项 | 实测结论 |

### 7.2 与上一版报告的结论修正

| 旧结论 | 本次实测 |
|---|---|
| “视觉一致性 Inconclusive，因为无法渲染” | 已渲染 22 条路由并采集 15 组响应式证据；视觉一致性可判定为 Fail，只有像素 diff 仍 Inconclusive。 |

### 7.3 需要设计决策（needs-design-decision）

1. **字体策略**：DESIGN.md 指定 Sohne，仓库只有 Inter，且当前未加载。批准 Inter 作为长期替代，还是引入 Sohne 授权字体？
2. **KPI 数字是否允许 Signifier <40px**：要么修改 DESIGN.md 增加“数据数字例外”，要么统一改用 Sohne。
3. **后台版心 1480 还是 1600**：HiFi 与 `PageContainer` 不一致，需确认后固化为令牌。
4. **金额涨跌颜色**：若沿用国内“红涨绿跌”，需在 DESIGN.md 显式声明其优先级高于“禁止饱和红绿”；否则改为 Rust/Graphite 组合。
5. **危险操作是否引入红色令牌**：删除确认目前使用 `red-700`，需决定保留语义红并建 token，还是用 Ink 描边 + 文案强调。
