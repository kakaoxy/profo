调价是「房源营销」模块最高频的写操作，但当前它没有独立组件——入口按钮、内联表单、差价 chip、历史时间线、送达统计全部混在 detail/notify-section.tsx 一张卡里，且沉在详情页第三屏； 列表页操作列也只有「预览 / 编辑 / 删除」。本稿将调价拆为独立可复用的 <PriceChangeCard>（浏览 / 表单 / 成功三态自包含），详情页重构为 左主右辅双栏——价格与调价升入右栏第一卡，并为列表页补上行内快捷调价入口。

Sec 01 · 现状问题

为什么调价需要被独立出来

P-01

职责混杂

推送订阅语义（被动展示）与调价操作语义（主动写操作）同卡；内联表单展开时把送达统计与历史时间线一起挤下屏。

P-02

页面重心错位

单列堆叠布局下，总价与调价——详情页最高频动作——位于第三屏；房源信息卡的「总价」行与调价入口相距两屏，价格状态无处聚合。

P-03

列表页无调价入口

ActionCell 仅预览 / 编辑 / 删除；运营盯「近期调价」筛选后的清单批量改价时，每套都要进详情页翻到第三屏。

P-04

结果反馈断裂

调价成功后 toast 文案不承诺送达人数，推送异步执行；但成功态缺少「推送已排队」的明确转达，运营只能去历史里核对送达统计。

重设计原则 一_PRICE 价格升为右栏第一卡，浏览 / 表单 / 成功三态同位切换，页面重心即操作重心 · 二_REUSE 组件自包含（数据入 props、动作出回调），列表行内弹层与详情卡共用同一交互语言 · 三_FEEDBACK 成功态显式转达「订阅推送已排队」，送达结果回历史时间线核对

Sec 06 · 状态机与口径

三态状态机与既有链路口径

BROWSE
浏览态
当前价 + 最近调价条 + 历史（懒加载）
⇄
FORM
表单态
卡内切换；差价 chip 实时联动；同值禁用
→
SUCCESS
成功态
推送已排队；完成 → 回浏览态 + router.refresh
↳ 提交失败：停留表单态 · toast.error（校验/网络两类）
↳ 取消 / Esc：reset 回浏览态，输入不保留
口径 / 边界约定（与现有实现严格对齐）
入口可见性showPricingEntry = publish_status === "发布" && hasPermission(L4_MARKETING_WRITE)，详情卡与列表「调价」项共用同一判定；「已售」行不展示快捷入口（改价语义已终结）。
提交契约复用既有 updateL4MarketingProjectPriceAction(id, total_price)（PUT exclude_unset 局部更新）；后端保证同值不产生调价记录 / 不触发通知——前端同值禁用只是体验层双保险。
成功反馈toast + 成功态文案只承诺「推送已排队」，不写具体人数；送达结果（notify_success / skipped / failed）由后台任务写回时间线分次展示。
金额方向降价 = --color-success 绿（用户得利视角，与 columns.tsx 调价副行一致）；涨价 = Graphite 灰中性；不引入红涨绿跌。
单价折算表单态实时显示 new_total_price × 10000 ÷ area 折算单价（仅 area 已知时）；列表副行单价由服务端 unit_price 下发，前端不自行改写。
时间线口径GET /price-changes 倒序全量（含分次送达计数）；详情卡懒加载（首次展开或进入表单态时拉取），列表弹层不拉时间线。
列表行刷新详情页成功 → router.refresh() + onRefresh；列表弹层成功 → 关弹层 + toast + router.refresh（revalidateTag 已在 action 内）。
键盘 / 焦点进入表单态自动 focus 新总价输入；Esc 逐层退出（弹层 → 表单态）；确认按钮同值 / 空值 / ≤0 / 提交中禁用。
Sec 07 · 实现落点与验证

组件化拆分落点（Router→Service 不动，纯前端重构）

新增 / 改造文件（frontend）

  1. 新增 admin/marketing/_components/price-change-card.tsx —— 独立组件：props 收 project / timeline / variant("card" | "popover") / canWrite，onPriceSubmit 回调上抛；三态内部 useState，zod schema 从 notify-section 平移。
  2. 瘦身 detail/notify-section.tsx —— 移除调价表单 / 差价 chip / 时间线，仅保留推送说明；若并入 PushStatCard 则整文件删除并更新 detail/index.ts 导出。
  3. 新增 _components/push-stat-card.tsx（或并入 PriceChangeCard 旁挂）—— notify_summary 两格统计纯展示。
  4. 改 marketing-detail-page.tsx —— view 态内容区改双栏 grid（左：MarketingInfoSection + BasicConfigSection + PhotosSection；右：PriceChangeCard + PushStatCard，sticky）。
  5. 改 action-cell.tsx —— 插入「调价」项（已发布 + canWrite + 非已售），挂 PricePopover（内嵌 PriceChangeCard variant="popover"）。
  6. 类型 —— 无 API 变更，不触发 pnpm gen-api；timeline 类型从 actions/projects.ts 导出复用，避免重复声明。

明确不做（防 scope 蔓延）

  1. 不新增后端接口 / 迁移：复用 PUT 局部更新与 GET /price-changes 既有契约。
  2. 不改列表页筛选：badge_filter=new/price 服务端链路不动，仅 pill 高亮引导。
  3. 不做批量调价：单房调价是既有语义；批量属新需求需单独立项。
  4. edit 态（EditMode 整页表单）不显示调价入口——调价只作用于 view 态，由父级保证（现状逻辑保留）。
  5. 小程序端展示不在本稿范围（C 端消息卡见 2026-10-04 订阅通知稿）。
E2E-1 发布房源 → 详情页右栏调价 428→421 → 成功态文案含「推送已排队」→ 列表行总价 421 / 副行「原 428」出现 / badge_filter=price 可筛出该行。
