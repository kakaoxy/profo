## 二、P0（4/4 已修复）

### 1. 门店合并越权（REQ-M12-001 / BR-M12-003）

- 问题：`merge_stores` 只校验 `merchant:write`，而默认 `user` 角色即持有该权限 → 普通员工可合并任意门店。
- 修复：`backend/dependencies/auth.py` 新增 `require_permission_with_roles(code, roles)`，并派生 `MerchantMergePermDep`；`backend/routers/merchant/admin.py` 的 `merge_stores` 改用该依赖。
- 服务层加固：`backend/services/merchant/store.py::merge_stores` 增加保留门店状态校验（已合并/已停用拒绝）、`ensure_store_visible` 双门店数据范围校验、审计 `after` 记录迁移数量。
- 验证：`backend/tests/test_merchant_admin.py::test_merge_and_agreement_review_require_internal_role`（user 角色 403，message 含 `admin/operator`）。

### 2. 协议审核越权（REQ-M04-009 / BR-M04-031）

- 修复：`MerchantAgreementReviewPermDep` 同源派生；`backend/routers/merchant/agreement_admin.py::review_agreement` 改用。
- 验证：同上测试用例的另一半（协议审核 403）。

### 3. 门店二维码邀请链路断（REQ-M06-006）

- 问题：二维码 `page=pages/merchant/home/index`，而该页无 `onLoad`，不解析 `scene` → 扫码后无任何动作。
- 修复：`miniapp/pages/merchant/home/index.ts` 新增 `parseSceneCode()`（兼容裸短码与 `code=` 键值）与 `onLoad()` → `wx.redirectTo` 到 `pages/merchant/broker/index?code=...`；下游 `broker/index.ts` 已消费该参数（`resolveQRCode` + 注册请求带 `qrcode_code`）。
- 验证：`cd miniapp && pnpm tsc` 通过。

### 4. 定位授权被拒仍可降级提交 / 无坐标门店 500（AC-V03-007）

- 问题：拒绝授权与弱网无法区分，均可走「定位失败」降级；`services/merchant/visit.py` 对无坐标门店执行 `float(None)` → 500。
- 修复：
  - 新增枚举 `MerchantLocationFailureType`（`auth_denied/timeout/unavailable`）与列 `merchant_visits.location_failure_type`（迁移 v111，幂等）。
  - `services/merchant/visit.py::_validate_location` 拦截 `auth_denied` → 400；距离计算加坐标非空守卫。
  - 小程序 `pages/merchant/visit/create/`：解析 `errMsg` 区分拒绝授权（引导 `wx.openSetting`）与弱网/超时，拒绝授权时禁用降级按钮并阻断提交。
- 验证：`backend/tests/test_merchant_store_visit.py::test_visit_location_auth_denied_and_missing_store_coordinates`；`tests/test_migration_registry.py` 9 passed。

## 六、已知偏差与说明（不静默）

1. **`former_store_no` 存门店名**：需求 R-V07-12 明确「取值口径待确认」，且数据模型无门店编号列；为让详情页「曾用门店」可读，暂存门店名并加注释，待确认后随迁移调整。

3. **列表页仍为客户端取数**（`'use client'` + `useEffect`）：与 AGENTS「默认 Server Component」偏离，属技术债，本轮未改（改动面覆盖 9 个页面，风险大于收益）。
4. **`migrations/_merchant_schema.py` 使用 `# fmt: off/on`**：`ruff format` 会合并隐式字符串拼接，改变已应用迁移的 token 流并触发 checksum 门禁（K4/K5），故对两个历史迁移函数加格式化豁免。
