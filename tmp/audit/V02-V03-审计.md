## 缺口明细

### GAP-V02-01 REQ-M01A-001 后台公司管理入口缺失
- 缺失验收项：AC-V02-001（admin/operator 在后台公司管理入口新建公司）、AC-V02-002（公司改名/停用）。
- 期望行为：后台提供公司列表/新建/编辑（改名、停用），停用后不可被新建门店选择。
- 现状（文件:行）：`backend/routers/merchant/admin.py` 有 `/admin/merchant/companies` GET/POST/PUT，但 `frontend/src/app/(main)/admin/merchant/` 下只有 `stores/brokers/agreements/map/tracks`，无 `companies` 目录；全仓 `merchant/companies` 前端引用仅 `agreements/page.tsx:76`、`stores/new/page.tsx:113`、`lib/api-types.d.ts`。
- 建议修复：新增 `frontend/src/app/(main)/admin/merchant/companies/page.tsx`（列表+新建+改名+停用），复用 `merchantApi`；或在门店列表页加公司管理抽屉。
- 严重级：P1

### GAP-V02-02 REQ-M01A-001 同名公司无提示
- 缺失验收项：REQ-M01A-001 主流程"同名公司存在时提示，不阻断"。
- 期望行为：创建公司时若同名已存在，返回/展示提示（仍允许创建）。
- 现状（文件:行）：`backend/services/merchant/company.py:61-96` 直接 insert，无同名查询；`miniapp/pages/merchant/store/create/index.ts:279-303` 无提示逻辑。
- 建议修复：`company.py:69` 后增加同名 count 查询，`MerchantCompanyResponse` 增加 `duplicate_hint` 字段或接口返回 warning。
- 严重级：P2

### GAP-V02-03 REQ-M01A-002 停用公司"可见不可选"未实现
- 缺失验收项：REQ-M01A-002 分支"停用公司：列表可见但不可选"。
- 期望行为：选择公司时停用公司可见并置灰禁用，而不是消失。
- 现状（文件:行）：`backend/services/merchant/company.py:48-49` 默认 `include_disabled=False` 直接过滤，前端拿不到停用公司；`frontend/.../stores/new/page.tsx:236-253` 渲染候选时不判 `status`，停用公司可点选，直到保存才被 `store.py:927-935` 拒绝。
- 建议修复：搜索接口默认返回 `disabled` 项并附 `selectable=false`；前端按 `status` 置灰并提示"公司已停用"。
- 严重级：P2

### GAP-V02-04 REQ-M01B-002 500 米不是独立召回信号
- 缺失验收项：AC-V02-007（按名称+地址+500 米+电话四信号召回候选）。
- 期望行为：仅坐标相距 ≤500m 但名称/地址/电话都不相似的门店也应进入候选列表。
- 现状（文件:行）：`backend/services/merchant/store.py:93-111` SQL 只用 `store_name ilike / address ilike / contact_phone_hash` 三条件召回（`limit 100`）；`store.py:123-126` 的 500m 只在**已召回行**上追加 `distance` 标签，无法独立召回。
- 建议修复：在 SQL 层加经纬度包围盒预筛（`lng between ? and ?` + `lat between ? and ?`，约 ±0.005°）后 OR 进主查询，再对结果做精确 haversine ≤500m 判定。
- 严重级：P1

### GAP-V02-05 REQ-M01B-002 查重"未完成"标记恒为 false
- 缺失验收项：REQ-M01B-002 分支"查重超时可继续，记录并标记查重未完成"。
- 期望行为：查重失败/超时时 `completed=false`，前端提示"查重未完成"并允许继续。
- 现状（文件:行）：`backend/services/merchant/store.py:144` `completed=True` 硬编码；`miniapp/pages/merchant/store/create/index.ts:465-467` catch 为空，注释"查重失败不阻断保存"，既不提示也不标记。
- 建议修复：`check_duplicates` 捕获异常返回 `completed=False`；小程序 catch 分支 `wx.showToast("查重未完成，可继续提交")` 并置标记。
- 严重级：P2

### GAP-V02-06 REQ-M01B-002 后台与经纪人建店无候选展示
- 缺失验收项：AC-V02-007（命中重复时展示候选门店列表）、REQ-M01B-007 主流程"查重命中展示候选，允许确认新建并填写理由"。
- 期望行为：后台新建门店与经纪人建店都应先查重、展示候选、允许填理由强制新建。
- 现状（文件:行）：`frontend/.../stores/new/page.tsx:169-187` 直接 POST `/admin/merchant/stores`，从不调 `/admin/merchant/stores/check-duplicates`；`miniapp/pages/merchant/broker/store-create/index.ts:98-112` payload 无 `force_create_reason`，也无查重调用。
- 建议修复：后台新建页提交前调查重接口并渲染候选表 + 理由输入；经纪人建店页补 `force_create_reason` 输入与查重弹窗。
- 严重级：P1

### GAP-V02-07 REQ-M01B-002 候选门店无坐标时查重崩溃
- 缺失验收项：REQ-M01B-002 稳定性（存量无坐标门店不得导致查重失败）。
- 期望行为：跳过无坐标候选的距离计算，仅按名称/地址/电话匹配。
- 现状（文件:行）：`backend/services/merchant/store.py:123-126` `distance = haversine_m(float(req.lng), float(req.lat), float(store.lng), float(store.lat))`，`store.lng/lat` 允许为空（`backend/models/merchant/store.py` 注释"GCJ-02(存量可空)"），`float(None)` 抛 `TypeError` → 500。
- 建议修复：`if req.lng is not None and req.lat is not None and store.lng is not None and store.lat is not None:` 再算距离。
- 严重级：P1

### GAP-V02-08 REQ-M01B-002 查重结果未写入审计
